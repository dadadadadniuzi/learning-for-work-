# 19-写一条日志的全流程模拟
关联笔记：
- [[TinyWebServer-面试拆解笔记]]
- [[TinyWebServer-拆解/08-日志系统与同步原语]]

## 这篇笔记讲什么
这篇只讲一件事：

> 在 TinyWebServer 里，代码里写下一句 `LOG_INFO(...)` 之后，到底发生了什么。

我会分成两部分讲：

1. 日志系统启动时是怎么初始化的
2. 一条日志真正被写入文件时的完整链路

并且我会用一个具体例子来模拟：

```cpp
LOG_INFO("deal with the client(%s)", "192.168.1.10");
```

然后把涉及到的函数、每一步关键变量、同步/异步分支的区别都拆出来。

---

## 先说结论：这个日志系统的本质是什么
这个项目的日志系统本质上是：

- 一个单例 `Log`
- 支持同步写日志
- 也支持异步写日志
- 异步模式下用一个阻塞队列 `block_queue<string>`
- 后台再开一个专门的日志线程，负责从队列里取日志并落盘

所以它的核心思想是：

> 业务线程负责“生成日志字符串”，后台日志线程负责“慢慢写文件”。

这样做的好处是：

> 避免业务线程频繁阻塞在磁盘 I/O 上。

---

## 先看入口：日志系统什么时候初始化
日志系统初始化发生在服务端启动阶段。

`main.cpp` 里的启动顺序大致是：

```cpp
server.init(...);
server.log_write();
server.sql_pool();
server.thread_pool();
server.trig_mode();
server.eventListen();
server.eventLoop();
```

其中直接负责初始化日志系统的是：

```cpp
server.log_write();
```

---

## 第 0 步：`WebServer::log_write()` 决定同步还是异步
### `WebServer::log_write()`
作用：
    初始化日志系统，并决定是同步日志还是异步日志。
输入：
    无，直接使用成员变量 `m_close_log`、`m_log_write`。
输出：
    无。

### 配置变量是什么意思
在这个项目里，和日志相关的两个重要配置项是：

- `m_close_log`
  - `0`：开启日志
  - `1`：关闭日志
- `m_log_write`
  - `0`：同步日志
  - `1`：异步日志

### 假设我们这次走异步日志
为了把流程讲完整，我们假设启动参数里是：

```text
LOGWrite = 1
close_log = 0
```

也就是：

- 日志系统开启
- 采用异步模式

### `server.log_write()` 最终会调用
```cpp
Log::get_instance()->init("./ServerLog", m_close_log, 2000, 800000, 800);
```

这组参数你可以先记成：

- 日志文件名前缀：`./ServerLog`
- `close_log = 0`
- 单条日志格式化缓冲区大小：`2000`
- 单文件最大行数：`800000`
- 异步队列大小：`800`

因为最后一个参数 `max_queue_size = 800 >= 1`，所以：

> 这次会进入异步日志模式。

---

## 第 1 步：`Log::get_instance()` 拿到单例对象
### `Log::get_instance()`
作用：
    返回整个进程唯一的日志对象。
输入：
    无。
输出：
    `Log*`

### 为什么要单例
因为整个服务器只需要：

- 一份日志配置
- 一份日志文件指针
- 一份日志队列
- 一组互斥保护

如果多个地方各建一个 `Log`，日志文件会很难统一管理。

---

## 第 2 步：`Log::init(...)` 初始化日志系统
### `Log::init(const char *file_name, int close_log, int log_buf_size, int split_lines, int max_queue_size)`
作用：
    初始化日志系统，决定同步/异步模式，创建日志文件，并保存相关配置。
输入：
    `file_name`：日志文件名前缀。  
    `close_log`：是否关闭日志。  
    `log_buf_size`：单条日志缓冲区大小。  
    `split_lines`：单个日志文件最多写多少行。  
    `max_queue_size`：异步队列大小，`0` 表示同步。
输出：
    `true`：初始化成功。  
    `false`：日志文件打开失败。

### 我们这次假设输入值
```cpp
file_name = "./ServerLog"
close_log = 0
log_buf_size = 2000
split_lines = 800000
max_queue_size = 800
```

---

## 第 3 步：`init()` 判断是不是异步模式
核心判断是：

```cpp
if (max_queue_size >= 1)
```

因为：

```cpp
max_queue_size = 800
```

所以条件成立。

### 于是会发生三件事
1. `m_is_async = true`
2. 创建阻塞队列：

```cpp
m_log_queue = new block_queue<string>(800);
```

3. 创建后台日志线程：

```cpp
pthread_create(&tid, NULL, flush_log_thread, NULL);
```

### 这一步结束后关键变量
- `m_is_async = true`
- `m_log_queue` 指向一个最大容量为 `800` 的阻塞队列
- 假设新建线程号：
  `tid = 3256`

---

## 第 4 步：`block_queue<string>(800)` 初始状态是什么
### `block_queue(int max_size = 1000)`
作用：
    构造一个循环数组实现的阻塞队列。
输入：
    `max_size`：队列容量。
输出：
    无。

### 构造完成后的关键变量
假设：

```cpp
max_size = 800
```

那么队列初始状态是：

- `m_max_size = 800`
- `m_size = 0`
- `m_front = -1`
- `m_back = -1`
- `m_array` 指向 800 个 `string` 槽位的底层数组

你可以把它理解成：

> 队列已经建好了，但现在里面还没有任何日志。

---

## 第 5 步：后台日志线程启动后会做什么
`pthread_create()` 创建出的线程入口函数是：

```cpp
Log::flush_log_thread
```

### `static void *flush_log_thread(void *args)`
作用：
    作为异步日志线程入口，进一步调用真正的日志消费函数。
输入：
    `args`：这里没有实际使用。
输出：
    `void*`

它内部实际上只做一件事：

```cpp
Log::get_instance()->async_write_log();
```

---

## 第 6 步：后台线程进入 `async_write_log()`
### `void *async_write_log()`
作用：
    后台日志线程不断从阻塞队列中取出日志字符串，并写入日志文件。
输入：
    无。
输出：
    `void*`

### 刚开始时队列为空
所以它会执行：

```cpp
while (m_log_queue->pop(single_log))
```

但因为队列是空的，所以：

- `m_size = 0`
- `pop()` 内部会阻塞等待

也就是说：

> 后台日志线程已经启动了，但它现在卡在队列上等新日志到来。

---

## 第 7 步：日志文件本身是怎么打开的
`Log::init()` 后半段会根据当前日期和文件名前缀，拼出最终日志文件名。

如果当前日期假设是：

- `2026-05-03`

而 `file_name = "./ServerLog"`，那么它最后可能会生成类似：

```text
2026_05_03_ServerLog
```

或者带目录前缀的完整形式。

### 这一步结束后关键变量
- `m_today = 3`
- `m_split_lines = 800000`
- `m_log_buf_size = 2000`
- `m_count = 0`
- `m_fp = fopen(...)` 打开的文件指针
- `m_buf` 指向一段 `2000` 字节的格式化缓冲区

到这里为止，日志系统已经初始化完毕。

---

## 现在开始模拟：写一条真实日志
我们选一条项目里真实很像的日志：

```cpp
LOG_INFO("deal with the client(%s)", "192.168.1.10");
```

你可以把它理解成：

> 主线程发现有客户端要处理了，于是记一条 info 日志。

---

## 第 8 步：先进入宏 `LOG_INFO(...)`
在 `log.h` 里，宏大致是：

```cpp
#define LOG_INFO(format, ...) \
if(0 == m_close_log) { \
    Log::get_instance()->write_log(1, format, ##__VA_ARGS__); \
    Log::get_instance()->flush(); \
}
```

### 这一步做了什么
1. 先判断：

```cpp
m_close_log == 0
```

如果日志没关，就继续。

2. 调用：

```cpp
Log::get_instance()->write_log(1, "deal with the client(%s)", "192.168.1.10");
```

3. 然后再调用：

```cpp
Log::get_instance()->flush();
```

### 当前关键变量
- `level = 1`
- `format = "deal with the client(%s)"`
- 可变参数 = `"192.168.1.10"`

这里的 `1` 对应的是：

```text
[info]:
```

---

## 第 9 步：进入 `Log::write_log(...)`
### `void Log::write_log(int level, const char *format, ...)`
作用：
    根据日志级别和格式化内容，生成完整日志字符串；异步模式下入队，同步模式下直接写文件。
输入：
    `level`：日志级别。  
    `format`：格式字符串。  
    `...`：格式化参数。
输出：
    无。

---

## 第 10 步：先拿当前时间，决定日志级别前缀
`write_log()` 一开始会调用：

- `gettimeofday(&now, NULL)`
- `localtime(&t)`

假设当前时间是：

- 日期：`2026-05-03`
- 时间：`21:15:42`
- 微秒：`123456`

那么此时局部变量大致是：

- `now.tv_sec = 1777814142`  
  这里只是举例，不要求你硬背
- `now.tv_usec = 123456`
- `my_tm.tm_year + 1900 = 2026`
- `my_tm.tm_mon + 1 = 5`
- `my_tm.tm_mday = 3`
- `my_tm.tm_hour = 21`
- `my_tm.tm_min = 15`
- `my_tm.tm_sec = 42`

### 日志级别字符串
因为：

```cpp
level = 1
```

所以 `switch(level)` 后：

```cpp
s = "[info]:"
```

---

## 第 11 步：先更新总行数，并检查是否要切分日志文件
接下来它会先加锁，然后：

```cpp
m_count++;
```

### 假设写这条日志前
- `m_count = 125`
- `m_today = 3`
- `m_split_lines = 800000`

那么写这条日志时：

```cpp
m_count = 126
```

然后检查：

```cpp
if (m_today != my_tm.tm_mday || m_count % m_split_lines == 0)
```

由于：

- 今天还是 3 号
- `126 % 800000 != 0`

所以：

> 不需要切分日志文件，继续写当前文件。

### 这一步结束后关键变量
- `m_count = 126`
- `m_today = 3`
- `m_fp` 不变

---

## 第 12 步：把完整日志格式化到 `m_buf`
这一段是日志内容真正生成的地方。

### 第一步：写统一前缀
先执行：

```cpp
int n = snprintf(m_buf, 48, "%d-%02d-%02d %02d:%02d:%02d.%06ld %s ",
                 2026, 5, 3, 21, 15, 42, 123456, "[info]:");
```

这一步后，`m_buf` 前半部分大致是：

```text
2026-05-03 21:15:42.123456 [info]:
```

假设：

```cpp
n = 35
```

意思是前缀已经写了 35 个字符。

### 第二步：把业务内容拼到后面
再执行：

```cpp
int m = vsnprintf(m_buf + n, m_log_buf_size - n - 1,
                  "deal with the client(%s)",
                  valst);
```

这里会把：

```text
deal with the client(192.168.1.10)
```

拼到后面。

假设：

```cpp
m = 37
```

然后代码会手工补上：

```cpp
m_buf[n + m] = '\n';
m_buf[n + m + 1] = '\0';
```

### 最终 `m_buf` 内容
```text
2026-05-03 21:15:42.123456 [info]: deal with the client(192.168.1.10)\n
```

然后：

```cpp
log_str = m_buf;
```

### 这一步结束后关键变量
- `s = "[info]:"`
- `n = 35`
- `m = 37`
- `log_str = "2026-05-03 21:15:42.123456 [info]: deal with the client(192.168.1.10)\n"`

---

## 第 13 步：异步模式下，不直接写文件，而是先入队
现在走到这段判断：

```cpp
if (m_is_async && !m_log_queue->full())
```

因为我们当前是假设异步模式，所以：

- `m_is_async = true`

假设当前队列里原本有 `12` 条日志，那么：

- `m_log_queue->m_size = 12`
- `m_max_size = 800`

所以：

```cpp
!m_log_queue->full() == true
```

### 于是执行
```cpp
m_log_queue->push(log_str);
```

这一步非常关键，它意味着：

> 业务线程到这里基本就完成任务了，它并没有自己去写磁盘。

---

## 第 14 步：`block_queue::push(log_str)` 是怎么把日志塞进队列的
### `bool push(const T &item)`
作用：
    往阻塞队列尾部插入一个新元素。
输入：
    `item`：这里是一条完整日志字符串。
输出：
    `true`：入队成功。  
    `false`：队列已满。

### 假设入队前队列状态
- `m_size = 12`
- `m_front = 7`
- `m_back = 18`
- `m_max_size = 800`

### 入队过程
1. 判断队列是否满  
   这里没满
2. 更新尾指针：

```cpp
m_back = (m_back + 1) % m_max_size
       = (18 + 1) % 800
       = 19
```

3. 写入数组：

```cpp
m_array[19] = log_str
```

4. 队列元素数加一：

```cpp
m_size = 13
```

5. `broadcast()` 唤醒可能正在等待日志的后台线程

### 入队后关键变量
- `m_back = 19`
- `m_size = 13`
- `m_array[19] = "2026-05-03 21:15:42.123456 [info]: deal with the client(192.168.1.10)\n"`

---

## 第 15 步：后台日志线程被唤醒
之前后台线程阻塞在：

```cpp
m_log_queue->pop(single_log)
```

现在因为 `push()` 里做了 `broadcast()`，所以它会被唤醒。

---

## 第 16 步：`block_queue::pop(single_log)` 把日志取出来
### `bool pop(T &item)`
作用：
    从阻塞队列头部取出一个元素；如果队列为空就阻塞等待。
输入：
    `item`：输出参数，用来接收取出的日志字符串。
输出：
    `true`：取出成功。  
    `false`：等待失败或异常。

### 假设唤醒前队列状态
- `m_size = 13`
- `m_front = 7`
- `m_back = 19`

### 出队过程
1. 因为 `m_size > 0`，不用再等待
2. 头指针前移：

```cpp
m_front = (m_front + 1) % m_max_size
        = (7 + 1) % 800
        = 8
```

3. 取出元素：

```cpp
item = m_array[8]
```

这里需要注意：

> 这个循环队列的 `m_front` 记录的是“上一次弹出的位置”，所以真正队头是 `(m_front + 1) % m_max_size`。

4. 元素数减一：

```cpp
m_size = 12
```

### 出队后关键变量
- `single_log = "2026-05-03 21:15:42.123456 [info]: deal with the client(192.168.1.10)\n"`
- `m_front = 8`
- `m_size = 12`

---

## 第 17 步：后台线程真正把日志写进文件
`async_write_log()` 拿到 `single_log` 后，会执行：

```cpp
fputs(single_log.c_str(), m_fp);
```

### 这里发生了什么
1. `single_log.c_str()` 变成 C 风格字符串
2. `fputs()` 把这条字符串写入当前日志文件流 `m_fp`

### 当前关键变量
- `single_log = "2026-05-03 21:15:42.123456 [info]: deal with the client(192.168.1.10)\n"`
- `m_fp = 当前打开的日志文件`

执行完后，这条日志已经进入 `FILE*` 对应的用户态缓冲区。

---

## 第 18 步：为什么宏里还会再调用一次 `flush()`
虽然异步线程已经 `fputs()` 了，但宏最后仍然会执行：

```cpp
Log::get_instance()->flush();
```

### `void flush()`
作用：
    强制把日志文件流缓冲区刷新到文件中。
输入：
    无。
输出：
    无。

它内部做的是：

```cpp
fflush(m_fp);
```

### 这里怎么理解
严格说：

- `write_log()` 负责生成并交付日志
- `fputs()` 把内容写到 `FILE*` 缓冲区
- `flush()` 尽量把缓冲区里的数据立刻刷到文件

所以你可以把 `flush()` 理解成：

> 尽快把内存里的日志推进到磁盘文件流里，降低程序崩溃时日志丢失的概率。

---

## 到这里，一条日志就完整写完了
如果我们把整条链只用一句话概括：

> 业务线程调用 `LOG_INFO` 后，先在 `write_log()` 里把时间戳、级别和正文拼成完整字符串；异步模式下把它放进阻塞队列，由后台日志线程 `pop` 出来并 `fputs` 到日志文件，最后再通过 `flush()` 刷新文件流。

---

## 整条调用链
```text
main()
-> WebServer::log_write()
-> Log::get_instance()->init(...)
-> pthread_create(..., flush_log_thread, ...)
-> 后台线程进入 async_write_log()

业务线程某处调用：
LOG_INFO("deal with the client(%s)", "192.168.1.10")
-> Log::get_instance()->write_log(1, ...)
-> 生成完整 log_str
-> m_log_queue->push(log_str)
-> 后台线程 pop(single_log)
-> fputs(single_log.c_str(), m_fp)
-> flush()
-> fflush(m_fp)
```

## 如果是同步日志，会少掉哪些步骤
如果配置是：

```cpp
m_log_write = 0
```

也就是同步模式，那么：

- `m_is_async = false`
- 不会创建阻塞队列
- 不会创建后台日志线程

此时 `write_log()` 在生成 `log_str` 后，会走：

```cpp
fputs(log_str.c_str(), m_fp);
```

也就是说：

> 当前业务线程自己直接把日志写进文件，而不是入队交给后台线程。

### 同步模式的优点
- 实现简单
- 不依赖后台线程
- 日志顺序更直观

### 同步模式的缺点
- 业务线程会被磁盘 I/O 拖慢
- 高并发下日志开销更明显

---

## 这个日志系统还做了什么额外工作
除了“写一条日志”本身，它还做了两件很实用的事：

### 1. 按天切分日志
如果：

```cpp
m_today != my_tm.tm_mday
```

说明跨天了，它会切到新的日期文件。

### 2. 按行数切分日志
如果：

```cpp
m_count % m_split_lines == 0
```

说明当前文件已经写太多行了，它会生成类似：

```text
2026_05_03_ServerLog.1
2026_05_03_ServerLog.2
```

这样的分卷文件。

## 面试时你可以怎么讲这条日志链路
你可以直接这样说：

> 这个项目的日志模块是一个单例，支持同步和异步两种模式。服务端启动时在 `WebServer::log_write()` 里初始化日志系统，如果配置成异步，就会创建一个阻塞队列和后台日志线程。业务线程调用 `LOG_INFO` 时，先进入 `write_log()`，把时间戳、日志级别和正文格式化成完整字符串；异步模式下这条字符串先进入阻塞队列，后台线程在 `async_write_log()` 里不断 `pop` 出日志并通过 `fputs` 写入文件。这个设计的核心目的是把业务线程和磁盘 I/O 解耦，减少高并发场景下日志对主业务路径的阻塞。`
