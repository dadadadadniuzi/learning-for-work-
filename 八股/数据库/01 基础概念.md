## SQL 是什么

### 简要回答

SQL 是结构化查询语言，用来操作关系型数据库。

### 常见分类

- DDL：建表、删表、修改表结构。
- DML：增删改数据。
- DQL：查询数据。
- DCL：权限控制。

## 常见 SQL 语句有哪些

### 简要回答

面试常考 SQL 可以按查询、连接、聚合、写入更新、索引这几类记。

### 查询

> [!tip] 记忆方式
> `SELECT` 是“查什么”，`FROM` 是“从哪张表查”，`WHERE` 是“过滤条件”，`ORDER BY` 是“排序”，`LIMIT` 是“只拿几条”。

| 语句 | 作用 | 面试记忆点 |
|---|---|---|
| `SELECT` | 查询数据 | DQL，最常用 |
| `*` | 所有字段 | 实际开发不建议乱用，容易多查无用列 |
| `WHERE` | 过滤行 | 先把不符合条件的数据筛掉 |
| `ORDER BY` | 排序 | `ASC` 升序，`DESC` 降序 |
| `DISTINCT` | 去重 | 对查询结果去重 |
| `LIMIT/OFFSET` | 分页 | `LIMIT 10 OFFSET 20` 表示跳过 20 条，再取 10 条 |
| `LIKE` | 模糊匹配 | `A%` 表示以 A 开头 |
| `BETWEEN` | 范围查询 | 包含左右边界 |

```sql
-- 查询 users 表的所有字段、所有行
SELECT * FROM users;

-- 只查询 id 和 name 两个字段，减少无用数据传输
SELECT id, name FROM users;

-- 只查询 age 大于 25 的用户
SELECT * FROM users WHERE age > 25;

-- 按 age 从大到小排序；DESC 表示降序，ASC 表示升序
SELECT * FROM users ORDER BY age DESC;

-- 查询所有城市，并去掉重复城市
SELECT DISTINCT city FROM users;

-- 分页查询：跳过前 20 条，再取 10 条
SELECT * FROM users LIMIT 10 OFFSET 20;

-- 查询 name 以 A 开头的用户；% 表示任意长度字符串
SELECT * FROM users WHERE name LIKE 'A%';

-- 查询 age 在 20 到 30 之间的用户，包含 20 和 30
SELECT * FROM users WHERE age BETWEEN 20 AND 30;
```

### 连接和子查询

| 写法 | 作用 | 适合场景 |
|---|---|---|
| `JOIN` / `INNER JOIN` | 内连接，只保留两边都匹配的数据 | 查“有订单的用户” |
| `LEFT JOIN` | 左连接，保留左表全部数据，右表没有则为 `NULL` | 查“所有用户及其订单” |
| 子查询 | 一个 SQL 里嵌套另一个 SQL | 先查一批 id，再按 id 查主表 |

```sql
-- 内连接：只查有订单的用户和订单金额
-- u、o 是表别名，写起来更短
SELECT u.name, o.amount
FROM users u
JOIN orders o ON u.id = o.user_id;

-- 左连接：users 是左表，所以即使用户没有订单，也会查出来
-- 没有订单时，o.amount 会是 NULL
SELECT u.name, o.amount
FROM users u
LEFT JOIN orders o ON u.id = o.user_id;

-- 子查询：先从 orders 表查出下过单的 user_id，
-- 再从 users 表查这些用户的 name
SELECT name
FROM users
WHERE id IN (SELECT user_id FROM orders);
```

### 聚合与分组

> [!tip] 记忆方式
> 聚合函数是“把多行算成一个结果”，`GROUP BY` 是“按某个字段分组后再算”，`HAVING` 是“对分组后的结果再过滤”。

| 函数/关键字 | 作用 |
|---|---|
| `COUNT(*)` | 统计行数 |
| `SUM()` | 求和 |
| `AVG()` | 求平均值 |
| `MAX()` / `MIN()` | 求最大值 / 最小值 |
| `GROUP BY` | 分组 |
| `HAVING` | 过滤分组后的聚合结果 |

```sql
-- 统计 users 表一共有多少行
SELECT COUNT(*) FROM users;

-- 统计所有订单金额总和
SELECT SUM(amount) FROM orders;

-- 统计用户平均年龄
SELECT AVG(age) FROM users;

-- 同时查询最大年龄和最小年龄
SELECT MAX(age), MIN(age) FROM users;

-- 按 city 分组，统计每个城市有多少用户
SELECT city, COUNT(*) FROM users GROUP BY city;

-- 先按 city 分组，再只保留用户数大于 10 的城市
-- WHERE 过滤原始行，HAVING 过滤分组后的结果
SELECT city, COUNT(*) FROM users GROUP BY city HAVING COUNT(*) > 10;
```

### 增删改

| 语句 | 作用 | 特别提醒 |
|---|---|---|
| `INSERT` | 插入新数据 | 字段和值要一一对应 |
| `UPDATE` | 修改已有数据 | 一定注意 `WHERE`，否则可能全表更新 |
| `DELETE` | 删除数据 | 一定注意 `WHERE`，否则可能全表删除 |

```sql
-- 插入一条用户记录：name 是 Alice，age 是 30
INSERT INTO users(name, age) VALUES('Alice', 30);

-- 一次插入多条用户记录，减少多次请求数据库的开销
INSERT INTO users(name, age) VALUES ('Bob', 25), ('Cathy', 22);

-- 把 id = 1 的用户年龄改成 28
-- 没有 WHERE 会把所有用户 age 都改成 28，面试和开发都要强调
UPDATE users SET age = 28 WHERE id = 1;

-- 删除未成年用户
-- 没有 WHERE 会删除整张表数据
DELETE FROM users WHERE age < 18;
```

### 索引相关

| 语句 | 作用 | 什么时候用 |
|---|---|---|
| `SHOW INDEX` | 查看一张表已有索引 | 排查慢 SQL 前先看索引情况 |
| `CREATE INDEX` | 创建普通索引 | 高频查询字段、连接字段、排序字段 |
| `DROP INDEX` | 删除索引 | 索引无用、重复或影响写入性能时 |

```sql
-- 查看 users 表上有哪些索引、索引字段是什么
SHOW INDEX FROM users;

-- 给 users 表的 age 字段创建普通索引，索引名叫 idx_age
-- 之后 WHERE age = ? 或按 age 范围查询可能更快
CREATE INDEX idx_age ON users(age);

-- 删除 idx_age 索引；删除后查询可能变慢，但写入维护成本会降低
DROP INDEX idx_age ON users;
```

## SQL 查询执行过程是什么

### 简要回答

大致经过连接器、查询缓存、解析与预处理、优化器、执行器、存储引擎，最后返回结果。

### 面试表达

> 一条 SQL 不是直接去磁盘找数据，而是先解析语法，再由优化器选择执行计划，最后执行器调用存储引擎接口读取或修改数据。

### 详细流程

1. 连接阶段：建立网络连接，校验用户名、密码和权限。
2. 查询缓存：MySQL 8.0 前可能检查缓存；8.0 后已移除。
3. 解析与预处理：词法分析、语法分析，生成语法树，并检查表和字段是否存在。
4. 优化器：根据统计信息和成本模型选择执行计划，如索引选择、JOIN 顺序。
5. 执行器：按照执行计划调用存储引擎接口。
6. 存储引擎：如 InnoDB，负责真正读取磁盘或内存中的数据。
7. 返回结果：过滤、排序、聚合后把结果返回客户端。

## 事务 ACID 是什么

### 简要回答

ACID 指原子性、一致性、隔离性、持久性。

### 详细回答

- 原子性：事务里的操作要么全做，要么全不做。
- 一致性：事务前后数据库从一个一致状态到另一个一致状态。
- 隔离性：并发事务之间互不干扰。
- 持久性：事务提交后结果永久保存。

## 事务隔离级别有哪些

### 简要回答

读未提交、读已提交、可重复读、串行化。

### 对比表

| 隔离级别 | 脏读 | 不可重复读 | 幻读 |
|---|---|---|---|
| 读未提交 | 可能 | 可能 | 可能 |
| 读已提交 | 不会 | 可能 | 可能 |
| 可重复读 | 不会 | 不会 | 可能 |
| 串行化 | 不会 | 不会 | 不会 |

### 面试提醒

MySQL InnoDB 默认隔离级别通常是可重复读，并通过 MVCC 和锁机制处理很多并发问题。

### 四种隔离级别

- 读未提交：可以读到其他事务未提交数据，会发生脏读。
- 读已提交：只能读到已提交数据，解决脏读，但可能不可重复读。
- 可重复读：同一事务内多次读同一行结果一致，MySQL InnoDB 默认级别。
- 串行化：隔离级别最高，事务串行执行，并发性能最低。

### 并发问题

- 脏读：读到其他事务未提交的数据。
- 不可重复读：同一事务内两次读同一行，结果不同。
- 幻读：同一事务内范围查询，两次读到的记录数量不同。

## 表之间有哪些关系

### 简要回答

常见有一对一、一对多、多对多。

### 详细回答

- 一对一：用户表和用户详情表。
- 一对多：一个订单对应多个订单项。
- 多对多：学生和课程，需要中间表拆分。

## 主键、外键和约束是什么

### 简要回答

主键唯一标识一行记录，外键表示表之间的关联，约束用来保证数据合法性和一致性。

### 常见约束

- 主键约束：唯一且不能为空。
- 唯一约束：字段值不能重复。
- 非空约束：字段不能为 `NULL`。
- 外键约束：限制关联字段必须来自另一张表。
- 默认值约束：字段未赋值时使用默认值。

### 面试表达

> 约束是数据库层面的数据保护规则，可以减少脏数据进入表中。主键解决“这一行是谁”，外键解决“这行和哪张表有关”。
