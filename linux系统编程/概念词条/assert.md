# assert

## 是什么

`assert` 是 C 语言里常用的断言宏，用来在运行时检查“某个条件是否必须成立”。

如果条件为假，程序通常会：

- 打印断言失败信息
- 给出文件名、行号、表达式
- 然后终止程序

## 依赖头文件

- `#include <assert.h>`

## 常见写法

```c
assert(ptr != NULL);
assert(fd >= 0);
assert(ret != -1);
```

## 怎么理解

可以把 `assert` 理解成“开发阶段的自我检查”。

例如：

```c
assert(buf != NULL);
```

它的意思不是“正常业务逻辑里去处理 `buf == NULL`”，而是：

- 我认为这里按程序设计来说 `buf` 不应该为空
- 如果它真的为空，说明程序内部逻辑很可能有 bug
- 那就直接暴露出来，不要悄悄带着错误继续跑

## 典型场景

- 检查指针不为空
- 检查返回值满足预期
- 检查状态机或内部不变量
- 调试阶段快速暴露逻辑错误

## 你要记住的点

- `assert` 是宏，不是普通函数。
- 它更适合检查“程序员认为一定成立的内部条件”。
- 它不适合替代正式的错误处理。

## 和错误处理的区别

- `assert`：
  用来发现程序内部假设被破坏的情况
- `if + 错误处理`：
  用来处理运行中本来就可能发生的异常情况

例如：

- 用户输入错误、网络断开、文件不存在
  这些通常应该正常处理
- 一个本应初始化好的指针却是空
  这更像断言要检查的问题

## `NDEBUG` 是什么

如果定义了 `NDEBUG`，`assert` 通常会被关闭。

这意味着：

- 断言表达式不会再触发终止
- 某些构建模式下它可能被编译掉

所以很多项目里会区分：

- 调试版本：保留 `assert`
- 发布版本：关闭部分断言

## 易错点

- 不要把有副作用的表达式写进 `assert`，例如 `assert(i++)`。
- 因为关闭断言后，这类表达式可能根本不会执行。
- `assert` 失败通常会直接中止程序，所以不适合拿来处理用户级错误。
- 它不能替代正常的参数校验和错误返回。

## 常见出现位置

- 网络服务器初始化
- 数据结构不变量检查
- 调试复杂流程时的保护条件
- 项目源码中快速验证状态是否正确
