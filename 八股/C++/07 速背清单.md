# C++ 速背清单

返回：[[C++导航]]

## 基础语法

- [[01 基础与语法#C++ 三大特性|C++ 三大特性]]：封装、继承、多态。
- [[03 指针引用与数组#指针和引用的区别|指针和引用]]：指针保存地址，可为空可改指向；引用是别名，通常不能为空且不能改绑。
- [[01 基础与语法#struct 和 class 的区别|struct 和 class]]：语法能力几乎一样，默认权限不同，`struct` 默认 `public`，`class` 默认 `private`。
- [[01 基础与语法#struct 和 union 的区别|struct 和 union]]：`struct` 成员独立存储；`union` 共享同一块内存。
- [[01 基础与语法#sizeof 和 strlen 的区别|sizeof 和 strlen]]：`sizeof` 看类型字节数，`strlen` 数到 `\0` 前字符数。
- [[01 基础与语法#浮点数比较方法|浮点数比较]]：多数情况下不用 `==`，固定范围用绝对误差，大范围计算常结合相对误差。
- [[01 基础与语法#C++ 四种类型转换|四种类型转换]]：`static_cast` 常规转换，`dynamic_cast` 安全向下转型，`const_cast` 改限定符，`reinterpret_cast` 底层重解释。

## 面向对象

- [[02 类与对象#构造函数和析构函数|构造和析构]]：构造负责初始化，析构负责释放资源；构造函数不能是虚函数，析构函数很多基类应写成虚函数。
- [[02 类与对象#构造函数有几种|构造函数种类]]：默认、参数化、拷贝、移动、委托、继承构造。
- [[02 类与对象#重载 重写和隐藏|重载和重写]]：重载是同作用域同名不同参，编译期决定；重写是子类重写父类虚函数，运行时决定。
- [[02 类与对象#C++ 如何实现多态|多态]]：运行时多态的核心是 `virtual + 继承 + 基类指针/引用 + 子类重写`。
- [[02 类与对象#虚函数和纯虚函数|虚函数和纯虚函数]]：虚函数可有默认实现；纯虚函数写成 `= 0`，通常让类变成抽象类。
- [[02 类与对象#虚函数表和虚函数指针|虚函数表]]：对象里的 `vptr` 指向类的 `vtable`，通过虚表做动态绑定。
- [[02 类与对象#多重继承和菱形继承|多重继承和菱形继承]]：多重继承表达力强，但布局复杂；菱形继承通常用虚继承解决。
- [[02 类与对象#如何禁止一个类被继承|禁止继承]]：现代 C++ 直接用 `final`。
- [[02 类与对象#深拷贝和浅拷贝|深拷贝和浅拷贝]]：浅拷贝复制地址，深拷贝复制资源副本；裸资源类要警惕 `double free`。
- [[02 类与对象#this 指针|this 指针]]：`this` 是非静态成员函数的隐藏参数，`*this` 是当前对象本身。
- [[02 类与对象#单例模式|单例模式]]：现代 C++ 首选 C++11 的 `Magic Static`。
- [[02 类与对象#std move 和移动语义|std::move 和移动语义]]：`std::move` 本身不移动数据，只是把左值转成右值引用，真正移动资源的是移动构造或移动赋值。

## 模板与 STL

- [[04 模板与泛型#template typename T 是什么|template<typename T>]]：类型模板参数。
- [[04 模板与泛型#template int N 是什么|template<int N>]]：非类型模板参数，传的是编译期常量。
- [[04 模板与泛型#std list T 指针成员变量|std::list<T*>]]：双向链表里存放 `T*` 类型元素。
- [[04 模板与泛型#线程池为什么适合写成模板|线程池模板化]]：任务类型不写死，复用性更强。
- [[09 STL与容器|STL 主线]]：先按容器分类、`vector`、`map/unordered_map`、`rehash`、`allocator` 这条线复习。
- [[09 STL与容器#STL 中 allocator 的作用|allocator]]：把原始内存分配释放和对象构造析构分离开，容器因此能切换不同内存策略。
- [[09 STL与容器#STL 中迭代器失效的场景|迭代器失效]]：容器结构变化后旧迭代器可能失效；`vector` 扩容和 `unordered_map` 的 `rehash` 触发后是高频坑，删除遍历时优先接 `erase` 返回值。
- [[09 STL与容器#map 和 unordered_map 的区别与实现原理|map 和 unordered_map]]：`map` 是红黑树，天然有序，复杂度稳定 `O(log n)`；`unordered_map` 是哈希表，平均 `O(1)`，但冲突严重时最坏会退化到 `O(n)`。
- [[09 STL与容器#map deque list 的底层实现原理|map / deque / list]]：`map` 是红黑树，`deque` 是分段连续空间，`list` 是双向链表；`deque` 头尾操作强，`list` 中间插删强，`map` 适合有序键值场景。
- [[09 STL与容器#unordered_map 的 rehash 机制|unordered_map 的负载因子和 rehash]]：负载因子是 `size / bucket_count`，太高时会触发 rehash，把所有元素重新分桶；这个过程是 `O(n)`，并且会让迭代器失效。预先知道元素规模时优先用 `reserve`。
- [[09 STL与容器#vector 底层原理和扩容过程|vector 底层和扩容]]：`vector` 是连续内存动态数组，随机访问 `O(1)`；满了会申请更大新空间，把旧元素搬过去再释放旧空间。扩容会让旧迭代器失效，预先知道规模时用 `reserve`。
- [[09 STL与容器#push_back 和 emplace_back 的区别|push_back 和 emplace_back]]：`push_back` 放的是现成对象，`emplace_back` 传的是构造参数并原地构造。一般“有现成对象用 push，需要现场构造用 emplace”；但 `emplace_back` 也不是永远更快，扩容时已有元素照样要搬迁。

- [[05 关键字与类型推导#inline 函数和宏的区别|inline 和宏]]：能用函数解决的优先用 `inline/constexpr`，宏更适合条件编译和 `#`、`##`。
- [[05 关键字与类型推导#auto 和 decltype 的区别|auto 和 decltype]]：`auto` 省类型名，`decltype` 精确拿表达式类型。

## 生命周期与静态

- [[06 内存生命周期与静态成员#局部变量 全局变量 静态局部变量|局部变量、静态局部变量、全局变量]]：作用域、生命周期、初始化行为和存储位置不同。
- [[06 内存生命周期与静态成员#静态成员变量必须类外定义|静态成员变量类外定义]]：类内通常只是声明，类外才是真正定义。
- [[06 内存生命周期与静态成员#new 对象和 new 数组|new 对象和 new 数组]]：`new[]` 配 `delete[]`，`new` 配 `delete`。

## 内存管理

- [[10 内存管理|内存管理主线]]：后面按内存分区 -> `new/malloc` -> `delete/free` -> `placement new` -> 泄漏/野指针/越界 -> 碎片与溢出 这条线复习。
- [[10 内存管理#C++ 内存分区，堆和栈的区别|内存分区、堆和栈]]：代码段、全局静态（数据段和BSS段）、常量区（只读数据段）、栈区、堆区。栈自动管理、快但小；堆手动管理、空间大但容易泄漏和碎片化。
- [[10 内存管理#new 和 malloc 的区别是什么|new 和 malloc]]：`new` 是对象级操作，负责“分配 + 构造”；`malloc` 是内存级操作，只负责分配原始内存。`new` 更类型安全，失败抛异常；`malloc` 返回 `NULL`。
- [[10 内存管理#free 和 delete 的区别是什么|free 和 delete]]：`free` 只释放原始内存，不调析构；`delete` 会先调析构再释放内存。对象数组一定要 `new[]` 配 `delete[]`，不能混用。
- [[10 内存管理#placement new 的作用|placement new]]：只在指定地址上原地构造对象，不负责申请内存。常用于内存池、对象池、共享内存；用完通常要显式析构，再按原始内存来源释放。
- [[10 内存管理#什么是内存泄漏 什么是野指针 什么是内存越界 如何避免|泄漏、野指针、越界]]：忘了还叫泄漏，用了废的叫野指针，越界胡来叫内存越界。减少裸指针、释放后置空、严格做边界检查，是最基本的防法。
- [[10 内存管理#内存碎片与内存溢出|内存碎片与内存溢出]]：碎片是“有空闲但不好用”，溢出是“空间不够了”或越界把堆/栈结构弄坏。外部碎片比内部碎片更难处理。
- [[10 内存管理#如何避免内存碎片|避免内存碎片]]：核心是减少频繁小块申请释放。常见手段有 `reserve`、对象池、内存池、复用对象、优先用连续容器和 RAII。

## C++11 与现代 C++

- [[11 C++11与现代C++|现代 C++ 主线]]：后面按新特性 -> 右值引用 -> 移动语义 -> 完美转发 -> `move/forward` -> `lambda` -> RAII -> 异常 -> 协程 这条线复习。
- [[11 C++11与现代C++#C++11 中的新特性有哪些|C++11 新特性]]：高频可以按三类记：语法增强（`auto`、范围 for、`lambda`）、性能与资源管理（右值引用、移动语义、智能指针）、标准库与并发（`thread`、`mutex`、`atomic`、`unordered_map`、变参模板）。
- [[11 C++11与现代C++#C++11 中的多线程编程|C++11 多线程与锁]]：核心组件是 `thread`、`mutex`、`lock_guard`、`unique_lock`、`condition_variable`、`atomic`。简单临界区常用 `lock_guard`，需要条件变量或灵活控制时用 `unique_lock`。
- [[11 C++11与现代C++#左值引用和右值引用的区别|左值引用和右值引用]]：左值引用 `T&` 绑定到已有对象，右值引用 `T&&` 绑定到临时对象或将亡值。右值引用是移动语义和完美转发的基础；模板里的 `T&&` 还可能是万能引用。
- [[11 C++11与现代C++#移动语义有什么作用，原理是什么|移动语义]]：移动语义的本质是“搬家而不是克隆”，通过右值引用接住临时对象，再用移动构造 / 移动赋值把资源转走。`std::move` 本身不移动数据，只是发放“可以移动”的许可。
- [[11 C++11与现代C++#完美转发的作用及实现|完美转发]]：目标是在模板里把参数原样转交下去，不丢左值 / 右值和 `const` 属性。核心是 `T&&`、引用折叠和 `std::forward`；`std::move` 无条件转右值，`std::forward` 按推导结果保留值类别。
- [[11 C++11与现代C++#std move 与 std forward 的区别|std::move 和 std::forward]]：`std::move` 无条件把对象转成右值引用，发放“可以移动”的许可；`std::forward` 主要用于模板里，按推导结果保留参数原本是左值还是右值，实现完美转发。
- [[11 C++11与现代C++#lambda 函数|lambda]]：Lambda 是匿名函数对象，语法是 `[捕获列表](参数列表){函数体}`。它特别适合 STL 算法、回调和局部小逻辑；本质上是编译器生成的闭包类对象，不是普通函数指针。
- [[11 C++11与现代C++#仿函数与 lambda 性能对比|仿函数和 lambda 性能]]：现代编译器下两者性能通常基本相当，因为 lambda 本质上也会变成闭包类对象。真正影响性能的常常是捕获方式和代码场景，而不是“lambda 还是仿函数”这个表面形式。
- [[11 C++11与现代C++.md#C++ 中的 RAII 机制|RAII]]：资源获取即初始化，资源释放绑定到对象生命周期。构造时拿资源，析构时还资源，所以它天然适合异常安全；智能指针、锁守卫、文件对象本质上都在体现 RAII。
- [[11 C++11与现代C++.md#C++ 中的异常处理机制|异常处理]]：C++ 用 `try-throw-catch` 做结构化错误处理。异常传播时会发生栈展开，已构造局部对象会自动析构，所以它和 RAII 天然配合；析构函数一般不应抛异常。
- [[11 C++11与现代C++.md#C++ 中的协程概念及实现|协程]]：协程是可挂起、可恢复的函数机制，核心关键字是 `co_await`、`co_yield`、`co_return`。它适合异步 I/O、生成器和状态机；本质上不是线程，而是更轻量的控制流切换抽象。

## 智能指针

- [[12 智能指针#什么是智能指针，C++ 中有哪几种智能指针|智能指针概览]]：`unique_ptr` 独占所有权，`shared_ptr` 共享所有权，`weak_ptr` 弱引用不增加计数，主要用来打破循环引用。它们本质上都体现了 RAII。
- [[12 智能指针#智能指针的实现原理是什么|智能指针原理]]：智能指针本质是类模板，靠构造接管资源、析构自动释放资源，并重载 `*` 和 `->` 模拟指针行为。`shared_ptr` 的关键是控制块和引用计数，`weak_ptr` 则共享控制块但不增加强引用计数。
- [[12 智能指针#C++11 中的智能指针线程安全性|智能指针线程安全]]：`shared_ptr`/`weak_ptr` 的控制块引用计数通常线程安全，但这不等于对象本身线程安全；多个线程同时修改同一个 `shared_ptr` 实例也需要同步。

## 并发与 I/O

- [[13 并发与IO#互斥锁与自旋锁|互斥锁与自旋锁]]：互斥锁抢不到时阻塞挂起，省 CPU 但有上下文切换；自旋锁抢不到时忙等待，延迟低但烧 CPU。短临界区偏自旋，长临界区偏互斥。
- [[13 并发与IO#select poll 和 epoll|select、poll、epoll]]：三者都是 I/O 多路复用。`select` 有 fd 上限，`poll` 去掉了上限但仍线性遍历，`epoll` 直接返回就绪列表，更适合 Linux 高并发场景；`epoll` 还支持 LT/ET 两种触发模式。
