## I/O 控制方式有哪些

### 简要回答

常见 I/O 控制方式有程序直接控制、中断驱动、DMA、通道控制。

### 详细回答

- 程序直接控制：CPU 主动轮询设备状态，效率低。
- 中断驱动：设备完成后用中断通知 CPU。
- DMA：设备和内存直接交换数据，减少 CPU 拷贝负担。
- 通道控制：更专门的 I/O 处理机制。

### 对比理解

程序直接控制方式下，CPU 要不断轮询设备，浪费 CPU；中断方式让设备完成后再通知 CPU；DMA 进一步让数据在设备和内存之间直接传输，CPU 只负责初始化和收尾。

## 缓冲区是什么

### 简要回答

缓冲区是内存中的一块临时区域，用来协调高速 CPU 和低速 I/O 设备之间的速度差异。

### 作用

- 缓解速度不匹配。
- 减少频繁 I/O 次数。
- 支持批量读写。
- 提高吞吐量。

### 面试表达

> 缓冲区的核心价值是“削峰填谷”。CPU 和设备速度差很多，缓冲区可以让数据先暂存起来，减少双方直接等待。

## 零拷贝是什么

### 简要回答

零拷贝是减少数据在用户态和内核态之间来回复制的技术，目标是降低 CPU 拷贝开销，提高 I/O 性能。

### 传统文件发送

```text
磁盘 -> 内核缓冲区 -> 用户缓冲区 -> socket 缓冲区 -> 网卡
```

### 零拷贝思路

通过 `sendfile`、`mmap` 等方式减少用户态拷贝，让数据尽量在内核态完成转发。

### 面试表达

> 零拷贝不是完全没有拷贝，而是减少不必要的 CPU 数据拷贝，尤其适合文件传输、静态资源服务器这类场景。

## 常见 I/O 模型有哪些

### 简要回答

常见有阻塞 I/O、非阻塞 I/O、I/O 多路复用、信号驱动 I/O、异步 I/O。

### 面试表达

> 阻塞 I/O 是调用后一直等；非阻塞 I/O 是没准备好就返回；I/O 多路复用是一个线程同时等待多个 fd；异步 I/O 是提交请求后由内核完成并通知结果。

### 五种模型

1. 阻塞 I/O：等待数据准备和数据拷贝都阻塞。
2. 非阻塞 I/O：数据没准备好立即返回，需要反复轮询。
3. I/O 多路复用：用 `select/poll/epoll` 同时监听多个 fd。
4. 信号驱动 I/O：数据准备好后用信号通知进程。
5. 异步 I/O：内核完成整个 I/O 后通知用户程序。

## select、poll、epoll 有什么区别

### 简要回答

`select`、`poll`、`epoll` 都是 I/O 多路复用机制，`epoll` 更适合大量连接。

### 对比表

| 对比点 | select | poll | epoll |
|---|---|---|---|
| fd 集合 | 位图 | 数组 | 内核事件表 |
| fd 数量限制 | 通常有 FD_SETSIZE 限制 | 无固定小限制 | 适合大量 fd |
| 返回后处理 | 遍历全部 | 遍历全部 | 返回就绪事件 |
| 性能特点 | 大量连接效率低 | 比 select 灵活 | 高并发更常用 |

相关：[[../C++/13 并发与IO#select poll 和 epoll|select、poll、epoll]]

### epoll 为什么高效

- 监听集合保存在内核里，不需要每次都完整传入。
- 就绪事件通过事件列表返回，不需要遍历所有 fd。
- 支持水平触发和边沿触发。
- 适合大量连接、少量活跃的场景。

### 易错点

`epoll` 并不是所有场景都绝对更快。如果 fd 数量很少，`select/poll` 也够用；`epoll` 的优势主要体现在高并发连接场景。

## 磁盘调度算法有哪些

### 简要回答

常见有先来先服务、最短寻道时间优先、扫描算法、电梯算法、循环扫描。

### 详细回答

- FCFS：按请求到达顺序处理。
- SSTF：优先处理距离当前磁头最近的请求。
- SCAN：磁头像电梯一样单方向移动处理请求。
- C-SCAN：只在一个方向处理，到头后快速回到起点。

## 设备管理主要做什么

### 简要回答

设备管理负责设备分配、设备驱动、缓冲管理、中断处理和设备独立性。

### 详细回答

- 设备分配：决定设备给哪个进程使用。
- 设备驱动：屏蔽具体硬件差异。
- 缓冲管理：协调 CPU 和设备速度差异。
- 中断处理：响应设备完成事件。
- 设备独立性：应用程序不需要关心具体硬件型号。
