## TCP 和 UDP 有什么区别

### 简要回答

TCP 面向连接、可靠、有序、面向字节流；UDP 无连接、不保证可靠和有序、面向数据报。

### 对比表

| 对比点 | TCP | UDP |
|---|---|---|
| 连接 | 面向连接，通信前要三次握手 | 无连接，直接发送 |
| 可靠性 | 有 ACK、重传、序列号等机制 | 尽力而为，不保证到达 |
| 顺序 | 保证数据按序交付 | 不保证顺序 |
| 数据边界 | 字节流，无天然消息边界 | 数据报，保留报文边界 |
| 头部开销 | 至少 20 字节 | 8 字节 |
| 流量控制 | 有滑动窗口 | 没有 |
| 拥塞控制 | 有慢启动、拥塞避免等 | 没有 |
| 典型场景 | HTTP/HTTPS、文件传输、邮件 | DNS、直播、游戏、语音视频 |

### 面试表达

> TCP 适合可靠性要求高的场景，UDP 适合实时性要求高、能容忍少量丢包的场景。TCP 的“慢”主要来自连接建立、确认重传、流量控制和拥塞控制这些可靠性成本。

## HTTP 常见请求方法有哪些

### 简要回答

常见有 GET、POST、PUT、DELETE、HEAD、OPTIONS、TRACE、CONNECT，后续还扩展了 PATCH。

### 详细回答

| 方法 | 作用 | 是否常见 | 记忆点 |
|---|---|---|---|
| GET | 获取资源 | 常见 | 查数据，不应该改变服务器状态 |
| POST | 提交数据或创建资源 | 常见 | 表单提交、登录、创建订单 |
| PUT | 整体更新资源 | 常见 | 用新资源整体替换旧资源 |
| PATCH | 局部更新资源 | 常见 | 只改某几个字段 |
| DELETE | 删除资源 | 常见 | 删除指定资源 |
| HEAD | 只获取响应头 | 较少 | 用于检查资源是否存在、大小、缓存信息 |
| OPTIONS | 查询服务器支持的方法 | 较少 | 常见于 CORS 预检请求 |
| TRACE | 回显请求路径 | 很少 | 主要用于诊断，实际常禁用 |
| CONNECT | 建立隧道 | 较少 | HTTPS 代理常见 |

### 安全性和幂等性

| 概念 | 含义 | 例子 |
|---|---|---|
| 安全方法 | 不应该修改服务器资源 | GET、HEAD、OPTIONS |
| 幂等方法 | 执行多次和执行一次效果相同 | GET、PUT、DELETE |
| 非幂等方法 | 多次执行可能产生多个结果 | POST |

### 示例

```http
# OPTIONS 常用于跨域预检：浏览器先问服务器是否允许后续请求
OPTIONS /api/users HTTP/1.1
Host: example.com

# CONNECT 常用于代理建立 HTTPS 隧道
CONNECT www.example.com:443 HTTP/1.1
Host: www.example.com:443
```

## GET 和 POST 有什么区别

### 简要回答

GET 通常用于获取资源，参数常放 URL；POST 通常用于提交数据，参数常放请求体。

### 对比表

| 对比点 | GET | POST |
|---|---|---|
| 语义 | 获取资源 | 提交数据、创建资源或触发处理 |
| 参数位置 | 常在 URL 查询参数 | 常在请求体 body |
| 幂等性 | 通常幂等 | 通常不保证幂等 |
| 缓存 | 更容易被浏览器或代理缓存 | 默认不容易缓存 |
| 书签/分享 | URL 可直接保存和分享 | 请求体不会体现在 URL |
| 安全性 | 参数暴露在 URL 中 | 参数不在 URL 中，但没有 HTTPS 仍然可能被抓包 |
| 数据大小 | 受浏览器、服务器、URL 长度限制 | 理论上更适合传大数据，但也受服务器配置限制 |

### 易错点

- POST 不等于安全，只是不把参数直接放在 URL 上；真正防窃听要用 HTTPS。
- GET 不应该用来做删除、扣款、下单这类有副作用的操作。
- 数据大小限制不是 HTTP 协议本身严格规定的，而是浏览器、服务器、网关配置共同决定。

## HTTP 状态码有哪些

### 简要回答

状态码按首位分为 1xx、2xx、3xx、4xx、5xx。

### 分类

| 分类 | 含义 | 例子 |
|---|---|---|
| 1xx | 信息提示，请求处理中 | 100、101 |
| 2xx | 请求成功 | 200、201、204、206 |
| 3xx | 重定向或缓存相关 | 301、302、304、307 |
| 4xx | 客户端错误 | 400、401、403、404 |
| 5xx | 服务器错误 | 500、502、503 |

### 高频状态码

| 状态码 | 含义 | 面试记忆点 |
|---|---|---|
| `200 OK` | 请求成功 | 最常见成功响应 |
| `201 Created` | 创建成功 | POST 创建资源常见 |
| `204 No Content` | 成功但无响应体 | 删除成功可用 |
| `206 Partial Content` | 部分内容 | 断点续传、范围请求 |
| `301 Moved Permanently` | 永久重定向 | 搜索引擎会更新地址 |
| `302 Found` | 临时重定向 | 临时跳转 |
| `304 Not Modified` | 资源未修改 | 协商缓存命中 |
| `400 Bad Request` | 请求格式错误 | 参数、语法错误 |
| `401 Unauthorized` | 未认证 | 没登录或 token 无效 |
| `403 Forbidden` | 无权限 | 登录了但权限不够 |
| `404 Not Found` | 资源不存在 | 路径或资源找不到 |
| `500 Internal Server Error` | 服务器内部错误 | 后端代码或服务异常 |
| `502 Bad Gateway` | 网关错误 | 网关访问上游失败 |
| `503 Service Unavailable` | 服务不可用 | 服务过载、维护、限流 |

### 示例

```http
# 协商缓存命中：浏览器问服务器资源是否变化，服务器说没变
HTTP/1.1 304 Not Modified

# 范围请求成功：只返回文件的一部分，常用于视频拖动、断点续传
HTTP/1.1 206 Partial Content
Content-Range: bytes 0-499/1000
```

## HTTP 头部字段有哪些

### 简要回答

HTTP Header 放的是请求或响应的元信息，比如域名、客户端类型、内容类型、认证信息、缓存策略、Cookie 等。

### 请求头

| 请求头 | 作用 | 示例 |
|---|---|---|
| `Host` | 指定访问的域名，支持同一 IP 多站点 | `Host: www.example.com` |
| `User-Agent` | 标识客户端类型 | `User-Agent: Mozilla/5.0` |
| `Accept` | 告诉服务器客户端能接受什么格式 | `Accept: application/json` |
| `Authorization` | 携带认证信息 | `Authorization: Bearer token` |
| `Cookie` | 携带浏览器保存的 Cookie | `Cookie: JSESSIONID=abc123` |

### 响应头和通用头

| 头字段 | 作用 | 示例 |
|---|---|---|
| `Server` | 服务器软件信息 | `Server: nginx` |
| `Set-Cookie` | 服务器让浏览器保存 Cookie | `Set-Cookie: sid=abc; HttpOnly` |
| `Location` | 重定向目标地址 | `Location: /login` |
| `Cache-Control` | 缓存控制 | `Cache-Control: max-age=3600` |
| `Connection` | 连接管理 | `Connection: keep-alive` |
| `Content-Type` | 响应体类型 | `Content-Type: text/html` |
| `Content-Length` | 响应体长度 | `Content-Length: 1024` |
| `Content-Encoding` | 内容压缩方式 | `Content-Encoding: gzip` |

### 示例

```http
# 请求 JSON 数据
GET /api/users HTTP/1.1
Host: example.com
Accept: application/json
Authorization: Bearer xxxxxx
Cookie: JSESSIONID=abc123

# 服务器返回 HTML，并设置 Cookie
HTTP/1.1 200 OK
Content-Type: text/html
Content-Length: 1024
Set-Cookie: JSESSIONID=abc123; HttpOnly; Secure
```

### 面试表达

> Header 不是业务正文，而是协议元信息。比如 `Host` 决定访问哪个站点，`Content-Type` 决定 body 怎么解析，`Cookie` 和 `Authorization` 负责身份状态，`Cache-Control` 负责缓存策略。

## 常见网络排查命令

### 简要回答

常用 `ping`、`curl`、`telnet`、`nc`、`ss`、`netstat`、`lsof`、`tcpdump`、`traceroute`。

### 常用命令表

| 命令 | 作用 | 常见用法 |
|---|---|---|
| `ping` | 测网络是否可达 | `ping www.baidu.com` |
| `curl` | 发送 HTTP 请求 | `curl -I https://example.com` |
| `telnet` | 测端口是否能连 | `telnet 127.0.0.1 80` |
| `nc` | 测端口、收发数据 | `nc -vz 127.0.0.1 80` |
| `ss` | 查看连接和监听端口 | `ss -tunlp` |
| `netstat` | 查看网络连接 | `netstat -tunlp` |
| `lsof` | 查看端口被哪个进程占用 | `lsof -i:8080` |
| `tcpdump` | 抓包分析 | `tcpdump -i eth0 port 80` |
| `traceroute` | 查看路由路径 | `traceroute example.com` |
