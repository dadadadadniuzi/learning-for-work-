# SIGTERM

## 它是什么

- `SIGTERM` 是常见的“请求进程正常终止”的信号。

## 怎么理解

- 它的语气更像“请你结束运行并做收尾工作”，而不是立刻强制杀死。
- 默认动作通常是终止进程。
- 和 `SIGKILL` 不同，`SIGTERM` 一般可以被程序捕捉、忽略或自定义处理。

## 常见触发场景

- 管理员或程序主动要求某个进程退出。
- 服务程序准备优雅关闭时。
- 使用 `kill -15` 或默认 `kill pid` 时。

## 为什么它很常见

- 很多服务端程序收到 `SIGTERM` 后，会先做清理动作：
  - 关闭文件
  - 刷新缓冲区
  - 释放资源
  - 通知子进程退出
- 所以它比“直接强杀”更适合正式环境停服务。

## 和 `SIGKILL` 的区别

- `SIGTERM`
  - 可以被捕捉
  - 可以做善后处理
  - 更适合优雅退出

- `SIGKILL`
  - 不能被捕捉或忽略
  - 内核直接终止进程
  - 更像强制结束

## 易错点

- `kill pid` 默认发的通常就是 `SIGTERM`，不是 `SIGKILL`。
- 如果程序屏蔽或忽略了 `SIGTERM`，它不一定立刻退出。
- 学信号时不要把“终止信号”都混成一种；不同信号在可否捕捉、使用场景上有差别。
