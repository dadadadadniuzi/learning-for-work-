# strncpy

> [!info] 功能
> 从源字符串中最多复制 `n` 个字符到目标缓冲区，常用于“有长度上限”的字符串复制场景。

## 函数原型

- `char *strncpy(char *dest, const char *src, size_t n);`

## 依赖头文件

- `#include <string.h>`

## 输入参数

- `dest`
  目标缓冲区首地址。`strncpy` 会把复制结果写到这里，所以这里必须指向一块可写内存，而且容量至少要能容纳你希望写入的内容。

- `src`
  源字符串首地址。函数会从这里开始读取字符，直到：
  - 已经复制了 `n` 个字符
  - 或者先遇到了源字符串结尾 `\0`

- `n`
  最多复制多少个字符，类型是 [[linux系统编程/概念词条/size_t|size_t]]。
  这里的 `n` 是“复制上限”，不是“目标字符串最终长度一定是多少”。

## 输出参数

- `dest`
  保存复制后的结果。

## 返回值

- 成功时返回目标缓冲区指针，也就是 `dest`。

## 怎么理解

`strncpy` 可以理解成“带数量上限的 `strcpy`”，但它和很多初学者想象得不太一样，最关键的点有两个：

- 如果 `src` 的长度小于 `n`，函数会在复制完原字符串后，继续用 `\0` 把后面的剩余位置补满
- 如果 `src` 的长度大于或等于 `n`，那么结果**可能不会自动补 `\0`**

这也是它最容易出错的地方。

## 常见用法

```c
#include <stdio.h>
#include <string.h>

int main(void) {
    char buf[8];

    strncpy(buf, "linux", sizeof(buf) - 1);
    buf[sizeof(buf) - 1] = '\0';

    printf("%s\n", buf);
    return 0;
}
```

## 典型场景

- 只想复制固定上限长度的字符串
- 从较长输入里截取前面一部分
- 处理固定长度字符数组

## 易错点

- `strncpy` **不保证**结果一定以 `\0` 结尾
- 如果你把 `n` 直接写成目标缓冲区总大小，复制满时可能没有字符串结尾符
- 它适合“固定长度复制”，但不一定适合所有“安全字符串复制”场景

## 和相关函数的区别

- `strcpy`：复制直到遇到 `\0`，不限制长度，容易越界
- `strncpy`：最多复制 `n` 个字符，但可能不自动补结尾 `\0`
- `memcpy`：按字节拷贝，不关心字符串结尾

## 知识点补充

- 如果你想安全地复制字符串，常见写法是：
  - `strncpy(dest, src, size - 1);`
  - 然后手动写 `dest[size - 1] = '\0';`
- `strncpy` 在处理“定长结构体字段”时很常见，比如某些协议字段、文件头字段、数据库固定长度名字字段
