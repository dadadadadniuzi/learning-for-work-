上一条会话里继续完成了两个问题：

1. HTTP 请求没有读全会不会阻塞？
   - 结论：不会。
   - 因为连接 fd 是非阻塞的。
   - 半包时 `parse_line()` 返回 `LINE_OPEN`，`process_read()` 返回 `NO_REQUEST`。
   - `process()` 会重新监听 `EPOLLIN` 并返回，工作线程不会一直占着这个任务。
   - 半包连接会保留资源，直到客户端补齐、主动断开，或者定时器超时回收。

2. 多人同时注册同一账号，以及大量注册时怎么保持并发？
   - 当前实现用全局 `users` map 和 `m_lock` 保护注册写入。
   - 设计意图是避免多线程同时改共享用户表。
   - 问题是 `users.find(name)` 在加锁前，存在竞态；数据库若无唯一约束，可能重复插入。
   - 全局锁会让注册写入串行化，高并发注册吞吐会下降。
   - 更好的回答是：用户名唯一性交给数据库唯一索引，服务端去掉包住数据库 I/O 的大锁，只在更新内存缓存时加短锁，必要时用分段锁或并发哈希表。

## 当前项目知识主线

TinyWebServer 是一个运行在 Linux 上的轻量级 C++ Web 服务器，核心是：

- `socket`
- `epoll`
- 非阻塞 I/O
- 线程池
- HTTP 状态机
- MySQL 连接池
- 定时器
- 同步/异步日志
- `mmap + writev` 静态文件响应

源码模块分工：

| 模块 | 作用 |
| --- | --- |
| `WebServer` | 总控，负责启动、初始化、事件循环、信号和定时器调度。 |
| `http_conn` | 表示单个客户端连接，负责读写、HTTP 解析、业务处理和响应构造。 |
| `threadpool` | 保存任务队列，工作线程不断取出 `http_conn` 任务执行。 |
| `sql_connection_pool` | 复用 MySQL 连接，减少频繁创建连接的开销。 |
| `timer` | 用升序双向链表管理连接超时，回收空闲连接。 |
| `log` | 支持同步日志和异步日志，异步日志依赖阻塞队列。 |
| `locker` | 封装互斥锁、信号量、条件变量等同步原语。 |
