# C++ 内存生命周期与静态成员

## 局部变量 全局变量 静态局部变量

### 简要回答

局部变量、静态局部变量、全局变量最大的区别在于：**作用域、生命周期、初始化行为和存储位置不同**。

- 局部变量：函数或代码块内定义，每次进入作用域创建，离开作用域销毁，通常在栈上，适合临时计算。
- 静态局部变量：函数内用 `static` 修饰，作用域仍在函数内，但生命周期贯穿程序运行期，只初始化一次，适合在函数内部记住上一次调用的状态。
- 全局变量：函数外定义，生命周期贯穿程序运行期，默认零初始化，通常在全局/静态存储区，不是在堆上，适合少量全局共享状态。

### 对比表

| 分类 | 局部变量 | 静态局部变量 | 全局变量 |
|---|---|---|---|---|
| 作用域 | 当前函数或代码块内 | 当前函数内部，外部不能访问 | 文件内；通过 `extern` 可跨文件访问 |
| 生命周期 | 每次进入作用域创建，离开作用域销毁 | 程序运行期 | 程序运行期 |
| 初始化行为 | 不初始化时值不确定 | 只初始化一次，默认初始化为 0 | 默认初始化为 0 |
| 存储位置 | 通常在栈区 | 全局/静态存储区，常见为 data 或 BSS | 全局/静态存储区，常见为 data 或 BSS |
| 适合场景 | 临时变量、中间计算、循环计数 | 函数内计数器、缓存、只初始化一次的状态 | 全局配置、程序状态、共享缓冲区，慎用 |

```cpp
void func() {
    static int count = 0;
    count++;
    cout << count << endl;
}
```

### 全局变量

全局变量定义在所有函数外面，生命周期从程序启动到程序结束。它默认会被初始化为 0，存储在全局/静态存储区。

```cpp
int g_count = 0;
```

如果要在其他文件中使用这个全局变量，需要用 `extern` 声明。

```cpp
// a.cpp
int g_count = 0;

// b.cpp
extern int g_count;
```

如果全局变量前加 `static`，它就变成当前文件私有，其他 `.cpp` 文件无法通过 `extern` 访问，可以减少命名冲突。

```cpp
static int file_private_count = 0;
```

使用建议：全局变量适合少量确实需要全局共享的数据，比如配置参数、程序状态、共享缓冲区。但不建议滥用，因为它会增加模块耦合，让程序更难维护和测试。

### 静态局部变量

静态局部变量定义在函数内部，用 `static` 修饰。

```cpp
void callMe() {
    static int times = 0;
    times++;
    cout << times << endl;
}
```

它的特点是：**作用域小，生命周期长**。外部不能直接访问它，但函数执行结束后它不会销毁，下次调用还能保留上次的值。

初始化特点：

- 只在第一次执行到声明语句时初始化一次。
- 后续调用不会重新初始化。
- 没有显式初始化时默认初始化为 0。

适合场景：

- 函数内部计数器。
- 递归深度或状态控制。
- 缓存上一次计算结果。
- 记录某个初始化动作是否已经执行。

### 局部变量

局部变量定义在函数或代码块内部，生命周期随着作用域进入和离开而开始和结束。

```cpp
void work() {
    int temp = 10;
}
```

它通常存储在栈上，创建和销毁开销小，访问速度快。没有初始化的普通局部变量值不确定。

```cpp
void foo() {
    int x; // 值不确定，不要直接使用
}
```

如果局部变量和全局变量同名，在当前作用域内会优先使用局部变量，相当于暂时屏蔽同名全局变量。

```cpp
int value = 1;

void foo() {
    int value = 2;
    cout << value << endl; // 2
}
```

适合场景：

- 临时数据。
- 循环计数器。
- 函数内部中间计算结果。
- 普通业务逻辑中能局部化的数据。

### 怎么用

优先使用局部变量。它作用域最小、生命周期最短，最干净，也最不容易引入隐藏依赖。

需要在函数内部记住上一次调用状态时，使用静态局部变量。比如计数器、缓存、只初始化一次的状态。

全局变量只在确实需要全局共享时使用。使用时要命名清楚、注释清楚，尽量避免到处读写。

### 面试表达

静态局部变量的特点是“作用域小，生命周期长”：外部不能直接访问它，但它不会随着函数返回而销毁。

## new 对象和 new 数组

```cpp
A* p = new A();    // 调用一次构造函数
A* arr = new A[3]; // 调用三次构造函数
```

释放时：

```cpp
delete p;     // 调用一次析构函数
delete[] arr; // 调用三次析构函数
```

### 易错点

`new[]` 要配 `delete[]`，`new` 要配 `delete`。

## 静态成员变量必须类外定义

### 规则

类内的 `static` 成员变量声明不等于定义。通常必须在类外定义一次。

```cpp
class A {
public:
    static int count; // 声明
};

int A::count = 0; // 定义
```

### 为什么不能在 main 函数里定义

静态成员变量是类的成员，它的定义必须在命名空间作用域下完成。写在 `main` 函数里会变成局部语句，不符合静态成员变量定义语法。

### ODR 是什么

ODR 是 One Definition Rule，唯一定义规则。简单说：一个具有外部链接的对象或函数，在整个程序中应该有且只有一个定义。

### 面试表达

类内 `static` 成员变量只是告诉编译器“类里有这个成员”；类外定义才是真正给它分配存储空间。

## 饿汉式单例中的静态成员初始化

```cpp
class single {
private:
    static single* p;
    single() {}

public:
    static single* getInstance() {
        return p;
    }
};

single* single::p = new single();
```

### 为什么 `single* single::p = new single();` 必须在类外

因为 `p` 是静态成员变量，类内只是声明，类外这句才是定义和初始化。

### 为什么类外这句仍然能访问 private 构造函数

关键点在于：`p` 是 `single` 类的静态成员，而

```cpp
single* single::p = new single();
```

这条语句是在定义这个类自己的静态成员。

虽然它写在类外，但它仍然处于“类成员定义”的语境中，使用的是 `single::` 这个类作用域限定，因此可以访问该类的私有构造函数。

对比普通类外代码：

```cpp
single* q = new single(); // 错
```

这只是普通外部代码，不属于类成员定义，自然不能访问 `private` 构造函数。

### 静态成员变量为什么必须单独定义

类内写：

```cpp
class Singleton {
    static Singleton* instance;
};
```

这里只是声明，不分配存储空间。

类外写：

```cpp
Singleton* Singleton::instance = new Singleton();
```

这才是真正的定义和初始化。这是 C++ 对静态成员变量的基本规则。

### 为什么这是饿汉式

`single::p` 在程序进入 `main` 之前就会完成初始化，对象提前创建好，所以叫饿汉式。

### 这行代码什么时候执行

```cpp
single* single::p = new single();
```

它属于静态存储期对象初始化的一部分，通常发生在程序启动阶段，也就是 `main` 执行之前。

所以饿汉式的特点就是：实例提前创建，获取最简单，但即使程序没用到它，也已经占用了资源。

### 面试表达

饿汉式单例的特点是实例提前创建，获取时简单，但可能带来启动期开销；它依赖静态成员变量的类外定义和静态初始化。

### 一句话记忆法

静态成员变量必须类外定义；定义时虽然写在类外，但仍然属于这个类成员的定义语境，所以可以访问 private 构造函数。

## 数组和对象生命周期

数组创建后不能被整体重新赋值，详见：[[03 指针引用与数组#数组为什么不能事后整体赋值]]

对象指针只是保存地址，不代表对象存在：

```cpp
A* p = nullptr; // 没有创建对象，不调用构造函数
```

## 面试速背

1. 局部变量生命周期短，全局变量和静态变量生命周期贯穿程序运行期。
2. 静态局部变量作用域在函数内，但生命周期是整个程序。
3. 静态成员变量属于类，所有对象共享一份。
4. 静态成员变量通常必须类外定义一次。
5. 饿汉式单例在 `main` 之前初始化静态实例。
6. `new[]` 调多次构造，`delete[]` 调多次析构。
