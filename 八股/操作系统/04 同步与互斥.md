## 同步和互斥有什么区别

### 简要回答

互斥解决“同一时刻只能一个线程访问临界资源”；同步解决“多个线程按一定顺序协作”。

### 面试表达

> 互斥强调资源访问不能同时发生，同步强调执行顺序要满足依赖关系。互斥是同步的一种常见手段，但同步不只靠互斥。

## 临界区是什么

### 简要回答

临界区是访问共享资源的代码区域，同一时间通常只能允许一个线程或进程进入。

### 详细回答

临界区要解决的是并发访问共享资源导致的数据竞争问题。进入临界区前通常要加锁，离开临界区后释放锁。

### 面试表达

> 临界区不是某个特殊内存区域，而是一段需要互斥保护的代码。只要这段代码会访问共享资源，就可能需要同步控制。

## 线程同步方式有哪些

### 简要回答

常见有互斥锁、读写锁、自旋锁、条件变量、信号量、原子操作。

### 详细回答

- 互斥锁：保护临界区。
- 读写锁：读多写少时提高并发。
- 自旋锁：短临界区、低竞争场景。
- 条件变量：等待某个条件成立。
- 信号量：控制资源数量或线程协作。
- 原子操作：适合简单计数和状态切换。

### 内核级线程和用户级线程

内核级线程常见同步方式：

- 互斥锁
- 信号量
- 条件变量
- 读写锁
- 自旋锁

用户级线程常见同步方式：

- 原子操作
- 用户态自旋锁
- 用户态调度器维护的条件等待队列

### 代码示例：条件变量等待队列非空

```cpp
std::mutex mtx;
std::condition_variable cv;
std::queue<int> q;

void consumer() {
    std::unique_lock<std::mutex> lock(mtx);
    cv.wait(lock, [] { return !q.empty(); });
    int task = q.front();
    q.pop();
}
```

这里 `wait` 必须配合条件判断，是为了处理虚假唤醒。

## 互斥锁和自旋锁有什么区别

### 简要回答

互斥锁抢不到会阻塞挂起，自旋锁抢不到会忙等。

### 对比表

| 对比点 | 互斥锁 | 自旋锁 |
|---|---|---|
| 等待方式 | 阻塞睡眠 | 忙循环 |
| CPU 消耗 | 较低 | 较高 |
| 上下文切换 | 可能发生 | 通常不发生 |
| 适合场景 | 临界区较长 | 临界区极短 |

相关：[[../C++/13 并发与IO#互斥锁与自旋锁|互斥锁与自旋锁]]

## 信号量和条件变量有什么区别

### 简要回答

信号量本身带计数，可以表示资源数量；条件变量不保存资源数量，通常配合互斥锁等待某个条件成立。

### 面试表达

> 信号量更像资源计数器，条件变量更像线程等待队列。条件变量必须配合条件判断使用，防止虚假唤醒。

## 生产者消费者问题怎么理解

### 简要回答

生产者消费者问题是典型同步互斥问题：生产者往缓冲区放数据，消费者从缓冲区取数据。

### 关键点

- 缓冲区是共享资源，需要互斥访问。
- 缓冲区满时，生产者要等待。
- 缓冲区空时，消费者要等待。

### 伪代码

```text
生产者：
等待 empty
加锁
放入数据
解锁
通知 full

消费者：
等待 full
加锁
取出数据
解锁
通知 empty
```

### 面试表达

> 这个问题同时体现互斥和同步：访问缓冲区要互斥，生产和消费之间要按“非空才能消费、非满才能生产”的条件同步。

## 读写问题怎么理解

### 简要回答

读写问题是多个读者和写者访问共享数据时的同步问题。多个读者可以同时读，但写者写时必须独占。

### 常见策略

- 读者优先：读者多时吞吐高，但写者可能饥饿。
- 写者优先：避免写者饥饿，但读者可能等待更久。
- 公平策略：按请求顺序处理，避免一方长期饥饿。

### 面试表达

> 读写锁适合读多写少场景。读读之间不互斥，读写和写写之间互斥。

## 进程同步与互斥怎么解决

### 简要回答

进程互斥可以用信号量、互斥锁、文件锁等方式；进程同步可以用信号量、管道、消息队列、条件通知等方式。

### PV 操作

信号量常见两个操作：

```text
P 操作：申请资源，信号量减 1；如果资源不足则阻塞等待。
V 操作：释放资源，信号量加 1；如果有等待者则唤醒。
```

### 面试表达

> 互斥是为了保护临界资源，同步是为了保证执行顺序。信号量既可以做互斥，也可以做同步，关键看初值和使用方式。
