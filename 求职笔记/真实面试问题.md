## 三、C 语言基础

### 9. 指针步长问题：假设定义了一个指针变量 `p`，执行 `p + 1` 操作后，其实际值增加了多少？

速答：
`p + 1` 增加的不是固定 1 个字节，而是“当前指针所指类型的一个元素大小”。

- 如果 `p` 是 `int*`，通常加 `sizeof(int)`，常见是 4 字节。
- 如果 `p` 是 `double*`，通常加 `sizeof(double)`，常见是 8 字节。
- 如果 `p` 是 `char*`，通常加 1 字节。

面试表达：
指针加 1 的本质是跨过一个同类型元素，不是简单地址加 1。

相关：[[../八股/C++/03 指针引用与数组#指针相减规则|指针与地址运算]]

### 10. 概念辨析：数组指针与指针数组的区别是什么？

速答：

- 指针数组：本质是数组，数组里每个元素都是指针。
- 数组指针：本质是指针，这个指针指向一个数组。

例子：

```cpp
int* arr[3];      // 指针数组
int (*p)[3];      // 数组指针
```

相关：[[../八股/C++/03 指针引用与数组#指针数组|指针数组和数组指针]]

### 11. 语法定义：如何写代码定义一个指向含 3 个 int 元素的一维数组的指针？

速答：

```cpp
int (*p)[3];
```

解释：
`p` 是一个指针，指向“含 3 个 `int` 元素的一维数组”。

示例：

```cpp
int arr[3] = {1, 2, 3};
int (*p)[3] = &arr;
```

相关：[[../八股/C++/03 指针引用与数组#指针数组|指针数组和数组指针]]

### 12. 二维数组地址计算：已知 `int a[2][3]` 起始地址为 `1000`

前提：
默认按常见面试设定，`sizeof(int) = 4` 字节。

#### (1) `a + 1` 的值是多少？为什么？

速答：
`a` 的类型是“指向含 3 个 `int` 的一维数组的指针”，也就是 `int (*)[3]`。

所以 `a + 1` 会跨过一整行，也就是跨过 3 个 `int`：

```text
3 * 4 = 12 字节
1000 + 12 = 1012
```

结论：
`a + 1` 的值是 `1012`。

#### (2) `a[0] + 1` 的值是多少？为什么？

速答：
`a[0]` 是第一行数组，在表达式里会退化成 `int*`，指向 `a[0][0]`。

所以 `a[0] + 1` 只跨过一个 `int`：

```text
1 * 4 = 4 字节
1000 + 4 = 1004
```

结论：
`a[0] + 1` 的值是 `1004`。

## 四、数据结构

### 13. 在单链表中，如何在节点 A 和节点 B 之间插入节点 C？又如何删除节点 C？

假设当前关系是：

```text
A -> B
```

#### 插入 C

做法：

```cpp
C->next = A->next;
A->next = C;
```

这样顺序变成：

```text
A -> C -> B
```

#### 删除 C

前提：
你得能拿到 `C` 的前驱节点 `A`。

做法：

```cpp
A->next = C->next;
delete C;
```

这样就恢复成：

```text
A -> B
```

面试提醒：
单链表删除一个节点，关键难点不是删本身，而是必须先找到它的前驱节点。

## 五、C++ 基础

### 14. 虚函数有了解吗？它的主要作用是什么？

速答：
虚函数是用 `virtual` 修饰的成员函数，主要作用是支持运行时多态。

通过基类指针或引用调用虚函数时，程序会根据对象真实类型决定调用哪个实现。

### 15. 什么是函数多态？在代码中如何实现和调用多态？

速答：
多态分为编译时多态和运行时多态。

- 编译时多态：函数重载、模板
- 运行时多态：继承 + 虚函数 + 基类指针或引用

最常被问的是运行时多态。

### 4. 关于构造函数

#### (1) 一个类必须由用户自定义构造函数吗？如果不写，是否会有默认构造函数？

速答：
不一定必须自己写。

- 如果用户没有定义任何构造函数，编译器通常会生成默认构造函数。
- 如果用户定义了别的构造函数，编译器通常不会再自动生成无参默认构造函数，除非显式写 `= default`。

相关：[[../八股/C++/02 类与对象#构造函数有几种|构造函数种类]]

#### (2) 如果一个类中包含了其他类对象成员，构造函数的调用顺序是怎样的？

速答：
构造顺序是：

1. 基类
2. 成员对象
3. 派生类自身
**先父后子，先成员后自己**

相关：[[../八股/C++/02 类与对象#构造函数什么时候会被调用|构造函数调用时机]]  
相关：[[../八股/C++/02 类与对象#构造函数和析构函数|构造和析构顺序]]

#### (3) 如果有多个成员对象，它们的构造顺序是按什么区分的？

速答：
按**成员声明顺序**，不是按初始化列表里写的顺序。

面试表达：
初始化列表写法顺序不决定真正构造顺序，真正顺序由类里成员声明先后决定。

#### (4) 如果构造函数执行到一半出错，之前已经构造好的成员会被自动析构吗？

速答：
会。

已经成功构造完成的基类和成员对象，会按相反顺序自动析构。对象自己因为没构造完成，不会进入完整对象的析构流程，但已构造成员会被清理。

#### (5) 析构函数可以缺省吗？

速答：
可以。

如果用户不写析构函数，编译器通常会生成默认析构函数。但只要类自己管理资源，比如裸指针、文件句柄、锁等，就通常要自己写析构函数或使用 RAII 封装资源。

相关：[[../八股/C++/02 类与对象#构造函数和析构函数|构造函数和析构函数]]  
相关：[[../八股/C++/02 类与对象#深拷贝和浅拷贝|深拷贝和浅拷贝]]

### 5. 关于 this 指针

#### (1) this 指针是什么？它的作用是什么？

速答：
`this` 是每个非静态成员函数里的隐藏参数，指向当前调用该函数的对象。

主要作用：

- 访问当前对象成员
- 解决同名歧义
- 返回当前对象自身，支持链式调用

相关：[[../八股/C++/02 类与对象#this 指针|this 指针]]

#### (2) 什么情况下会使用 this 指针？

速答：

1. 形参与成员变量同名时
2. 需要返回当前对象引用时，如 `return *this;`
3. 想显式强调访问的是当前对象成员时

相关：[[../八股/C++/02 类与对象#this 指针|this 指针]]

### 6. 关于变量作用域与重名

#### (1) 全局变量和局部变量可以重名吗？谁优先生效？

速答：
可以重名。

在函数或代码块内部，局部变量优先生效，会屏蔽同名全局变量。

相关：[[../八股/C++/06 内存生命周期与静态成员#局部变量|局部变量]]  
相关：[[../八股/C++/06 内存生命周期与静态成员#全局变量|全局变量]]

#### (2) 在同一个函数内，两个局部变量可以重名吗？

速答：
同一个作用域里不可以。

但如果是在不同嵌套作用域中，可以重新定义同名变量，内层变量会屏蔽外层变量。

#### (3) 静态变量跟全局变量可以重名吗？

速答：
可以，但要看作用域和链接属性。

- 不同作用域下可以同名
- 同一作用域下同名会冲突
- 文件作用域 `static` 变量有内部链接，只在当前文件可见

相关：[[../八股/C++/06 内存生命周期与静态成员#局部变量 全局变量 静态局部变量|局部变量、全局变量、静态局部变量]]

### 8. 多线程交互问题

#### (1) 多个线程访问同一份资源时，如何保证资源的完整性？

速答：
常见手段有：

- 互斥锁 `mutex`
- 读写锁 / `shared_mutex`
- 原子变量 `std::atomic`
- 条件变量协调时序

核心目标是避免数据竞争，保证共享资源同一时刻的访问符合预期。

#### (2) 既然加了锁，同一时间只有一个线程能处理，为什么还能提高效率？

速答：
因为真正提高效率的前提不是“所有代码都并行”，而是把可并行的部分并行，把共享临界区尽量缩小。

锁只保护必须串行的那一小段；临界区外的计算、I/O 等仍然可以并发执行，所以总体吞吐仍然可能提高。

## 9. 操作系统概念

#### (1) 进程和线程有什么区别？

速答：

- 进程是资源分配的基本单位
- 线程是 CPU 调度的基本单位
- 同一进程内线程共享地址空间和大部分资源
- 不同进程之间默认资源隔离更强

相关：[[../linux系统编程/04 进程基础|进程基础]]  
相关：[[../linux系统编程/09 线程基础|线程基础]]

#### (2) 进程间通信是否需要用到锁？进程锁和线程锁是一样的吗？

速答：
进程间通信是否需要锁，要看是否存在多个执行单元并发访问同一份共享数据。

- 如果通过共享内存通信，通常也需要同步机制
- 如果只是消息队列、管道这类内核帮你串好的通信方式，锁需求会弱一些

进程锁和线程锁思路相似，都是为了解决并发访问问题，但底层对象和适用范围不完全一样。线程锁通常用于同一进程内线程；进程间同步通常会用进程共享的互斥量、信号量、文件锁等。

相关：[[../linux系统编程/06 进程间通信 IPC|进程间通信 IPC]]  
相关：[[../linux系统编程/10 线程同步|线程同步]]

## 六、综合素质与行为面试

### 16. 面对一个陌生的技术领域，你的学习流程和思路是怎样的？

口语版答案：

> 我一般会先建立整体框架，而不是一上来扎进细节。比如我之前看 TinyWebServer 这个项目时，我先把它拆成几个核心模块去理解：主线程事件循环、`http_conn`、线程池、定时器、数据库连接池和日志系统。先知道每个模块各自负责什么，以及一次请求在它们之间是怎么流转的。  
>   
> 第二步我会先找一条最小可运行主线，把它跑通。比如不是一开始就死抠所有 HTTP 细节，而是先盯住“一次请求从 `accept` 进来，到 `epoll` 监听，到 `http_conn::process()`，最后把响应写回客户端”这条主链路。这样先有整体直觉，再往下钻会快很多。  
>   
> 第三步我再按模块深入，把关键原理、常见坑和边界条件补齐。像在 TinyWebServer 里，我后面就是按 HTTP 状态机、线程池并发模型、定时器、数据库登录注册这些模块逐个拆。  
>   
> 第四步我会通过输出去巩固，比如写笔记、做逐请求模拟，或者把复杂过程讲成能口头复述的版本。因为我发现，能不能给别人讲清楚，基本就能反映我是不是真的掌握了。  
>   
> 我的习惯是先把“能跑通”和“主链路搞懂”放在前面，再去追“为什么要这么设计”，这样效率更高，也不容易一开始就陷进局部细节里。

### 17. 举一个曾经困扰你很久、最后通过自己努力解决的难题案例。

口语版答案：

> 我之前有一个困扰我挺久的问题，是在看 TinyWebServer 的 HTTP 状态机时遇到的。  
>   
> 当时我一开始能看懂它大概是在“解析请求”，但真正卡住我的地方是：一个 HTTP 请求到底是怎么被分段读进缓冲区的，`m_read_idx`、`m_checked_idx`、`m_start_line` 这几个下标是怎么配合工作的，以及为什么它能处理半包、又不会把请求解析乱。  
>   
> 这个问题难的地方在于，它不是单看某一个函数就能明白的。你如果只看 `parse_request_line()`，会发现很多上下文都不够；只看 `read_once()`，又不知道后面的状态机怎么接。它其实横跨了读缓冲区、从状态机、主状态机和一次完整请求的调用链。  
>   
> 后来我没有继续一大段一大段硬啃源码，而是先把问题拆小。第一步，我先确认请求真正从哪里开始进入状态机，最后定位到是 `http_conn::process()` 里调用 `process_read()`。第二步，我把三个最关键的变量单独拎出来分析：`m_read_idx` 表示已经读进来多少字节，`m_checked_idx` 表示状态机已经扫描到哪里，`m_start_line` 表示当前行起始位置。第三步，我拿一个真实的 GET 请求和一个 POST 请求，按时间线去模拟每一步变量怎么变化，`parse_line()` 什么时候切出一行，`parse_headers()` 什么时候转状态，为什么请求体不完整时会返回 `NO_REQUEST` 继续等下一批数据。  
>   
> 最后我把这一套过程整理成了逐请求模拟笔记，相当于把抽象源码还原成了一个动态执行过程。这样我不只是知道“HTTP 状态机存在”，而是真的能讲清楚它怎么解决 TCP 流式传输带来的半包问题。  
>   
> 这件事对我最大的帮助是，我后来面对复杂代码时不会急着一口气全看懂，而是会先抓主链路，再抓关键状态变量，最后通过最小案例模拟执行过程。这样效率高很多，而且也更容易把东西真正吃透。


## 1. 怎么实现 C++ 和 Python 的 bridge？了解 GIL 吗？

### 题目合并

- 怎么实现的 C++ 和 Python 的 bridge
- 了解 GIL 吗

### 回答

`C++ 和 Python bridge` 的本质，是让两种语言之间可以互相调用、互相传数据。常见方式有三类：

1. `Python 调 C++`
- 最常见的是把 C++ 封装成 Python 扩展模块。
- 常用方案有 `pybind11`、`Boost.Python`、`Cython`、Python C API。
- 适合性能敏感模块，比如感知后处理、路径计算、仿真接口。

2. `C++ 调 Python`
- C++ 进程里嵌入 Python 解释器。
- 常用方式是 Python C API，例如 `Py_Initialize`、`PyImport_ImportModule`、`PyObject_CallObject`。
- 适合把 Python 当脚本层，比如配置流程、测试脚本、数据分析逻辑。

3. `进程间 bridge`
- 不直接在一个进程里混编，而是通过 `RPC`、`HTTP`、`Socket`、`gRPC`、消息队列通信。
- 好处是解耦更强，崩溃隔离更好，缺点是序列化和通信开销更大。

如果让我说“项目里怎么做 bridge”，我会这样答：

> 如果 Python 主要做测试编排、数据分析，而核心性能模块在 C++，我会优先选 `pybind11`。因为它比直接写 Python C API 更简洁，类型绑定也更自然，适合把 C++ 核心能力暴露给 Python 测试脚本调用。

### GIL 是什么

`GIL` 是 `Global Interpreter Lock`，全局解释器锁，是 CPython 解释器里的一个机制。

核心点：

- 同一个进程内，多个 Python 线程不能同时执行 Python 字节码。
- 所以 Python 多线程在 `CPU 密集型任务` 上通常不能真正并行。
- 但是在 `I/O 密集型任务` 里问题没那么大，因为线程等待 I/O 时会释放 GIL。

### 面试可直接说的版本

> C++ 和 Python 的 bridge，本质上是让两种语言互相调用。常见做法是用 `pybind11` 把 C++ 封装成 Python 模块，或者用 Python C API 在 C++ 中嵌入解释器。如果是强解耦场景，也可以走 RPC 或 Socket。  
> GIL 是 CPython 的全局解释器锁，它导致多个 Python 线程不能同时执行 Python 字节码，所以 Python 多线程更适合 I/O 密集型，不适合纯 CPU 密集型并行。

### 回答框架

如果问“你 C++ 重构怎么做的”，不要只说“优化代码结构”，要从 `目标、步骤、风险控制、结果` 四部分答。

### 标准回答

> 我做 C++ 重构时，一般不是直接大改，而是先确认重构目标。常见目标有三类：  
> 1. 提高可维护性，比如拆掉过长函数、解耦模块依赖。  
> 2. 提高稳定性，比如统一资源管理，减少野指针、内存泄漏。  
> 3. 提高可测试性，比如把业务逻辑和 I/O、配置读取分离。  
>   
> 具体步骤上，我会先梳理现有类关系和调用链，找出高耦合点和重复逻辑；然后优先做小步重构，比如提炼函数、抽象公共类、统一接口、把裸指针替换成智能指针、引入 RAII；同时保证每一步都有编译和回归验证。

> 如果面向性能敏感场景，我还会关注对象拷贝、锁粒度、容器选择和内存生命周期，避免为了“结构更好看”反而带来性能回退。

- 补测试，保证重构不改行为

## 4. B+ 树，B+ 树的分裂和合并

### B+ 树是什么

`B+ 树` 是数据库索引中最常见的数据结构，特别适合磁盘和范围查询。

特点：

- 非叶子节点只存 `键`，不存完整数据
- 叶子节点存 `键 + 数据地址`，或者直接存数据
- 所有数据都出现在叶子节点
- 叶子节点之间通常有链表，方便范围扫描

### 为什么数据库喜欢 B+ 树

- 高度低，磁盘 I/O 次数少
- 范围查询效率高
- 顺序遍历稳定

### 分裂

当某个节点插入后超过容量上限，就要 `分裂`。

过程：

1. 新建一个兄弟节点
2. 把当前节点的一半元素移动过去
3. 把中间键提升到父节点
4. 如果父节点也满了，就继续向上分裂

### 合并

删除时如果某节点元素太少，低于下限，就要 `借位或合并`。

过程：

1. 先看兄弟节点能不能借一个元素
2. 如果不能借，就和兄弟节点合并
3. 父节点对应分隔键也要删掉
4. 如果父节点也过少，就继续向上调整

### 面试短答

> B+ 树是数据库最常见的索引结构，它的非叶子节点只存键，叶子节点存完整索引项，而且叶子节点之间通常串成链表，所以非常适合范围查询。插入过满时会分裂，把中间键上推到父节点；删除过少时先尝试向兄弟借位，不够再合并，并把父节点分隔键同步调整。

## 5. MySQL 设计表之间有什么关系？MySQL 索引

### 表之间的关系

常见有四种：

1. `一对一`
- 例如用户表和用户详情表

2. `一对多`
- 例如一个订单对应多个订单项

3. `多对一`
- 本质是一对多的反向描述

4. `多对多`
- 例如学生和课程，需要中间表

设计时常见做法：

- 用 `主键` 唯一标识一行
- 用 `外键` 或逻辑关联字段表示关系
- 多对多一定要通过中间表拆开

### MySQL 索引

索引本质上是帮助数据库快速定位数据的数据结构。

常见索引：

- 主键索引
- 唯一索引
- 普通索引
- 联合索引

### 索引为什么快

- 不用全表扫描
- 通过 B+ 树快速定位到目标行或目标范围

### 联合索引注意点

最重要的是 `最左前缀原则`：

- 索引 `(a, b, c)` 能命中 `a`
- 能命中 `a,b`
- 能命中 `a,b,c`
- 不能跳过 `a` 直接高效命中 `b,c`

### 面试短答

> 表关系主要有一对一、一对多、多对多。设计时通常通过主键和外键，或者业务字段逻辑关联。MySQL 索引底层常用 B+ 树，作用是减少全表扫描，提高点查和范围查询效率。联合索引要注意最左前缀原则。

## 6. HTTP 的 GET 和 POST 区别？什么数据会放到 HTTP header 里？

### GET 和 POST 区别

1. `语义不同`
- GET 通常表示获取资源
- POST 通常表示提交数据

2. `参数位置不同`
- GET 常把参数拼在 URL 后面
- POST 通常把参数放在请求体里

3. `幂等性不同`
- GET 通常应该是幂等的
- POST 通常不保证幂等

4. `缓存和书签`
- GET 更容易被缓存、收藏、复制链接
- POST 一般不直接暴露在 URL 中

### 什么数据会放到 HTTP header

Header 里一般放 `元信息`，而不是大块业务数据。

常见包括：

- `Host`
- `Content-Type`
- `Content-Length`
- `Authorization`
- `Cookie`
- `User-Agent`
- `Accept`
- `Connection`
- `Referer`

简单理解：

- `header` 放“这次请求怎么处理”
- `body` 放“这次请求真正提交了什么内容”

### 面试短答

> GET 和 POST 最核心区别是语义和参数位置。GET 一般用于获取资源，参数常放 URL；POST 一般用于提交数据，参数常放 body。HTTP header 里通常放元信息，比如 Host、Content-Type、Authorization、Cookie、User-Agent，而真正业务数据一般放在 body 里。
