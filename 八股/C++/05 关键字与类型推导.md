## static 关键字

### 简要回答

`static` 主要用来控制**生命周期**和**可见性**。

它可以让局部变量在多次函数调用之间持续存在；也可以让全局变量或函数只在当前 `.cpp` 文件内部可见；还可以让类成员属于类本身，被所有对象共享，而不是每个对象各自持有一份。

核心思想：**存储不随栈帧消亡，名字不向外部暴露。**

### 常见作用

1. 修饰局部变量：生命周期变成整个程序运行期，但作用域仍在函数内。
2. 修饰全局变量或函数：限制链接属性，只在当前文件可见。
3. 修饰类成员变量：属于类本身，所有对象共享一份。
4. 修饰类成员函数：属于类本身，没有 `this` 指针。

### 1. 局部静态变量

在函数内部用 `static` 声明的变量，生命周期会延长到整个程序运行期间，但作用域仍然限制在函数内部。

它只在第一次执行到声明语句时初始化一次，后续函数调用会保留上一次的值。

```cpp
void counter() {
    static int cnt = 0;
    cnt++;
    cout << cnt << endl;
}
```

调用过程可以这样理解：

```text
程序启动 -> 分配静态存储区
首次调用 -> 执行初始化
后续调用 -> 保留上次的值
程序结束 -> 析构释放
```

### 2. 全局静态变量和静态函数

在文件作用域使用 `static`，会把变量或函数的链接属性限制为**内部链接**，也就是只在当前文件可见，其他 `.cpp` 文件不能通过 `extern` 访问它。

```cpp
static int g_count = 0;

static void helper() {
    // 只给当前文件使用
}
```

### 3. 类的静态成员变量

类的静态成员变量属于类本身，不属于某一个对象。所有对象共享同一份静态成员变量，它通常存储在全局或静态区。

```cpp
class A {
public:
    static int count;
};

int A::count = 0;
```

静态成员变量通常必须在类外定义一次。C++17 起可以使用 `inline static` 在类内完成定义。

```cpp
class A {
public:
    inline static int count = 0; // C++17
};
```

### 4. 类的静态成员函数

静态成员函数属于类本身，没有 `this` 指针，**因此不能直接访问非静态成员**。

```cpp
class Factory {
public:
    static Factory create() {
        return Factory();
    }
};

Factory obj = Factory::create();
可以这么使用
Factory::create()->私有函数
```

常见使用场景：

- 工厂方法。
- 单例模式。
- 只依赖类级状态的工具函数。

### 代码示例

```cpp
#include <iostream>
using namespace std;

// 1. 文件作用域 static：仅本文件可见
static int filePrivate = 42;

class Counter {
public:
    static int count; // 类内声明

    Counter() {
        ++count;
    }

    ~Counter() {
        --count;
    }

    // 静态成员函数没有 this，不能直接访问非静态成员
    static int getCount() {
        return count;
    }
};

int Counter::count = 0; // 类外定义

void callMe() {
    static int times = 0; // 只初始化一次
    cout << "called " << ++times << " times" << endl;
}

int main() {
    callMe(); // called 1 times
    callMe(); // called 2 times
    callMe(); // called 3 times

    {
        Counter a, b, c;
    } // 离开代码块，三个对象析构，count 重新变为 0

    cout << "alive: " << Counter::getCount() << endl;

    return 0;
}
```

输出：

```text
called 1 times
called 2 times
called 3 times
alive: 0
```

## const 关键字

### 简要回答

`const` 表示一种“不修改”的承诺。

它可以把变量标记为只读，把指针或引用标记为不能通过它修改所指对象，也可以把成员函数标记为不会修改对象状态。

核心思想：**编译器帮你守住承诺，一旦违背就报错。**

### 常见作用

1. 修饰变量：变量值不能被修改。
2. 修饰指针：区分指向常量的指针、常量指针。
3. 修饰成员函数：表示该函数不修改对象成员。
4. 修饰引用参数：避免拷贝，同时防止函数修改实参。

### 1. 修饰普通变量

普通变量被 `const` 修饰后，不能再被赋值修改。

```cpp
const int x = 10;
// x = 20; // 编译错误
```

### 2. 修饰指针

这是面试高频点。口诀：`const` 在 `*` 左边，通常修饰指向的值；`const` 在 `*` 右边，修饰指针本身。

| 写法 | 含义 | 能否改指向 | 能否通过指针改值 |
|---|---|---|---|
| `const int* p` | 指向常量的指针，底层 const | 可以 | 不可以 |
| `int* const p` | 常量指针，顶层 const | 不可以 | 可以 |
| `const int* const p` | 指针和值都 const | 不可以 | 不可以 |

```cpp
int a = 1;
int b = 2;

const int* p1 = &a;
p1 = &b;     // 对
// *p1 = 3;  // 错

int* const p2 = &a;
*p2 = 3;     // 对
// p2 = &b;  // 错
```

更详细的指针组合见：[[03 指针引用与数组#const 和指针的组合]]

### 3. 修饰引用

`const int& ref = x` 表示不能通过 `ref` 修改 `x`。

它常用于函数参数传递：既避免拷贝开销，又保证函数不会意外修改实参。

```cpp
void printName(const string& name) {
    cout << name << endl;
}
```

### 4. 修饰成员函数

在成员函数末尾加 `const`，表示这个函数承诺不修改对象的非 `mutable` 成员。

```cpp
class Student {
private:
    string name;

public:
    string getName() const {
        return name;
    }
};
```

`const` 对象只能调用 `const` 成员函数。

```cpp
const Student stu;
stu.getName(); // 对
```

### 代码示例

```cpp
#include <iostream>
#include <string>
using namespace std;

class Student {
private:
    string name_;
    mutable int accessCount_ = 0; // mutable 允许在 const 函数中修改

public:
    Student(const string& n) : name_(n) {}

    string getName() const {
        ++accessCount_;
        return name_;
    }

    void setName(const string& n) {
        name_ = n;
    }
};

int main() {
    const int MAX = 100;
    // MAX = 200; // 编译错误

    int a = 10;
    int b = 20;

    const int* p1 = &a;
    // *p1 = 30; // 编译错误，不能通过 p1 改值
    p1 = &b;     // 可以改指向

    int* const p2 = &a;
    *p2 = 30;    // 可以改值
    // p2 = &b;  // 编译错误，不能改指向

    const Student s("Alice");
    cout << s.getName() << endl; // getName 是 const 成员函数
    // s.setName("Bob");         // 编译错误，const 对象不能调用非 const 成员函数

    return 0;
}
```

## static 和 const 的核心差异

| 维度 | static | const |
|---|---|---|
| 核心语义 | 控制生命周期和可见性 | 控制可修改性 |
| 修饰局部变量 | 生命周期延长到程序结束 | 值不可修改 |
| 修饰全局变量 | 限制为文件内部链接 | C++ 中默认内部链接，并且只读 |
| 修饰类成员变量 | 所有对象共享一份 | 一般需要初始化，表示成员只读 |
| 修饰成员函数 | 无 `this` 指针，可用类名调用 | 不修改对象状态，`const` 对象可调用 |
| 能否同时使用 | 可以，如 `static const int X = 42` | 可以 |

## 变量存储位置速记

| 区域 | 常见内容 |
|---|---|
| 栈区 | 普通局部变量，如 `int x = 5`；局部 `const int y = 10` 通常也在栈上 |
| 全局/静态区 | 静态局部变量、静态全局变量、类静态成员变量 |
| 只读区 | 字符串字面量，如 `"hello"`；部分编译期常量可能被放入只读区域或直接优化掉 |

## static 和 const 面试官可能追问

### Q1：const 和 define 有什么区别？

`#define` 是预处理阶段的文本替换，没有类型检查，不受普通 C++ 作用域约束，调试时也看不到真正的变量符号名。

`const` 是编译阶段处理，有类型安全、有作用域，可以参与调试。编译器还可能对 `const` 常量做常量折叠优化。

结论：C++ 中应优先使用 `const` 或 `constexpr`，不要优先用 `#define` 定义常量。

```cpp
#define MAX_SIZE 100
const int maxSize = 100;
```

### Q2：const 和 constexpr 有什么区别？

`const` 表示运行时不可修改，但初始值可以运行时才确定。`constexpr` 是 C++11 引入的更强语义，表示编译期常量，值必须在编译期就能确定。

| 关键字 | 含义 | 值何时确定 | 常见用途 |
|---|---|---|---|
| `const` | 只读 | 可以运行时确定 | 保护变量不被修改 |
| `constexpr` | 编译期常量 | 必须编译期确定 | 数组大小、模板参数、编译期计算 |

```cpp
int n;
cin >> n;

const int a = n;        // 可以，运行时初始化后不可修改
constexpr int b = 1 + 2; // 可以，编译期确定
// constexpr int c = n;  // 错，n 运行时才知道
```

### Q3：static 局部变量是线程安全的吗？

C++11 标准保证：局部 `static` 变量的**初始化**是线程安全的，也常叫 magic statics。编译器会保证多个线程同时第一次进入函数时，只有一个线程执行初始化。

但注意：初始化之后对这个对象的读写操作不自动线程安全。如果多个线程会修改它，仍然需要锁或原子操作。

这也是 Meyer's Singleton 的基础：

```cpp
class Singleton {
public:
    static Singleton& getInstance() {
        static Singleton instance; // C++11 起初始化线程安全
        return instance;
    }

private:
    Singleton() = default;
};
```

### Q4：mutable 关键字的作用是什么？

`mutable` 允许成员变量即使在 `const` 成员函数中也可以被修改。

典型场景：

- 缓存计算结果。
- 访问计数器。
- 互斥锁，如 `mutable std::mutex mtx_;`。

它通常不破坏逻辑上的 `const`，因为对象对外可观察的业务状态没有变化，只是内部实现细节发生了变化。

```cpp
class Cache {
private:
    mutable bool cached_ = false;
    mutable int value_ = 0;

public:
    int get() const {
        if (!cached_) {
            value_ = 42;
            cached_ = true;
        }
        return value_;
    }
};
```

### Q5：能不能用 const_cast 去掉 const？有什么风险？

`const_cast` 可以移除或添加 `const` 限定。

如果原始对象本身就是 `const`，去掉 `const` 后再修改它是未定义行为。

```cpp
const int x = 10;
int* p = const_cast<int*>(&x);
// *p = 20; // 未定义行为
```

相对合理的场景是：对象本身不是 `const`，只是通过 `const` 指针或引用传递进来，并且你非常确定可以安全修改。

```cpp
int x = 10;
const int& ref = x;
int& r = const_cast<int&>(ref);
r = 20; // 原始对象不是 const，这种情况可以修改
```

面试建议：强调尽量不用，除非在维护老接口或适配特殊库接口时非常确定安全。

### Q6：static 变量的初始化顺序有什么问题？

不同编译单元，也就是不同 `.cpp` 文件中的全局变量和静态存储期对象，初始化先后顺序通常不能依赖。这个问题常被称为 Static Initialization Order Fiasco。

如果 `file_a.cpp` 的静态变量初始化依赖 `file_b.cpp` 的静态变量，就可能在对方尚未初始化时被使用。

```cpp
// file_a.cpp
extern int b_val;
int a_val = b_val + 1; // b_val 可能还没初始化
```

常见解决方案是使用函数内局部 `static`，也叫 Construct On First Use Idiom。它在首次调用时才初始化。

```cpp
int& getA() {
    static int a_val = getB() + 1;
    return a_val;
}
```

### Q7：C 语言的 const 和 C++ 的 const 有什么不同？

C 语言里的 `const` 更接近“只读变量”。C++ 里的 `const` 在很多场景更接近“常量”语义。

| 语言 | const 默认链接属性 | 能否作为编译期常量使用 |
|---|---|---|
| C | 通常是外部链接 | 通常不能直接作为普通数组大小等编译期常量使用 |
| C++ | 命名空间作用域下默认内部链接 | 如果初始化表达式是常量表达式，可以作为编译期常量使用 |

面试加分表达：把 `static` 和单例模式联系起来，把 `const` 和 `constexpr` 联系起来，说明你理解的是语言机制，不只是背关键词。

## extern C 的作用

### 简要回答

`extern "C"` 是 C++ 编译器提供的链接规范，用来告诉 C++ 编译器：被它修饰的函数或变量要按照 C 语言的规则进行编译和链接。

简单说，它的核心作用是：**禁止 C++ 名称修饰，让 C++ 代码能够正确链接 C 语言编译出来的库或目标文件。**

```cpp
extern "C" {
    int add(int a, int b);
}
```

### 为什么需要：名称修饰问题

C++ 支持函数重载，也就是多个函数可以同名但参数不同。

为了让链接器区分这些函数，C++ 编译器会对函数名做名称修饰，把函数名、参数类型等信息编码成一个新的符号名。这个过程叫 Name Mangling。

例如：

```cpp
void foo(int);
```

在 C++ 编译后，符号名可能变成类似：

```text
_Z3fooi
```

C 语言不支持函数重载，所以通常不会做这种 C++ 风格的名称修饰。C 编译器编译出来的符号名可能仍然就是：

```text
foo
```

### 链接时的问题

如果 C++ 程序调用一个 C 库里的函数 `foo`，但没有写 `extern "C"`，C++ 编译器可能会去找修饰后的符号，比如 `_Z3fooi`。

但 C 库里真正导出的符号叫 `foo`。

结果链接器找不到 `_Z3fooi`，就会报类似：

```text
undefined reference to `foo(int)'
```

### extern C 的解决方案

使用 `extern "C"` 后，C++ 编译器会按 C 风格处理这部分函数名，不做 C++ 名称修饰。

这样 C++ 目标文件里寻找的符号就是 `foo`，可以和 C 库里的 `foo` 成功匹配。

### 调用约定

除了名称修饰，`extern "C"` 在一些平台和编译器上也和 C 语言调用约定有关，比如参数如何传递、栈由谁清理等。

面试中最主要抓住一点即可：`extern "C"` 解决的是 C++ 和 C 在二进制链接层面的兼容问题，核心是名称修饰。

### 代码示例：C++ 封装成 C 接口

```cpp
// my_class.h
class MyClass {
public:
    int doSomethingComplex(int x);
};
```

```cpp
// c_interface.h
#ifdef __cplusplus
extern "C" {
#endif

int c_wrapper_do_something(int x);

#ifdef __cplusplus
}
#endif
```

```cpp
// c_interface.cpp
#include "my_class.h"
#include "c_interface.h"

extern "C" int c_wrapper_do_something(int x) {
    MyClass obj;
    return obj.doSomethingComplex(x);
}
```

### 适用场景

1. C++ 调用 C 语言库。
   例如 Linux 系统 API、glibc、SQLite、Lua、libpng 等。

2. C 程序调用 C++ 实现。
   如果用 C++ 写库，但希望导出给 C 程序调用，就需要提供 C 风格包装函数。

3. 和其他语言交互。
   Python、Lua 等语言的扩展接口或 FFI 通常采用 C ABI。用 C++ 写扩展时，经常需要用 `extern "C"` 导出入口函数。

### 面试速背

`extern "C"` 不是把 C++ 代码变成 C 代码，也不是让 C 直接理解类、模板、重载。它只是让被修饰的函数或变量使用 C 风格链接规则，避免 C++ 名称修饰，从而实现 C 和 C++ 的二进制链接兼容。

## volatile 关键字

### 简要回答

`volatile` 表示变量可能被编译器看不见的外部因素修改，因此编译器每次访问它时都要真正执行读写，不能把它随意缓存到寄存器里，也不能把相关访问优化掉。

它主要解决的是：**防止编译器过度优化对特殊内存位置的访问。**

典型外部因素包括：硬件寄存器、中断服务程序、异步信号处理程序等。

### volatile 和 const 的区别

`const` 表示“程序本身不应该修改它”；`volatile` 表示“程序之外可能修改它”。

二者不冲突，可以同时使用。

```cpp
const volatile uint32_t* reg_status;
```

这表示：程序不能通过 `reg_status` 修改寄存器值，但这个寄存器值可能被硬件随时改变，所以每次读取都必须真的去读。

| 关键字 | 核心语义 | 典型含义 |
|---|---|---|
| `const` | 不允许通过这个名字修改 | 程序承诺只读 |
| `volatile` | 不允许编译器假设值不变 | 外部可能修改 |
| `const volatile` | 程序只读，但外部会变 | 只读硬件状态寄存器 |

### volatile 和 std::atomic 的区别

这是现代 C++ 里最重要的边界。

`volatile` 主要约束编译器优化；`std::atomic` 用于多线程同步，提供原子性和内存顺序语义。

| 对比点 | volatile | std::atomic |
|---|---|---|
| 是否保证原子性 | 不保证 | 保证对应 atomic 操作原子 |
| 是否适合多线程同步 | 不适合 | 适合 |
| 是否提供内存顺序 | 不提供 C++ 多线程同步语义 | 提供，如 `memory_order_relaxed/acquire/release` |
| 主要用途 | 硬件寄存器、ISR、信号处理相关访问 | 多线程共享数据同步 |
| 现代 C++ 推荐 | 少数底层场景使用 | 多线程首选 |

### 适用场景

- 嵌入式系统或驱动开发：访问内存映射硬件寄存器。
- 与中断服务程序 ISR 通信：主循环读取被 ISR 修改的标志位。
- 信号处理程序修改的全局变量，通常结合 `sig_atomic_t` 使用。
- 缺少 `std::atomic` 的旧式编译器或特殊环境中，可能出现脆弱的共享变量写法，但现代 C++ 强烈不推荐。

### 常见场景

- 硬件寄存器。
- 信号处理相关变量。
- 某些嵌入式场景。

### 易错点

`volatile` 不等于线程安全。多线程同步应该使用锁、原子变量或条件变量。

### 面试官可能追问

#### Q1：volatile 能保证原子性吗？为什么？

不能。

`volatile` 只能要求编译器不要省略或缓存对变量的访问，但它不保证复合操作的原子性。

例如：

```cpp
volatile int i = 0;
i++;
```

`i++` 不是一个不可分割的动作，它通常包含：

1. 读取 `i`。
2. 加 1。
3. 写回 `i`。

多个线程交错执行这些步骤时，仍然会发生数据竞争和结果丢失。

> [!warning] 面试修正
> 不能说 volatile 能保证这三个步骤作为整体不被中断。它不能。它只是不让编译器把这些访问优化掉，不提供线程间同步和复合操作原子性。

#### Q2：volatile 和 std::atomic 有什么区别？

主要有三点：

1. 原子性不同。
   `std::atomic` 保证对应原子操作不可被其他线程观察到中间状态；`volatile` 不保证。

2. 内存顺序不同。
   `std::atomic` 可以指定内存顺序，如 `memory_order_relaxed`、`memory_order_acquire`、`memory_order_release`；`volatile` 不提供 C++ 多线程内存模型里的同步语义。

3. 主要用途不同。
   `volatile` 用于硬件、ISR、异步信号这类“程序外部会改值”的场景；`std::atomic` 用于多线程共享数据同步。

### 面试速背

`volatile` 不是多线程同步工具。它告诉编译器“这个值可能被外部改变，不要乱优化访问”；如果是多线程共享变量，现代 C++ 应该优先使用 `std::atomic`、锁或条件变量。

## inline 函数和宏的区别

### 简要回答

宏是预处理阶段的文本替换；`inline` 是 C++ 函数，有类型检查、作用域和调试信息。

| 对比点 | 宏 | inline 函数 |
|---|---|---|
| 阶段 | 预处理 | 编译 |
| 类型检查 | 没有 | 有 |
| 作用域 | 弱 | 正常 C++ 作用域 |
| 调试 | 较差 | 较好 |
| 副作用风险 | 高 | 低 |

```cpp
#define SQUARE(x) x * x

inline int square(int x) {
    return x * x;
}
```

`SQUARE(a + 1)` 会展开成 `a + 1 * a + 1`，容易出错。

### 详细回答

#### inline 函数

- 是 C++ 语言层面的函数修饰符。
- 由编译器处理，会进行类型检查和作用域分析。
- 遵循函数的所有规则，有返回值类型和参数列表。
- 调试时可以作为普通函数进行单步跟踪。
- 可以被类的封装性保护，也可以是类的成员函数。

#### define 宏

- 是预处理器指令，在编译前进行文本替换。
- 没有类型检查，容易产生意想不到的错误。
- 不遵循普通 C++ 作用域规则，容易污染命名空间。
- 调试时无法像普通函数一样跟踪，看到的往往是替换后的代码。
- 因为是简单文本替换，可能产生多次求值问题。

```cpp
#define MAX(a, b) ((a) > (b) ? (a) : (b))

int x = 1;
int y = 2;
int z = MAX(++x, y);
```

上面 `++x` 可能被求值不止一次，这就是宏的典型风险。

### 推荐使用 inline 函数的场景

1. 简单数学运算：如 `max`、`min`、`square`。
2. 访问器和修改器：类的 getter / setter。
3. 模板函数：需要类型安全的泛型编程。
4. 性能关键的简单函数：减少函数调用开销。
5. 头文件中的短函数定义：配合 `inline` 避免多重定义问题。

### 宏仍有优势的场景

1. 条件编译：根据编译选项包含或排除不同代码。
2. 日志和调试：在发布版本中完全移除调试代码。
3. 代码生成：重复的模式化代码定义。
4. 字符串化和令牌拼接：使用 `#` 和 `##`。
5. 平台特定代码：处理不同编译器、系统平台差异。

### 面试官可能追问

#### Q1：inline 函数一定会被内联展开吗？

不一定。

`inline` 只是给编译器的建议，最终是否内联由编译器决定。编译器可能因为函数体太大、包含复杂循环、递归调用等原因拒绝内联。

反过来，没有显式写 `inline` 的函数，也可能被编译器优化为内联展开。

#### Q2：宏的 # 和 ## 运算符有什么作用？

`#` 用于把宏参数转换成字符串字面量。

```cpp
#define TO_STRING(x) #x

cout << TO_STRING(hello) << endl; // "hello"
```

`##` 用于连接两个令牌。

```cpp
#define MAKE_VAR(name) int var_##name

MAKE_VAR(count); // 展开为 int var_count
```

这两个操作是宏特有能力，`inline` 函数无法做到这种预处理期的字符串化和令牌拼接。

#### Q3：在类定义中直接实现的成员函数默认是 inline 吗？

是的。

在类定义内部直接实现的成员函数默认具有 `inline` 语义，不需要显式添加 `inline`。

```cpp
class A {
public:
    int get() const {
        return 10;
    }
};
```

但注意：默认具有 `inline` 语义，不代表编译器一定会把它展开。

## auto 和 decltype 的区别

### 简要回答

`auto` 根据初始化表达式推导变量类型；`decltype` 根据表达式本身推导类型。

```cpp
int a = 10;
auto x = a;        // int
decltype(a) y = 0; // int
```

### 常见区别

- `auto` 必须有初始化值。
- `decltype` 不一定真正计算表达式，只取类型。
- `decltype((a))` 会得到引用类型，这是高频易错点。

```cpp
int a = 10;
decltype(a) x = a;   // int
decltype(a+1.0) x = a;   // double
decltype((a)) y = a; // int&
```

### 适用场景

#### auto 适用场景

1. 简化复杂类型名的变量声明。
2. 范围 `for` 循环中的迭代变量。
3. lambda 表达式中的参数。
4. 模板函数中简化局部变量类型。

```cpp
std::vector<std::pair<int, std::string>> vec;

for (const auto& item : vec) {
    // item 类型由编译器推导
}
```

#### decltype 适用场景

1. 需要精确推导表达式类型。
2. 函数返回类型依赖参数的模板编程。
3. 需要保留引用和 `const` 限定的情况。
4. 元编程和类型特征检查。

```cpp
template <typename T, typename U>
auto add(T a, U b) -> decltype(a + b) {
    return a + b;
}
```

### 面试官可能追问

#### Q1：为什么 decltype((x)) 会推导出引用类型，而 decltype(x) 不会？

因为 `decltype` 有两套规则。

- `decltype(x)` 中的 `x` 是未加括号的变量名，因此得到变量的声明类型。
- `decltype((x))` 中的 `(x)` 是一个表达式，而且它是左值表达式，所以推导为 `T&`。

```cpp
int x = 10;

decltype(x) a = x;   // int
decltype((x)) b = x; // int&
```

#### Q2：auto 和 decltype 在模板元编程中各有什么优势？

`auto` 更适合简化代码和局部变量声明，重点是让编译器帮你写出明显但很长的类型。

`decltype` 更适合需要精确类型信息的场合，比如 SFINAE、类型特征检查、表达式返回类型推导等。它可以用于编译期类型计算和表达式类型检查。

#### Q3：decltype(auto) 解决了什么问题？

`decltype(auto)` 结合了 `auto` 的简洁和 `decltype` 的精确。

普通 `auto` 推导时会剥离引用和顶层 `const`，而 `decltype(auto)` 使用 `decltype` 的规则推导类型，可以保留引用和 `const`。

```cpp
int x = 10;

int& getRef() {
    return x;
}

auto a = getRef();           // int，引用被剥离
decltype(auto) b = getRef(); // int&，保留引用
```

它常用于完美转发、包装函数和返回类型推导。

## 面试速背

1. `static` 既能控制生命周期，也能控制链接属性，还能声明类级成员。
2. `const` 表示只读语义，常用于变量、指针、引用参数、成员函数。
3. `extern "C"` 解决 C++ 和 C 的符号链接兼容问题。
4. `volatile` 防止编译器过度优化，但不保证线程安全。
5. `inline` 比宏更安全，因为它仍然是函数。
6. `auto` 看初始化值，适合简化变量声明；`decltype` 看表达式类型，适合保留引用、const 和做模板类型推导。
