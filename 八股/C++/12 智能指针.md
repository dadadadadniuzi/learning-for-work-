## 什么是智能指针，C++ 中有哪几种智能指针

### 简要回答

智能指针本质上是“像指针一样用，但会自动管理资源生命周期的对象”。

C++11 里最常见的三种智能指针是：

1. `std::unique_ptr`
2. `std::shared_ptr`
3. `std::weak_ptr`

更口语一点说：

- `unique_ptr`：独家专属，一个资源同一时间只能归一个指针管
- `shared_ptr`：合作共赢，多个指针可以一起管一个资源，靠引用计数控制释放
- `weak_ptr`：偷偷观察，不管后事，不拥有资源，主要用来避免循环引用

### 详细回答

提到智能指针，最核心的背景就是：

- RAII

也就是：

> 资源获取即初始化，资源释放绑定到对象生命周期。

智能指针本质上是一个类模板，它把原生指针封装起来，在对象离开作用域时自动析构并释放资源，从而避免手写 `delete` 带来的泄漏和异常路径问题。

#### 1. unique_ptr

`std::unique_ptr` 表示独占所有权。

特点：

- 一个资源同一时间只能被一个 `unique_ptr` 拥有
- 不能拷贝
- 可以移动

适合场景：

- 独占资源
- 明确所有权归属
- 绝大多数“只有一个主人”的堆对象

```cpp
#include <memory>

std::unique_ptr<int> ptr1(new int(10));
// std::unique_ptr<int> ptr2 = ptr1; // 错，不能拷贝
std::unique_ptr<int> ptr2 = std::move(ptr1); // 对，转移所有权
```

#### 2. shared_ptr

`std::shared_ptr` 表示共享所有权。

特点：

- 多个 `shared_ptr` 可以共同管理同一个对象
- 内部通过引用计数控制生命周期
- 最后一个 `shared_ptr` 析构时，资源才真正释放

适合场景：

- 资源需要被多个对象共享
- 无法明确唯一所有者

```cpp
#include <memory>

std::shared_ptr<int> p1 = std::make_shared<int>(10);
std::shared_ptr<int> p2 = p1; // 引用计数 +1
```

#### 3. weak_ptr

`std::weak_ptr` 是弱引用。

特点：

- 它可以观察 `shared_ptr` 管理的对象
- 但不会增加引用计数
- 它不拥有资源

最重要作用：

- 打破 `shared_ptr` 循环引用

```cpp
std::shared_ptr<int> sp = std::make_shared<int>(42);
std::weak_ptr<int> wp = sp; // 不增加引用计数
```

如果要访问资源，通常要先：

```cpp
if (auto p = wp.lock()) {
    // 对象还活着
}
```

### 三种智能指针一起看的例子

```cpp
#include <iostream>
#include <memory>
using namespace std;

class Animal {
public:
    Animal(string name) : name_(name) {
        cout << "Animal " << name_ << " created.\n";
    }

    ~Animal() {
        cout << "Animal " << name_ << " destroyed.\n";
    }

    void speak() {
        cout << "Hi, I'm " << name_ << endl;
    }

private:
    string name_;
};

int main() {
    unique_ptr<Animal> dog = make_unique<Animal>("Dog");
    dog->speak();

    shared_ptr<Animal> cat1 = make_shared<Animal>("Cat");
    {
        shared_ptr<Animal> cat2 = cat1;
        cout << "Cat use_count = " << cat1.use_count() << endl;
    }
    cout << "Cat use_count = " << cat1.use_count() << endl;

    weak_ptr<Animal> weakCat = cat1;
    if (auto catShared = weakCat.lock()) {
        catShared->speak();
    }

    return 0;
}
```

### 为什么智能指针更安全

因为它把资源释放动作放进了析构函数里。

这意味着：

- 正常离开作用域会释放
- 抛异常时也会随着栈展开自动释放

也就是说，它把内存管理从“靠人记得 delete”，变成了“靠对象生命周期自动完成”。

### 什么是 RAII

RAII 全称是：

- `Resource Acquisition Is Initialization`

意思就是：

- 获取资源时立刻交给对象托管
- 对象销毁时顺手把资源释放掉

通俗一点说：

> 我拿到资源我就负责到底，我走了我就顺手把它销毁。

```cpp
{
    std::unique_ptr<int> ptr(new int(10));
    // 用 ptr 做事
} // 离开作用域自动释放
```

### 记忆口诀

- `unique`：独家专属，不能复制
- `shared`：合作共赢，数清关系
- `weak`：偷偷观察，不管后事
- `RAII`：资源托管，内存不手动

## 智能指针的实现原理是什么

### 简要回答

智能指针本质上是一个类，通过：

- 构造函数接管资源
- 析构函数释放资源
- 运算符重载模拟指针行为

来实现 RAII 风格资源管理。

### 详细回答

智能指针本质上是一个类模板，它把原生指针包起来，通过对象的构造、析构和运算符重载，让它“看起来像指针”，但实际拥有自动资源管理能力。

可以把它理解成：

- 外面像指针
- 里面是一个会自动善后的对象

### 1. 基本原理

智能指针一般通过三件事工作：

1. 构造函数接管资源  
   比如保存原始指针地址，接手所有权。

2. 析构函数释放资源  
   对象离开作用域时自动清理。

3. 运算符重载模拟原生指针行为  
   例如重载：
   - `operator*`
   - `operator->`

所以你可以像用普通指针一样用智能指针，但不需要手写 `delete`。

### 2. unique_ptr 的实现原理

`unique_ptr` 的本质是：

- 内部保存一个原始指针
- 析构时自动 `delete`
- 禁止拷贝
- 支持移动

它通过“删除拷贝构造和拷贝赋值，只保留移动语义”来保证独占所有权。

```cpp
std::unique_ptr<int> p1(new int(10));
std::unique_ptr<int> p2 = std::move(p1);
```

这意味着：

- `p1` 不能复制给别人
- 但可以把所有权搬给 `p2`

### 3. shared_ptr 的实现原理

`shared_ptr` 的核心在于**引用计数**。

它通常不是只保存一个裸指针，而是还会关联一个“控制块”。

控制块里通常会有：

- 指向真实资源的指针
- `shared_count`：强引用计数
- `weak_count`：弱引用计数
- 删除器信息

可以粗略理解成：

```cpp
struct ControlBlock {
    void* ptr;
    std::atomic<int> shared_count;
    std::atomic<int> weak_count;
};
```

当 `shared_ptr` 发生：

- 拷贝构造
- 赋值

时，`shared_count + 1`。

当某个 `shared_ptr` 析构时，`shared_count - 1`。

当 `shared_count == 0` 时：

- 真实对象被释放

当 `shared_count == 0` 且 `weak_count == 0` 时：

- 控制块本身也会被释放

### 4. weak_ptr 的实现原理

`weak_ptr` 和 `shared_ptr` 共享同一个控制块，但它不增加 `shared_count`。

所以：

- 它能观察对象是否还活着
- 但不拥有对象
- 不阻止对象销毁

访问时通常要：

```cpp
if (auto p = wp.lock()) {
    // 说明对象还活着
}
```

这就是它解决循环引用的关键。

### 5. 代码示例

```cpp
#include <iostream>
#include <memory>
using namespace std;

class Dog {
public:
    std::string name;

    Dog(const std::string& name) : name(name) {
        std::cout << "Dog " << name << " is created." << std::endl;
    }

    ~Dog() {
        std::cout << "Dog " << name << " is destroyed." << std::endl;
    }

    void bark() {
        std::cout << name << " says: Woof!" << std::endl;
    }
};

void useUniquePtr() {
    std::unique_ptr<Dog> dog1 = std::make_unique<Dog>("UniqueDog");
    dog1->bark();
}

void useSharedAndWeakPtr() {
    std::shared_ptr<Dog> sharedDog = std::make_shared<Dog>("SharedDog");

    std::cout << "Shared use_count: " << sharedDog.use_count() << std::endl;

    std::weak_ptr<Dog> weakDog = sharedDog;

    {
        std::shared_ptr<Dog> sharedDog2 = sharedDog;
        std::cout << "Inside block, use_count: " << sharedDog.use_count() << std::endl;
    }

    std::cout << "Outside block, use_count: " << sharedDog.use_count() << std::endl;

    if (std::shared_ptr<Dog> lockedDog = weakDog.lock()) {
        std::cout << "Dog is still alive, name: " << lockedDog->name << std::endl;
        lockedDog->bark();
    }
}
```

### 6. 为什么推荐 make_shared / make_unique

例如：

```cpp
auto p = std::make_shared<MyClass>();
```

相比直接：

```cpp
std::shared_ptr<MyClass> p(new MyClass());
```

优点通常包括：

- 写法更简洁
- 异常安全更好
- `make_shared` 常常只申请一次内存，更高效、更缓存友好

### 7. 自定义删除器

智能指针不一定只能释放 `new` 出来的对象。

比如管理：

- `FILE*`
- `malloc` 出来的内存
- socket
- 第三方库句柄

就可以配自定义删除器。

这也是它比裸指针更强大的地方之一。

### 面试官可能追问

#### Q1：为什么说智能指针体现了 RAII？

因为智能指针对象构造时接管资源，析构时自动释放资源，资源生命周期被绑定到了对象生命周期上。

#### Q2：shared_ptr 为什么需要控制块？

因为它要管理：

- 强引用计数
- 弱引用计数
- 删除器
- 真实资源地址

没有控制块，就无法实现共享所有权和弱引用机制。

#### Q3：make_shared 为什么常常更高效？

因为它通常可以把“控制块 + 对象本体”放在一次内存分配里完成，而不是分两次申请。

### 面试短答

> 智能指针的本质是一个类模板，它把原生指针封装起来，通过构造函数接管资源、析构函数释放资源，并重载 `*` 和 `->` 来模拟指针行为，从而实现 RAII 风格资源管理。`unique_ptr` 通过禁止拷贝实现独占所有权，`shared_ptr` 通过控制块里的引用计数实现共享所有权，`weak_ptr` 和 `shared_ptr` 共用控制块但不增加强引用计数，主要用于解决循环引用问题。

## C++11 中的智能指针线程安全性

### 简要回答

智能指针的线程安全不能一概而论：

- `shared_ptr` 的引用计数增加和减少通常是线程安全的
- 但多个线程同时操作“同一个 shared_ptr 对象实例”本身，不代表所有操作都天然安全
- `unique_ptr` 不共享所有权，本身不提供跨线程共享语义

一句话记忆：

> `shared_ptr` 是“控制块线程安全”，不是“对象天然线程安全”。  
> 智能指针管的是所有权，不是自动帮你把业务数据也加锁。

### 详细回答

C++11 智能指针的线程安全性要分层理解，不能只回答“线程安全”或者“不线程安全”。

#### 1. 控制块的线程安全

对于 `shared_ptr` 和 `weak_ptr`，标准库内部通常会维护一个控制块，里面有：

- 强引用计数
- 弱引用计数
- 删除器等元数据

这些引用计数的增减通常通过原子操作完成，所以：

- 多个线程分别持有各自的 `shared_ptr` 副本
- 同时做拷贝、析构、计数增减

通常是安全的。

这就是“控制块线程安全”的含义。

#### 2. shared_ptr 指向的对象不自动线程安全

这是面试里最关键的一句。

即使多个线程安全地共享了同一个 `shared_ptr`，也不代表它指向的对象内部操作就是线程安全的。

例如：

```cpp
class Data {
public:
    int value = 0;
    void process() {
        ++value; // 非线程安全
    }
};
```

这里即便 `shared_ptr<Data>` 本身的引用计数安全，多个线程同时执行 `process()` 仍然会发生数据竞争。

也就是说：

- `shared_ptr` 解决的是“对象何时释放”
- 不是“对象内部怎么并发访问”

#### 3. 对同一个 shared_ptr 实例本身的写操作不安全

还要再区分一个层次：

- 多线程各自持有 `shared_ptr` 副本，并发读它们，一般没问题
- 但如果多个线程同时修改“同一个 shared_ptr 对象实例”，比如 `reset()`、重新赋值，就需要同步

因为这类写操作会涉及：

- 修改内部指针
- 调整引用计数
- 释放旧对象或接管新对象

如果没有同步，会产生数据竞争。

#### 4. unique_ptr 的线程安全性

`unique_ptr` 表示独占所有权，本身不适合被多个线程共同共享。

如果要跨线程转移 `unique_ptr`，通常要明确所有权转移时机，并保证：

- 不会多个线程同时操作同一个 `unique_ptr`

它没有像 `shared_ptr` 那样的共享控制块，所以没有“引用计数线程安全”这个层面。

#### 5. weak_ptr 的线程安全性

`weak_ptr` 和 `shared_ptr` 共用控制块，所以在：

- 引用控制块
- `lock()` 观察对象是否还活着

这些层面通常也是线程安全的。

但它同样不保证被观察对象内部的数据访问线程安全。

### 代码示例

```cpp
#include <iostream>
#include <memory>
#include <mutex>
#include <thread>
#include <vector>
using namespace std;

class Data {
public:
    int value = 0;

    void process() {
        ++value; // 非线程安全
    }
};

std::mutex data_mutex;

void safe_operation(std::shared_ptr<Data> sp) {
    auto local_sp = sp; // 安全：增加引用计数

    {
        std::lock_guard<std::mutex> lock(data_mutex);
        local_sp->process(); // 访问对象时仍需加锁
        std::cout << "Value: " << local_sp->value
                  << " in thread " << std::this_thread::get_id() << std::endl;
    }
}

void unsafe_operation(std::shared_ptr<Data>& sp_ref) {
    // 如果多个线程同时操作同一个 shared_ptr 实例并改它，可能数据竞争
    sp_ref->process();
}

int main() {
    auto shared_data = std::make_shared<Data>();

    std::vector<std::thread> threads;

    std::cout << "=== 安全操作示例 ===" << std::endl;
    for (int i = 0; i < 5; ++i) {
        threads.emplace_back(safe_operation, shared_data);
    }

    for (auto& t : threads) {
        t.join();
    }

    std::cout << "最终值: " << shared_data->value << std::endl;
}
```

### 多线程下的安全使用方式

比较稳的做法有三种：

#### 1. 值传递 shared_ptr

函数参数按值接收 `shared_ptr`，每个线程拿自己的副本。

```cpp
void worker(std::shared_ptr<Data> p);
```

这样对控制块引用计数的增加是安全的。

#### 2. const 引用 + 内部复制

如果不想在调用层多一次拷贝，也可以传 `const&`，再在函数内部显式复制一个本地副本。

#### 3. 发布 / 替换时加同步

如果是：

- 一个线程发布新 `shared_ptr`
- 其他线程读取这个全局 `shared_ptr`

那么这个“共享指针实例本身”的读写就需要同步，常见做法是：

- 加锁
- 或使用更新的原子共享指针方案

### 适用场景

#### shared_ptr 控制块线程安全的典型场景

1. 共享只读对象
2. 写入时复制场景
3. 多线程共同延长对象生命周期

#### 仍需同步的场景

1. 发布-订阅模式里替换全局 `shared_ptr`
2. 动态重配置时整体替换资源对象
3. 多线程同时修改被管理对象本身

### 面试官可能追问

#### Q1：shared_ptr 的引用计数是如何保证线程安全的？

通常通过原子操作实现。控制块中的引用计数增减是原子的，因此多个线程同时拷贝或销毁不同 `shared_ptr` 副本时，计数仍然正确。

#### Q2：为什么对同一个 shared_ptr 实例的写操作需要同步？

因为写操作会同时修改：

- 指针值
- 引用计数关系
- 资源所有权关系

这些步骤组合起来不是天然无锁安全的，所以多个线程同时改同一个 `shared_ptr` 实例会产生数据竞争。

#### Q3：如何安全地在多线程环境中传递 shared_ptr？

常见方式：

1. 按值传递
2. `const&` 传入后内部复制
3. 对共享实例的替换和发布加锁

#### Q4：什么是 ABA 问题？shared_ptr 如何避免？

ABA 问题是指一个值从 A 变成 B，又变回 A，表面看值没变，但中间其实发生过变化。

`shared_ptr` 不只是看裸指针值，它还关联控制块。哪怕地址值表面一样，如果控制块不是同一个，也不应该被视作同一个资源。

### 面试短答

> C++11 智能指针的线程安全要分层看：`shared_ptr` 和 `weak_ptr` 的控制块引用计数通常是线程安全的，但它们管理的对象本身并不会自动线程安全；另外，多个线程同时修改同一个 `shared_ptr` 实例也需要同步。简单说，智能指针保证的是“所有权和释放时机”这层的线程安全，不保证“对象内部业务数据”天然线程安全。
