## 类的基本结构

```cpp
class A {
public:
    A() {
        cout << "A()" << endl;
    }

    ~A() {
        cout << "~A()" << endl;
    }
};
```

- `public`：类外可以访问。
- `private`：只能类内访问，`class` 默认就是 private。
- 构造函数：对象创建时自动调用。
- 析构函数：对象销毁时自动调用。

## 构造函数什么时候会被调用

### 会调用构造函数

```cpp
A a;               // 调用 A::A()
A* p = new A();    // 调用 A::A()
A* arr = new A[3]; // 调用 3 次 A::A()
```

### 成员对象也会先构造

```cpp
class B {
    A a;
};

B b; // 先调用 A::A()，再调用 B::B()
```

### 不会调用构造函数

```cpp
A* p = nullptr; // 只是定义一个空指针，没有创建 A 对象
```

### 面试表达

构造函数和“对象真正被创建”绑定。定义对象、`new` 对象、创建数组元素、创建成员对象都会触发构造；单纯定义一个指针不会触发构造。

## 析构函数的基本作用

析构函数在对象生命周期结束时调用，常用于释放资源，比如堆内存、文件描述符、锁、数据库连接等。

```cpp
class FileGuard {
public:
    ~FileGuard() {
        // close(fd);
    }
};
```

相关思想：[[../../linux系统编程/概念词条/文件描述符|文件描述符]]、RAII。

## 构造函数和析构函数

### 简要回答

构造函数在对象创建时自动调用，用来初始化对象；析构函数在对象销毁时自动调用，用来释放对象持有的资源。

析构函数可以是虚函数，而且在“类可能作为基类、并通过基类指针删除派生类对象”时，通常必须写成虚函数；构造函数不能是虚函数，因为虚函数机制依赖对象已经构造完成后的虚表指针。

### 详细回答

#### 构造函数

构造函数是与类同名、没有返回类型的特殊成员函数。

它在对象创建时自动调用，主要作用是：

- 初始化成员变量。
- 建立对象的不变式。
- 申请对象需要持有的资源。

```cpp
class Student {
private:
    string name;
    int age;

public:
    Student(string n, int a) : name(n), age(a) {}
};
```

#### 析构函数

析构函数是类名前加 `~` 的特殊成员函数，也没有返回类型。

它在对象生命周期结束时自动调用，主要作用是：

- 释放堆内存。
- 关闭文件、socket、句柄。
- 回收锁、连接、临时资源。

```cpp
class Buffer {
private:
    int* data;

public:
    Buffer() : data(new int[10]) {}

    ~Buffer() {
        delete[] data;
    }
};
```

### 构造函数和析构函数能不能是虚函数

#### 构造函数不能是虚函数

构造函数不能声明为虚函数。

原因是：虚函数调用依赖对象中的虚函数指针，而这个虚函数指针是在对象构造过程中逐步建立的。对象都还没构造完成，就不可能通过完整的虚函数机制去分发构造函数。

换句话说，虚函数机制依赖“对象已经存在并且虚表已经就绪”，而构造函数正是对象建立过程的一部分，所以它不能是虚函数。

#### 析构函数可以是虚函数

析构函数可以声明为虚函数，而且基类析构函数很多时候应该是虚函数。

原因是：当我们通过基类指针删除派生类对象时，需要先执行派生类析构函数，再执行基类析构函数。如果基类析构函数不是虚函数，就会只调用基类析构函数，派生类部分得不到正确销毁，可能导致资源泄漏甚至未定义行为。

### 代码示例

```cpp
#include <iostream>
using namespace std;

class Base {
public:
    Base() {
        cout << "Base构造函数" << endl;
    }

    virtual ~Base() {
        cout << "Base析构函数" << endl;
    }
};

class Derived : public Base {
public:
    Derived() {
        cout << "Derived构造函数" << endl;
    }

    ~Derived() override {
        cout << "Derived析构函数" << endl;
    }
};

int main() {
    Base* obj = new Derived();
    delete obj;
    return 0;
}
```

输出顺序：

```text
Base构造函数
Derived构造函数
Derived析构函数
Base析构函数
```

### 构造和析构顺序

构造顺序：

1. 基类
2. 成员对象
3. 派生类

析构顺序刚好相反：

1. 派生类
2. 成员对象
3. 基类

### 知识拓展：纯虚析构函数

析构函数可以声明成纯虚函数，这样可以把类变成抽象类。

但注意：**纯虚析构函数仍然必须提供实现**，因为派生类析构时最终一定会调用到基类析构函数。

```cpp
class Abstract {
public:
    virtual ~Abstract() = 0;
};

Abstract::~Abstract() {}
```

### 面试官可能追问

#### Q1：什么情况下必须使用虚析构函数？

当一个类可能被继承，并且可能通过基类指针或基类引用的动态对象生命周期管理来销毁派生类对象时，基类析构函数应当声明为 `virtual`。

#### Q2：构造函数中可以调用虚函数吗？

技术上可以写，但构造函数中调用虚函数不会表现出我们平时理解的“多态”，而是静态绑定到当前正在构造的类版本。通常不建议这样做，因为容易让人误解对象已经完整构造好。

#### Q3：析构函数中抛出异常会怎样？

非常危险。

如果在栈展开过程中析构函数再抛异常，程序通常会直接调用 `std::terminate` 终止。因此析构函数一般不应抛异常。

## 构造函数有几种

### 简要回答

C++ 构造函数常见有以下几种：

1. 默认构造函数：无参或所有参数都有默认值，用于对象默认初始化。
2. 参数化构造函数：带参数，用于创建对象时进行特定初始化。
3. 拷贝构造函数：接受同类型对象引用，用已有对象初始化新对象。
4. 移动构造函数：C++11 引入，接受同类型对象右值引用，用于高效转移资源。
5. 委托构造函数：C++11 引入，一个构造函数调用同类中的另一个构造函数。
6. 继承构造函数：C++11 引入，派生类通过 `using Base::Base` 复用基类构造函数。

### 1. 默认构造函数

默认构造函数是无参构造函数，或者所有参数都有默认值的构造函数。

如果用户没有显式定义任何构造函数，编译器会尝试自动生成默认构造函数。

如果用户定义了其他构造函数，编译器通常不会再自动生成默认构造函数，除非显式写 `= default`。

```cpp
class A {
public:
    A() = default;
};
```

### 2. 参数化构造函数

参数化构造函数允许创建对象时传入参数，直接初始化成员变量。

```cpp
class Student {
private:
    string name;
    int age;

public:
    Student(string n, int a) : name(n), age(a) {}
};
```

它可以重载多个版本，以适应不同的初始化需求。

### 3. 拷贝构造函数

拷贝构造函数用于通过已有对象初始化新对象。

典型形式：

```cpp
ClassName(const ClassName& other);
```

如果不定义，编译器会生成默认拷贝构造函数，通常按成员逐个拷贝。对于含裸指针资源的类，这可能导致浅拷贝问题。

### 4. 移动构造函数

移动构造函数是 C++11 引入的，用于接收右值对象，把对方资源“搬过来”，避免昂贵的深拷贝。

典型形式：

```cpp
ClassName(ClassName&& other) noexcept;
```

常见于 STL 容器、智能指针、字符串、文件句柄等资源管理场景。

### 5. 委托构造函数

委托构造函数允许一个构造函数调用同一个类中的另一个构造函数，减少初始化代码重复。

```cpp
class Point {
public:
    Point() : Point(0, 0) {}
    Point(int x, int y) {}
};
```

### 6. 继承构造函数

派生类可以通过 `using Base::Base` 继承基类构造函数。

```cpp
class Base {
public:
    Base(int x) {}
};

class Derived : public Base {
public:
    using Base::Base;
};
```

注意：继承来的构造函数只负责基类部分初始化，派生类新增成员仍需要自己处理默认初始化或成员默认值。

### 代码示例

```cpp
#include <iostream>
#include <utility>
using namespace std;

class Example {
public:
    int* data;

    Example() : data(new int(0)) {
        cout << "Default constructor" << endl;
    }

    Example(int val) : data(new int(val)) {
        cout << "Parameterized constructor" << endl;
    }

    Example(const Example& other) : data(new int(*other.data)) {
        cout << "Copy constructor" << endl;
    }

    Example(Example&& other) noexcept : data(other.data) {
        other.data = nullptr;
        cout << "Move constructor" << endl;
    }

    Example(int a, int b) : Example(a + b) {
        cout << "Delegating constructor" << endl;
    }

    ~Example() {
        delete data;
        cout << "Destructor" << endl;
    }
};

class Derived : public Example {
public:
    using Example::Example;
    int derived_member = 42;
};

int main() {
    Example obj1;
    Example obj2(10);
    Example obj3(obj2);
    Example obj4(std::move(obj2));
    Example obj5(1, 2);

    Derived d(100);
    cout << *d.data << " " << d.derived_member << endl;

    return 0;
}
```

### 面试官可能追问

#### Q1：为什么需要移动构造函数？

为了避免对临时对象资源做昂贵深拷贝，提升性能。

比如 `std::vector::push_back`、函数返回局部对象、容器扩容等场景，如果对象持有堆内存、文件句柄、网络连接等资源，移动构造可以直接转移资源所有权。

#### Q2：拷贝构造函数参数为什么通常必须是 const 引用？

如果按值传参，会为了传入参数再次调用拷贝构造函数，从而无限递归。

使用 `const ClassName&` 有两个好处：

1. 避免再次拷贝。
2. 支持从 `const` 对象拷贝。

#### Q3：什么情况下编译器不会生成默认构造函数？

当用户定义了其他构造函数后，编译器通常不会自动生成无参默认构造函数。

如果仍然需要默认构造函数，可以显式声明：

```cpp
class A {
public:
    A(int x) {}
    A() = default;
};
```

## 虚析构函数

### 简要回答

如果一个类要作为基类，并且可能通过基类指针删除派生类对象，析构函数应该声明为 `virtual`。

```cpp
class Base {
public:
    virtual ~Base() = default;
};
```

### 为什么必须这样做

通过基类指针删除派生类对象时，程序必须知道对象的真实动态类型，才能按正确顺序执行析构函数链。

如果基类析构函数不是虚函数：

- `delete base_ptr;` 只会调用基类析构函数。
- 派生类析构函数不会执行。
- 派生类持有的资源可能泄漏。
- 行为属于未定义行为风险区域。

### 典型示例

```cpp
class Base {
public:
    ~Base() {
        cout << "Base dtor" << endl;
    }
};

class Derived : public Base {
private:
    int* data;

public:
    Derived() : data(new int[100]) {}

    ~Derived() {
        delete[] data;
        cout << "Derived dtor" << endl;
    }
};

Base* p = new Derived();
delete p; // 如果 Base 析构函数非虚，Derived 析构函数不会被正确调用
```

### 什么时候不一定需要虚析构

如果类明确不会被当作多态基类使用，也不会通过基类指针删除派生类对象，就不一定要把析构函数写成虚函数。

但经验上，只要类已经有其他虚函数，或者就是设计给继承层次使用的基类，析构函数通常就应该是虚函数。

## 重载 重写和隐藏

### 简要回答

- 重载：同一作用域内，函数名相同，参数列表不同。
- 重写：派生类重新实现基类虚函数，函数签名通常一致。
- 隐藏：派生类函数名和基类同名，会隐藏基类同名函数，哪怕参数不同。

更口语一点说：

- 重载：同一个类里，名字一样，但参数不一样，编译器在编译期就能分清。
- 重写：子类把父类的虚函数重新实现，真正调用哪个版本要到运行时才能决定。

### 详细回答

#### 1. 重载 Overload

重载发生在**同一个作用域**中，函数名相同，但参数列表不同。

参数列表不同可以表现为：

- 参数个数不同。
- 参数类型不同。
- 参数顺序不同。

返回值类型不同**不能单独**构成重载。

```cpp
class Printer {
public:
    void show(int x) {
        std::cout << "打印 int: " << x << std::endl;
    }

    void show(double x) {
        std::cout << "打印 double: " << x << std::endl;
    }
};
```

它属于编译时多态，也叫静态绑定。

#### 2. 重写 Override

重写发生在**继承关系**中，子类重新实现父类的虚函数。

要构成重写，通常要满足：

1. 必须有继承关系。
2. 父类函数必须是 `virtual`。
3. 子类函数名相同。
4. 参数列表相同。
5. 返回值相同，或满足协变返回类型规则。

```cpp
class Animal {
public:
    virtual void speak() {
        std::cout << "动物在叫" << std::endl;
    }
};

class Dog : public Animal {
public:
    void speak() override {
        std::cout << "狗在叫：汪汪汪" << std::endl;
    }
};
```

```cpp
Animal* a = new Dog();
a->speak(); // 输出 Dog 版本
```

它属于运行时多态，也叫动态绑定。

#### 3. 隐藏 Hide

隐藏也发生在继承中。

只要子类中出现了和父类同名的函数，就可能把父类同名函数隐藏掉，即使参数列表不同。

```cpp
class Base {
public:
    void func(int) {}
};

class Derived : public Base {
public:
    void func(double) {}
};
```

这时候 `Derived` 中的 `func(double)` 会把 `Base::func(int)` 隐藏掉。

### 重载和重写的核心区别

| 对比点 | 重载 overload | 重写 override |
|---|---|---|
| 发生位置 | 同一作用域，同一个类或同一命名空间 | 继承体系中，父类和子类之间 |
| 函数名 | 相同 | 相同 |
| 参数列表 | 必须不同 | 必须相同 |
| 返回值 | 不能仅靠返回值区分 | 通常相同，可协变 |
| 是否需要 virtual | 不需要 | 父类必须有 `virtual` |
| 绑定时机 | 编译期 | 运行期 |
| 本质 | 编译器挑选最匹配函数 | 运行时根据对象真实类型分发 |

### virtual 和 override 的区别

这是面试很爱追问的点。

#### virtual 是什么

`virtual` 写在**父类函数**前面，意思是：

“这个函数将来允许子类重写，并且我希望通过基类指针或引用调用时，能够表现出运行时多态。”

```cpp
class Base {
public:
    virtual void f() {}
};
```

#### override 是什么

`override` 写在**子类函数**后面，意思是：

“我这个函数就是要重写父类中的某个虚函数，请编译器帮我检查签名是否真的匹配。”

```cpp
class Derived : public Base {
public:
    void f() override {}
};
```

#### 两者关系

- `virtual` 是前提，决定父类函数能否参与运行时多态。
- `override` 是检查机制，帮助你避免“以为自己重写了，其实没有重写成功”的错误。

#### 为什么推荐写 override

因为一旦你写错参数、`const` 限定、引用限定或者返回类型，编译器会直接报错，而不是悄悄变成一个新的函数。

```cpp
class Base {
public:
    virtual void print() const {}
};

class Derived : public Base {
public:
    void print() override {} // 报错：少了 const
};
```

这正是 `override` 的价值。

### 面试时最好这样说

重载是同一作用域下同名不同参，编译器在编译期决定调用哪个；重写是子类重新实现父类虚函数，运行时根据对象真实类型决定调用哪个。`virtual` 写在父类上，表示这个函数支持多态；`override` 写在子类上，表示我明确要重写父类函数，并让编译器帮我检查。

### 面试官可能追问

#### Q1：重载能不能只靠返回值区分？

不能。

编译器在函数调用点选择函数时主要依据参数列表，不能只靠返回值判断调用哪个重载版本。

#### Q2：不加 virtual 会怎样？

如果父类函数不是虚函数，那么子类即使写了一个同名同参函数，也不会形成运行时多态。通过基类指针调用时，仍然会执行父类版本。

#### Q3：override 是不是必须写？

语法上不是必须。

但工程上强烈建议写。它能让编译器帮你检查重写是否真的成功，是非常有价值的防错机制。

#### Q4：子类里再写 virtual 有意义吗？

有，但更多是可读性上的重复声明。

父类已经把函数声明为虚函数后，子类对应重写函数天然也是虚函数。你可以继续写 `virtual`，但现代 C++ 更推荐直接写 `override`，表达更明确。

## C++ 如何实现多态

### 简要回答

C++ 多态分为编译时多态和运行时多态。

- 编译时多态：函数重载、运算符重载、模板。
- 运行时多态：继承 + 虚函数 + 基类指针或引用指向派生类对象。

如果面试官问“C++ 怎么实现多态”，一般重点答运行时多态：

**C++ 通过虚函数 `virtual`、继承、基类指针或引用调用，实现运行时多态。**

### 详细回答

#### 1. 编译时多态

编译时多态也叫静态多态，编译阶段就能确定调用哪个函数或实例化哪个模板。

常见形式：

- 函数重载
- 运算符重载
- 模板

#### 2. 运行时多态

运行时多态也叫动态多态，是 C++ 面向对象里最经典的多态形式。

实现条件通常有 4 个：

1. 必须有继承关系。
2. 基类函数必须声明为 `virtual`。
3. 派生类要对该虚函数进行重写。
4. 通过基类指针或基类引用调用该函数。

```cpp
class Animal {
public:
    virtual void speak() {
        std::cout << "动物在叫" << std::endl;
    }
};

class Dog : public Animal {
public:
    void speak() override {
        std::cout << "狗在叫：汪汪汪" << std::endl;
    }
};

int main() {
    Animal* a = new Dog();
    a->speak(); // 调用 Dog::speak()
    delete a;
}
```

### 一句话总结

**C++ 多态 = virtual + 继承 + 基类指针/引用调用 + 子类重写**

### 抽象类

如果一个虚函数写成 `= 0`，它就是纯虚函数；包含纯虚函数的类通常叫抽象类，不能直接实例化。

```cpp
class Animal {
public:
    virtual void run() = 0;
};
```

抽象类的意义是：定义统一接口，让派生类必须给出具体实现。

### C++11 中的 override 和 final

- `override`
  表示“我明确要重写父类虚函数”，让编译器帮你检查签名是否匹配。

- `final`
  可以修饰虚函数，表示禁止子类继续重写；
  也可以修饰类，表示禁止继续继承。

```cpp
class Base {
public:
    virtual void f() {}
};

class Derived : public Base {
public:
    void f() override final {}
};
```

### 性能方面

虚函数调用相比普通函数调用会稍慢一些，因为它需要通过虚函数表做一次间接跳转。

不过大多数业务代码里，这点开销通常不是瓶颈。真正影响更大的往往是对象设计、内存布局、缓存命中率和资源管理方式。

### 面试官可能追问

#### Q1：多态的底层是怎么实现的？

含有虚函数的类，编译器通常会为它生成一张虚函数表 `vtable`，表里保存虚函数地址。

每个这类对象内部通常会隐藏一个虚函数指针 `vptr`，指向所属类的虚函数表。

调用虚函数时，程序会先通过对象里的 `vptr` 找到虚函数表，再根据槽位取出对应函数地址并跳转执行。这就是动态绑定。

#### Q2：为什么普通成员函数不能实现运行时多态？

因为普通成员函数在编译阶段就确定要调用哪个函数，没有虚函数表参与，不会根据对象真实类型做运行时分发。

#### Q3：基类指针指向派生类对象，为什么能调用派生类版本？

因为基类指针虽然静态类型是基类，但对象真实类型是派生类。虚函数调用时看的是对象中的 `vptr`，而不是单纯看指针变量写成了什么类型。

## 虚函数和纯虚函数

### 简要回答

虚函数用 `virtual` 修饰，可以在派生类中重写；纯虚函数写成 `= 0`，含有纯虚函数的类通常是抽象类，不能直接实例化。

```cpp
class Shape {
public:
    virtual void draw() = 0;
};
```

更口语一点可以这么说：

- 虚函数：父类说“这个功能我先给你一个默认版本，子类可以改”。
- 纯虚函数：父类说“这个功能必须有，但我不规定具体怎么做，子类必须自己实现”。

### 详细回答

#### 1. 虚函数

虚函数是基类中用 `virtual` 声明的成员函数，用来支持运行时多态。

当通过基类指针或引用调用它时，程序会根据对象的真实类型，动态绑定到正确的函数实现。

虚函数的特点：

- 可以有默认实现。
- 派生类可以选择重写，也可以不重写。
- 含有虚函数的类仍然可以实例化。

```cpp
#include <iostream>
using namespace std;

class Animal {
public:
    virtual void speak() {
        cout << "Animal sound" << endl;
    }

    virtual ~Animal() {}
};

class Dog : public Animal {
public:
    void speak() override {
        cout << "Woof!" << endl;
    }
};
```

#### 2. 纯虚函数

纯虚函数是在虚函数声明后面加 `= 0`。

```cpp
class Shape {
public:
    virtual void draw() = 0;
};
```

它表示：

- 这个函数属于接口规范的一部分。
- 基类不要求给出普通默认实现。
- 派生类通常必须重写它。

包含纯虚函数的类称为**抽象类**，抽象类不能直接实例化。

```cpp
#include <iostream>
using namespace std;

class Shape {
public:
    virtual void draw() = 0;
    virtual ~Shape() {}
};

class Circle : public Shape {
public:
    void draw() override {
        cout << "Drawing a circle" << endl;
    }
};
```

### 虚函数和纯虚函数的核心区别

| 对比点 | 虚函数 | 纯虚函数 |
|---|---|---|
| 写法 | `virtual void f()` | `virtual void f() = 0` |
| 是否可有默认实现 | 可以 | 通常不作为普通默认实现使用 |
| 派生类是否必须重写 | 不必须 | 通常必须 |
| 所在类能否实例化 | 可以 | 含纯虚函数的类通常不能实例化 |
| 主要用途 | 提供可重写的默认行为 | 定义接口规范、形成抽象类 |

### 代码示例

#### 虚函数示例

```cpp
#include <iostream>
using namespace std;

class Animal {
public:
    virtual void speak() {
        cout << "Animal sound" << endl;
    }

    virtual ~Animal() {}
};

class Dog : public Animal {
public:
    void speak() override {
        cout << "Woof!" << endl;
    }
};

int main() {
    Animal* animal = new Dog();
    animal->speak(); // 输出 Woof!
    delete animal;
    return 0;
}
```

#### 纯虚函数示例

```cpp
#include <iostream>
using namespace std;

class Shape {
public:
    virtual void draw() = 0;
    virtual ~Shape() {}
};

class Circle : public Shape {
public:
    void draw() override {
        cout << "Drawing a circle" << endl;
    }
};

int main() {
    Shape* shape = new Circle();
    shape->draw(); // 输出 Drawing a circle
    delete shape;
    return 0;
}
```

### 知识拓展

#### 抽象类

只要类中存在纯虚函数，这个类通常就是抽象类，不能直接创建对象。

抽象类的作用是：统一接口，约束所有派生类必须提供某种能力。

#### Derived 是什么

`Derived` 就是“派生类”的意思，表示通过继承从基类 `Base` 扩展出来的新类。

#### 虚函数表工作原理

含有虚函数的类，编译器通常会生成虚函数表 `vtable`。

- `vtable` 里存放虚函数地址。
- 每个对象里通常有一个隐藏的虚函数指针 `vptr`。
- `vptr` 指向当前对象所属类型的虚函数表。
- 调用虚函数时，程序通过 `vptr` 找到 `vtable`，再跳转到正确函数，这就是动态绑定。

### 现代 C++ 相关关键字

#### override

`override` 用来显式标记“我是在重写父类虚函数”，编译器会帮你检查签名是否真的匹配。

```cpp
class Derived : public Base {
public:
    void show() override;
};
```

#### final

`final` 可以用来禁止继续重写虚函数，或者禁止类被继续继承。

```cpp
class Base {
public:
    virtual void show() final;
};
```

### 纯虚函数的特殊用法

纯虚函数虽然写了 `= 0`，但**仍然可以提供函数体实现**。

```cpp
class Interface {
public:
    virtual void api() = 0;
};

void Interface::api() {
    cout << "Default implementation" << endl;
}

class Impl : public Interface {
public:
    void api() override {
        Interface::api();
        cout << "Impl extension" << endl;
    }
};
```

这不影响它仍然是纯虚函数，也不改变该类是抽象类的事实。

### 面试官可能追问

#### Q1：为什么构造函数不能是虚函数？

构造函数的职责是把对象构造出来，而虚函数机制依赖对象中的 `vptr` 已经正确建立。对象还在构造过程中时，完整的虚函数分发机制还没准备好，所以构造函数不能是虚函数。

#### Q2：什么情况下应该使用纯虚函数？

当基类只规定“必须提供什么能力”，但不负责定义“具体怎么实现”时，就适合用纯虚函数。

典型场景：

- 设计接口类。
- 强制所有派生类都实现某个行为。
- 把公共抽象和具体实现分开。

#### Q3：虚函数表是如何工作的？

编译器会为含虚函数的类生成一张 `vtable`，对象里有一个 `vptr` 指向这张表。调用虚函数时，程序通过 `vptr` 找到 `vtable` 中对应函数地址，再跳转执行。

## 虚函数表和虚函数指针

### 简要回答

虚函数表 `vtable` 是 C++ 实现运行时多态的核心机制。它本质上是一张保存虚函数地址的表，通常可以理解成一个函数指针数组。

每个包含虚函数的类通常都会有一张对应的虚函数表；每个对象内部通常会有一个隐藏的虚函数指针 `vptr` 指向这张表。程序调用虚函数时，会通过 `vptr` 找到 `vtable`，再从里面取出正确的函数地址完成动态绑定。

### 详细回答

#### 1. 虚函数表 vtable

如果一个类中有虚函数，编译器通常会为这个类生成一张虚函数表 `vtable`。

这张表里通常按照声明顺序保存该类各个虚函数对应的函数地址。派生类如果重写了某个虚函数，那么它自己那张虚表里对应槽位会被替换成派生类版本的函数地址。

可以把它理解成一张“函数地址清单”。

#### 2. 虚函数指针 vptr

每个含虚函数的对象内部，通常会有一个隐藏成员指针，叫 `vptr`。

它指向当前对象所属动态类型对应的虚函数表。

面试里可以这么说：

“对象里藏着一个指向虚函数表的指针，调用虚函数时就是靠这个指针找到正确函数地址。”

#### 3. 调用过程

当通过基类指针或基类引用调用虚函数时，大致流程是：

1. 先通过对象找到内部的 `vptr`。
2. 再通过 `vptr` 找到该对象对应的 `vtable`。
3. 然后从 `vtable` 中取出对应虚函数地址。
4. 最后跳转执行这个函数。

这就是动态绑定，也是运行时多态的底层基础。

### 一句话总结

虚函数表保存虚函数地址，虚指针指向虚函数表，调用虚函数时通过 `vptr -> vtable -> 函数地址` 完成动态绑定。

### 按代码理解虚函数表

```cpp
#include <iostream>
using namespace std;

class Base {
public:
    virtual void func1() {
        cout << "Base::func1" << endl;
    }

    virtual void func2() {
        cout << "Base::func2" << endl;
    }

    void func3() {
        cout << "Base::func3" << endl;
    }
};

class Derived : public Base {
public:
    void func1() override {
        cout << "Derived::func1" << endl;
    }

    virtual void func4() {
        cout << "Derived::func4" << endl;
    }
};

int main() {
    Base b;
    Derived d;

    Base* pb = &d;
    pb->func1(); // Derived::func1
    pb->func2(); // Base::func2
    // pb->func4(); // 编译错误，Base 接口里没有 func4

    return 0;
}
```

### 这段代码里虚表大致是什么样

`Base` 类有两个虚函数：`func1` 和 `func2`，所以它的虚函数表可以理解为包含两个主要槽位：

- `&Base::func1`
- `&Base::func2`

`func3` 不是虚函数，因此不会进入虚函数表。

`Derived` 类会基于 `Base` 的虚函数表做扩展：

- 继承 `Base` 的虚函数槽位。
- 把 `func1` 对应槽位覆盖成 `&Derived::func1`。
- 保留 `func2` 对应槽位为 `&Base::func2`。
- 新增 `func4` 对应槽位为 `&Derived::func4`。

所以可以把 `Derived` 的虚表大致理解成：

- `&Derived::func1`
- `&Base::func2`
- `&Derived::func4`

### 为什么 pb->func1() 能调到 Derived 版本

因为 `pb` 虽然静态类型是 `Base*`，但它指向的真实对象是 `Derived`。调用虚函数时，程序会从这个真实对象里的 `vptr` 找到 `Derived` 对应的虚表，再取出 `func1` 槽位中的地址，所以最终执行 `Derived::func1`。

### 为什么 pb->func4() 不能调用

不是因为运行时找不到，而是因为在编译阶段，`pb` 的静态类型是 `Base*`，而 `Base` 的接口里根本没有声明 `func4`，所以这行代码连编译都过不了。

这也说明：**虚函数多态解决的是“调用哪个版本”的问题，不解决“接口里有没有这个函数声明”的问题。**

### 内存布局

#### vptr 一般放在哪里

在很多主流编译器实现中，`vptr` 通常会放在对象内存布局的起始位置或靠前位置，这样可以更快地通过对象地址访问虚函数表。

但要注意，这属于常见 ABI 实现细节，不应该写成“C++ 标准强制规定一定在第一个字节”。

#### 多继承时会怎样

多继承下，一个对象可能会有多个 `vptr`，因为不同继承链上的基类子对象可能各自需要一套虚函数分发表。

所以多继承对象的内存布局会比单继承复杂很多，这也是多继承难理解、难调试的一部分原因。

#### vtable 通常放在哪里

虚函数表通常由编译器在编译期生成，并放在程序的只读数据区，例如常见 ABI 下的 `.rodata` 或类似只读段。

面试里答“通常在只读数据段，由编译器生成”就够了，不必把它说成标准强制规定。

### 性能开销

虚函数和普通函数最大的区别在于绑定时机和调用方式。

- 普通函数：编译期绑定，调用时通常直接跳转。
- 虚函数：运行期绑定，调用时需要先通过 `vptr` 找 `vtable`，再间接跳转到目标函数。

因此虚函数调用通常会多一次间接寻址，开销略高于普通函数。

不过这点开销换来了运行时多态能力。多数业务代码里，这不是主要瓶颈。

### 面试官可能追问

#### Q1：vtable 和 vptr 的内存布局是怎样的？

可以答：对象内部通常会有一个隐藏的 `vptr`，它一般位于对象布局的前部，用来指向类的 `vtable`。但这是常见实现方式，不是语言标准对字节级布局的硬性承诺。多继承场景下，一个对象可能带多个 `vptr`。

#### Q2：虚函数和普通函数调用开销有什么不同？

普通函数通常在编译期完成绑定，调用更直接。虚函数需要运行时通过 `vptr` 找 `vtable` 再跳转，因此多了一次间接调用，性能略低。但这种代价换来了运行时多态能力。

#### Q3：派生类重写虚函数后，虚表会发生什么？

派生类自己的虚函数表中，对应槽位会替换成派生类重写后的函数地址。这样基类指针指向派生类对象时，调用虚函数就会跳到派生类实现。

#### Q4：构造函数中能调用虚函数吗？会发生什么？

可以调用，但不会表现出我们平时理解的完整运行时多态。

在构造过程中，对象的动态类型正在逐步建立，当前阶段通常只会绑定到“当前正在构造的类”对应的版本，而不是更深层派生类版本。所以构造函数里调用虚函数通常会静态地落到当前类实现上，工程里一般不推荐这样写。

#### Q5：虚函数多态和模板多态有什么区别？

虚函数多态是运行时多态，依赖继承、虚函数表和动态绑定，灵活但有运行时开销。

模板多态是编译时多态，依赖模板实例化，通常没有虚函数那样的运行时分发开销，但要求类型关系在编译期就确定。

## 多重继承和菱形继承

### 简要回答

多重继承允许一个类继承多个基类，表达能力强，但会带来对象布局复杂、命名冲突、菱形继承等问题。

菱形继承指两个中间类继承同一个基类，最终派生类同时继承这两个中间类，可能导致基类子对象重复。

菱形继承会让最派生类里出现多个同一基类子对象，产生二义性和数据冗余。C++ 通常通过**虚继承**来解决，保证虚基类在最派生类中只保留一份。

### 详细回答

#### 多重继承是什么

多重继承指一个类同时继承多个基类。

```cpp
class A {};
class B {};

class C : public A, public B {};
```

这让类 `C` 可以同时获得 `A` 和 `B` 的接口和行为。

### 多重继承的优点

1. 接口组合。
   可以把多个抽象接口组合在一个类里，实现更复杂能力。

2. 代码复用。
   可以同时复用多个已有类的实现。

3. 更自然的建模。
   某些现实世界关系用多重继承表达更直观，比如“助教既是老师又是学生”。

### 多重继承的缺点

1. 名称冲突。
   多个基类如果有同名成员，派生类使用时会产生二义性。

2. 菱形继承问题。
   同一个基类通过多条路径被继承，可能在最派生类中重复出现。

3. 复杂性增加。
   类层次更难理解、更难维护。

4. 对象布局复杂。
   多重继承对象的内存布局通常更复杂，调试和分析成本更高。

### 菱形继承问题是什么

当一个派生类通过两条路径继承同一个基类时，就形成菱形继承。

```text
    Person
    /    \
Teacher Student
    \    /
TeachingAssistant
```

这时 `TeachingAssistant` 里可能会出现两份 `Person` 子对象：一份来自 `Teacher` 路径，一份来自 `Student` 路径。

这会带来两个典型问题：

1. 数据冗余。
   同一个基类成员保存了两份。

2. 访问二义性。
   编译器不知道你想访问哪一条路径上的基类成员。

### 代码示例

```cpp
#include <iostream>
#include <string>
using namespace std;

class Person {
public:
    string name;

    Person(const string& n) : name(n) {}

    virtual void introduce() {
        cout << "我是" << name << endl;
    }
};

class Teacher : public Person {
public:
    string subject;

    Teacher(const string& n, const string& s)
        : Person(n), subject(s) {}

    void introduce() override {
        cout << "我是教师" << name << "，教授" << subject << endl;
    }
};

class Student : public Person {
public:
    int grade;

    Student(const string& n, int g)
        : Person(n), grade(g) {}

    void introduce() override {
        cout << "我是学生" << name << "，年级" << grade << endl;
    }
};

class TeachingAssistant : public Teacher, public Student {
public:
    TeachingAssistant(const string& n, const string& s, int g)
        : Teacher(n, s), Student(n, g) {}
};
```

此时：

```cpp
TeachingAssistant ta("张三", "数学", 3);
// cout << ta.name << endl; // 错，二义性

cout << ta.Teacher::name << endl;
cout << ta.Student::name << endl;
```

### 如何解决菱形继承：虚继承

C++ 通过虚继承解决菱形继承问题。

```cpp
class VirtualTeacher : virtual public Person {
public:
    string subject;

    VirtualTeacher(const string& n, const string& s)
        : Person(n), subject(s) {}
};

class VirtualStudent : virtual public Person {
public:
    int grade;

    VirtualStudent(const string& n, int g)
        : Person(n), grade(g) {}
};

class VirtualTeachingAssistant : public VirtualTeacher, public VirtualStudent {
public:
    VirtualTeachingAssistant(const string& n, const string& s, int g)
        : Person(n),
          VirtualTeacher(n, s),
          VirtualStudent(n, g) {}

    void introduce() override {
        cout << "我是助教" << name
             << "，教授" << subject
             << "，年级" << grade << endl;
    }
};
```

虚继承的效果是：无论 `Person` 在继承路径中出现多少次，在最终派生类中都只保留一个共享的 `Person` 子对象。

### 为什么最派生类要初始化虚基类

在虚继承中，虚基类最终由**最派生类**负责初始化。

所以在：

```cpp
class VirtualTeachingAssistant : public VirtualTeacher, public VirtualStudent
```

里，需要由 `VirtualTeachingAssistant` 负责写 `: Person(n)`。

### 虚继承的大致实现原理

编译器通常会通过虚基类指针 `vbptr` 和虚基类表 `vbtable` 一类机制，记录虚基类子对象在对象布局中的偏移信息，从而保证所有继承路径共享同一个虚基类实例。

面试里答到这个层次已经很够了，不用过度展开 ABI 细节。

### 多重继承的替代方案

很多场景下，组合比多重继承更稳。

常见替代思路：

1. 组合优先。
   把多个能力类作为成员对象组合到新类里。

2. 接口继承。
   使用纯虚函数接口类，实现“接口继承”和“实现继承”分离。

3. Mixin 混入类。
   用模板或小功能类给现有类增加通用能力。

### 什么时候应避免多重继承

1. 能用组合表达清楚时。
2. 对性能和对象布局敏感的系统。
3. 团队成员对这套继承关系很难快速理解时。

### 面试官可能追问

#### Q1：如何解决多重继承中的名称冲突？

使用作用域解析运算符显式指定访问路径。

```cpp
ta.Teacher::name;
ta.Student::name;
```

#### Q2：虚继承是如何解决菱形继承问题的？

虚继承保证虚基类在最终派生类中只保留一个共享实例，不会沿着每条继承路径各复制一份。编译器通常通过记录偏移量的辅助结构来定位这唯一的虚基类子对象。

#### Q3：多重继承时析构函数应该怎么写？

派生类析构函数通常不需要手动显式调用基类析构函数，编译器会自动按正确顺序调用。

但如果类层次会通过基类指针删除派生类对象，那么基类析构函数应该声明为虚函数，否则可能无法正确析构派生类部分。

## 如何禁止一个类被继承

### 简要回答

C++11 之后可以使用 `final` 禁止类被继承。

```cpp
class A final {
};
```

当 `final` 修饰类时，这个类就成为最终类，任何类再去继承它，都会在编译阶段直接报错。

### 详细回答

#### 1. 使用 final 关键字

`final` 是 C++11 引入的关键字，专门用于限制类的继承或者虚函数的继续重写。

当它修饰类时，表示这个类不能再被继承：

```cpp
class Base final {
public:
    void show() {}
};

// class Derived : public Base {}; // 编译错误
```

原理很直接：编译器在解析继承关系时，发现你试图继承一个 `final` 类，就会在编译期报错，因此没有运行时开销。

这也是现代 C++ 里**禁止类被继承的首选方案**。

#### 2. final 除了修饰类，还能修饰虚函数

`final` 不仅能修饰类，也能修饰虚函数。

当它修饰虚函数时，表示这个函数在当前类里已经是最终版本，派生类不能继续重写。

```cpp
class Base {
public:
    virtual void f() final {}
};
```

如果子类再尝试重写 `f()`，编译器会报错。

### 为什么说 final 语义好

因为它非常直白。

- 修饰类：我这个类不允许再被继承。
- 修饰虚函数：我这个虚函数不允许再被继续重写。

这种写法比各种技巧性写法更清晰，也更容易维护。

### C++11 之前的替代方案

在 C++11 之前，没有 `final` 关键字，只能通过一些比较绕的技巧间接限制继承。

常见思路是：

1. 把基类构造函数设为私有。
2. 利用友元类放开特定访问权限。
3. 借助虚继承等机制，让再往下的派生类无法正确调用基类构造函数。

例如：

```cpp
class MakeFinal {
private:
    MakeFinal() {}
    friend class Derived;
};

class Derived : virtual public MakeFinal {
public:
    Derived() {}
};

// class FurtherDerived : public Derived {}; // 再往下继承会很麻烦甚至直接失败
```

这种写法的核心问题是：

- 语义不直观。
- 可读性差。
- 依赖复杂继承和访问控制细节。
- 维护成本高。

所以现在面试里只需要知道：**C++11 之前有曲线救国的办法，但现代 C++ 已经用 final 彻底取代它。**

### 性能上的好处

`final` 有时还能给编译器更多优化空间。

如果编译器知道一个类是 `final`，或者一个虚函数是 `final`，它就能更大胆地做去虚拟化优化，也就是把原本需要通过虚表间接分发的调用，优化成直接调用，甚至进一步内联。

这对性能敏感代码是有帮助的。

### 面试官可能追问

#### Q1：final 在性能上有什么好处？

编译器知道类或虚函数不会再被继续派生或重写后，可以更容易做去虚拟化优化，把虚函数调用变成直接调用，减少虚表间接跳转开销。

#### Q2：final 和 override 能一起用吗？

可以。

```cpp
class Base {
public:
    virtual void f() {}
};

class Derived : public Base {
public:
    void f() override final {}
};
```

这里 `override` 表示“我在重写父类虚函数”，`final` 表示“我重写到这里为止，后面不准再改”。

#### Q3：C++11 之前怎么禁止继承？

知道有“私有构造函数 + 友元 + 虚继承”这类技巧即可。面试里不建议把它当主方案讲，重点强调现代 C++ 直接用 `final`。

## 深拷贝和浅拷贝

### 简要回答

浅拷贝只复制成员变量的值。如果成员里有指针，那么复制的只是地址，多个对象会指向同一块资源。

深拷贝会重新分配资源，并把原对象的内容复制过去。这样新旧对象互不影响，各自拥有独立资源。

### 详细回答

拷贝语义主要通过两类操作体现：

- 拷贝构造函数
- 拷贝赋值运算符

当类里只包含普通值类型成员时，编译器生成的默认拷贝一般问题不大；但只要类开始自己管理资源，比如堆内存、文件句柄、网络连接、锁等，就必须小心区分浅拷贝和深拷贝。

#### 浅拷贝

浅拷贝只复制对象的第一层成员。

- 基本类型直接复制值。
- 指针成员只复制地址。

这样两个对象会共享同一块资源。（指针指向同一块地址）

后果可能包括：

- 一个对象修改资源，另一个对象也受到影响。
- 一个对象释放资源后，另一个对象手里的指针变成悬垂指针。
- 两个对象析构时都去释放同一块内存，导致 `double free`。

#### 深拷贝

深拷贝会给资源重新分配一份独立副本。

- 指针成员不只是复制地址。
- 而是重新 `new` 一块内存，把内容复制进去。

这样两个对象各自拥有自己的资源副本，生命周期互不干扰。

### 一个好记的比喻

把对象想成一个带锁的箱子，箱子里有贵重物品。

- 浅拷贝像复制钥匙：两个人都能打开同一个箱子。
- 深拷贝像连箱子和里面的物品一起复制：各管各的，不会互相干扰。

### 代码示例

```cpp
#include <iostream>
using namespace std;

class Deep {
public:
    int* data;

    Deep(int value) {
        data = new int(value);
    }

    Deep(const Deep& other) {
        data = new int(*other.data);
    }

    Deep& operator=(const Deep& other) {
        if (this != &other) {
            delete data;
            data = new int(*other.data);
        }
        return *this;
    }

    ~Deep() {
        delete data;
    }
};

int main() {
    Deep obj1(10);
    Deep obj2 = obj1;

    *obj2.data = 20;

    cout << *obj1.data << endl; // 10
    cout << *obj2.data << endl; // 20

    return 0;
}
```

### 什么时候适合浅拷贝

1. 对象只包含基本类型或 POD 类型。
2. 设计上就是要共享资源。
3. 用了共享所有权机制，比如某些引用计数对象。

### 什么时候必须考虑深拷贝

1. 对象包含裸指针或动态分配资源。
2. 需要得到完全独立的对象副本。
3. 不希望不同对象共享内部状态。
4. 资源生命周期由对象自己负责管理。

### 为什么会出现 double free

因为浅拷贝后两个对象保存的是同一个地址，而析构函数里都执行 `delete`。

```cpp
// 假设默认浅拷贝
Shallow a(10);
Shallow b = a;
```

`a.data` 和 `b.data` 指向同一块内存。等两个对象析构时，就会对同一地址释放两次。

### STL 容器里的影响

STL 容器默认是值语义。

这意味着：

- `push_back`
- `insert`
- 扩容搬迁

都可能触发拷贝构造或移动构造。

如果你的类包含裸指针，却没有正确实现深拷贝或移动语义，放进容器后很容易因为浅拷贝导致崩溃。

另外还有一个经典问题：对象切片。

```cpp
std::vector<Base> vec;
vec.push_back(Derived()); // 派生类额外部分被切掉
```

如果是多态对象，通常更适合用指针容器或智能指针容器：

```cpp
std::vector<std::unique_ptr<Base>> vec;
```

### 如何设计“既能深拷贝又能共享资源”的类

一种经典思路是写时复制 COW（Copy On Write）：

- 默认先共享资源。
- 真正修改前再复制出自己的独立副本。

现代 C++ 更常见的做法是：

- 用 `std::shared_ptr` 管理共享资源。
- 在需要独立副本时显式克隆。

面试里知道这个方向就够了，不需要一上来把 COW 讲得过深。

### 面试官可能追问

#### Q1：什么情况下浅拷贝会出问题？

当类中有裸指针或自己管理动态资源时，默认浅拷贝会让多个对象共享同一资源，进而引发悬垂指针、重复释放和状态互相污染。

#### Q2：为什么会 double free？

因为两个对象通过浅拷贝拿到了同一个资源地址，析构时都去释放它，导致同一块内存被释放两次。

#### Q3：在 STL 容器中存储自定义对象时，拷贝语义如何影响容器行为？

容器采用值语义，插入和扩容都可能触发拷贝构造或移动构造。如果类没实现好拷贝语义，放进容器后很容易出现共享同一资源、析构崩溃等问题。继承场景下还要注意对象切片。

#### Q4：拷贝构造和赋值运算符有什么区别？

拷贝构造是“创建一个新对象时，用另一个对象初始化它”；赋值运算符是“对象已经存在，再把另一个对象赋值给它”。两者都可能需要处理资源复制。

#### Q5：三五法则是什么？

如果类需要自定义析构函数、拷贝构造函数、拷贝赋值运算符中的一个，通常就要考虑另外两个，这叫三法则。

到了 C++11，还要把移动构造和移动赋值也一起考虑，这就是五法则。

## this 指针

### 简要回答

`this` 是每个**非静态成员函数**里隐含存在的一个特殊指针，它指向“当前调用这个成员函数的对象”。

它的本质可以理解为一个隐藏参数，类型通常是：

```cpp
ClassName *const this
```

也就是说，`this` 本身是常量指针，指向当前对象。

```cpp
class A {
public:
    int x;

    void set(int x) {
        this->x = x;
    }
};
```

### 详细回答

#### 本质与类型

`this` 是编译器自动加到每个非静态成员函数最前面的一个隐藏参数。

如果成员函数不是 `const` 成员函数，它大致可以看成：

```cpp
ClassName *const this
```

如果成员函数是 `const` 成员函数，那么它更接近：

```cpp
const ClassName *const this
```

这意味着：

- `this` 这个指针本身不能改指向。
- 但在非 `const` 成员函数里，可以通过它修改对象成员。
- 在 `const` 成员函数里，不能通过它修改普通成员，除非成员被 `mutable` 修饰。

#### 存储位置

`this` 本质上是函数参数，所以它和普通函数参数一样，通常跟随函数调用约定传递。你可以把它理解成“调用成员函数时，编译器悄悄把对象地址传了进去”。

#### 生命周期

`this` 的生命周期和普通函数形参一样：

- 成员函数被调用时传入。
- 成员函数返回时结束。

#### 主要用途

1. 访问当前对象的成员。
2. 解决成员变量和函数参数同名时的歧义。
3. 返回当前对象自身，用于链式调用。

#### 箭头运算符和点运算符

这一点很容易混：

```cpp
p->member
```

等价于：

```cpp
(*p).member
```

它们**都用于指针场景**，只是前者是语法糖，后者是先解引用再访问成员。

真正的对象访问写法是：

```cpp
obj.member
```

所以更准确的说法是：

- `p->member`：指针访问成员。
- `(*p).member`：指针解引用后访问成员。
- `obj.member`：对象直接访问成员。

#### 代码示例

```cpp
#include <iostream>
using namespace std;

class MyClass {
public:
    MyClass(int value) : value_(value) {}

    void PrintValue() {
        cout << "Value: " << value_ << endl;
        cout << "This address: " << this << endl;
    }

    void SetValue(int value_) {
        this->value_ = value_;
    }

    MyClass& Add(int n) {
        value_ += n;
        return *this;
    }

private:
    int value_;
};

int main() {
    MyClass obj1(10);
    MyClass obj2(20);

    cout << "Address of obj1: " << &obj1 << endl;
    obj1.PrintValue();

    cout << "Address of obj2: " << &obj2 << endl;
    obj2.PrintValue();

    obj1.SetValue(42);
    obj1.PrintValue();

    obj2.Add(5).Add(10).PrintValue();
    return 0;
}
```

#### const 成员函数中的 this

在 `const` 成员函数中，`this` 可以理解为指向常量对象的指针，所以不能通过它修改普通成员。

```cpp
class A {
public:
    int get() const {
        return value_;
    }

private:
    int value_ = 0;
};
```

#### 静态成员函数为什么没有 this

静态成员函数属于类本身，而不是某个具体对象。

调用它时甚至不需要对象：

```cpp
ClassName::func();
```

既然没有“当前对象”，自然也就没有对象地址可传，所以静态成员函数没有 `this`。

### 易错点

- `this` 只能在非静态成员函数中使用。
- 静态成员函数属于类本身，不属于某个具体对象，因此没有 `this`。
- `p->member` 和 `(*p).member` 都是指针访问成员，不要和 `obj.member` 混淆。

### 后续追问

#### Q1：this 指针是谁传进去的？

编译器自动传入。

成员函数表面上看起来像 `obj.func()`，底层可以理解成普通函数调用时把 `&obj` 作为隐藏实参传给了这个成员函数。

#### Q2：this 指针可以为 nullptr 吗？

从“值”上说可以出现，比如你通过空指针错误地调用成员函数时，函数内部的 `this` 可能就是空。

但这种行为是未定义行为。只要函数内部访问成员变量，基本就会触发空指针解引用风险，所以不能把这当成合法设计。

#### Q3：this 指针和智能指针有什么关系？

`this` 是一个裸指针，只表示地址，不拥有对象，也不管理生命周期。

它和 `std::shared_ptr`、`std::unique_ptr` 这种管理所有权的智能指针不是一个层面的东西。

如果确实需要在对象内部安全地拿到指向自身的 `shared_ptr`，通常使用 `std::enable_shared_from_this`。

#### Q4：为什么静态成员函数没有 this 指针？

因为静态成员函数不依赖某个具体对象，调用时没有对象地址可传，自然没有 `this`。

#### Q5：*this 是什么？

`this` 是指针，`*this` 是对它解引用后得到的当前对象本身，类型通常是 `ClassName&`。

它常用于返回当前对象，支持链式调用：

```cpp
return *this;
```

## 单例模式

### 简要回答

单例模式保证一个类在程序中只有一个实例，并提供一个全局访问点。

常见写法：

- 饿汉式：程序启动时创建实例。
- 懒汉式：第一次使用时创建实例。
- Meyer's Singleton：函数内局部静态对象，C++11 起初始化线程安全。

如果面试官问“C++ 如何实现一个单例模式”，最推荐直接答：

**现代 C++ 优先使用 C++11 的局部静态变量写法，也叫 Magic Static。**

```cpp
class Singleton {
public:
    static Singleton& getInstance() {
        static Singleton instance;
        return instance;
    }

private:
    Singleton() = default;
    Singleton(const Singleton&) = delete;
    Singleton& operator=(const Singleton&) = delete;
};
```

### 详细回答

单例模式要解决两个问题：

1. 如何保证这个类只能有一个实例。
2. 如何提供一个全局访问点让别人拿到这个实例。

常见做法有三部分：

- 权限控制：构造函数私有化，防止外部直接 `new` 或直接定义对象。
- 禁止拷贝：删除拷贝构造和赋值运算符，防止复制出第二个对象。
- 静态管家：类内部保存唯一实例，并通过 `getInstance()` 暴露访问入口。

### 1. 饿汉式

特点：程序启动时就把实例创建好。

优点：

- 实现简单。
- 天生线程安全。

缺点：

- 如果实例始终没被用到，也会提前占用资源。

```cpp
class Singleton {
private:
    static Singleton* instance;
    Singleton() {}

public:
    static Singleton* getInstance() {
        return instance;
    }
};

Singleton* Singleton::instance = new Singleton();
```

### 2. 懒汉式

特点：第一次使用时才创建实例。

优点：

- 延迟创建，资源利用率更高。

缺点：

- 最基础写法线程不安全。

```cpp
class Singleton {
private:
    static Singleton* instance;
    Singleton() {}

public:
    static Singleton* getInstance() {
        if (!instance) {
            instance = new Singleton();
        }
        return instance;
    }
};

Singleton* Singleton::instance = nullptr;
```

### 3. 双检锁

特点：懒加载 + 线程安全。

思路是：

- 第一次先不加锁快速判断。
- 为空时再进入临界区加锁。
- 加锁后再次判断，避免多个线程重复创建。

```cpp
class Singleton {
private:
    static Singleton* instance;
    static std::mutex mtx;
    Singleton() {}

public:
    static Singleton* getInstance() {
        if (instance == nullptr) {
            std::lock_guard<std::mutex> lock(mtx);
            if (instance == nullptr) {
                instance = new Singleton();
            }
        }
        return instance;
    }
};
```

这类写法在面试里可以知道，但现代 C++ 更推荐下面这种更简洁的方案。

### 4. 局部静态变量 Magic Static

这是现代 C++ 最推荐的单例实现方式。

特点：

- 写法简洁。
- C++11 起初始化线程安全。
- 延迟初始化。
- 对象生命周期由语言机制管理，程序结束时自动销毁。

```cpp
class Singleton {
public:
    Singleton(const Singleton&) = delete;
    Singleton& operator=(const Singleton&) = delete;

    static Singleton& getInstance() {
        static Singleton instance;
        return instance;
    }

private:
    Singleton() = default;
};
```

### 推荐实现代码

```cpp
#include <iostream>
#include <string>
using namespace std;

class Singleton {
public:
    Singleton(const Singleton&) = delete;
    Singleton& operator=(const Singleton&) = delete;

    static Singleton& getInstance() {
        static Singleton instance; // C++11 起线程安全初始化
        return instance;
    }

    void log(const string& message) {
        cout << "[LOG] " << message << endl;
    }

private:
    Singleton() {
        cout << "Singleton created" << endl;
    }

    ~Singleton() {
        cout << "Singleton destroyed" << endl;
    }
};

int main() {
    Singleton::getInstance().log("Hello World");
    Singleton::getInstance().log("Another message");
    return 0;
}
```

### 单例模式的优缺点

优点：

1. 严格控制实例数量，避免重复创建。
2. 提供统一的全局访问入口。
3. 适合管理日志器、配置、设备控制器等全局资源。

缺点：

1. 容易形成全局状态，测试不方便。
2. 可能隐藏模块之间的依赖关系。
3. 某种程度上违反单一职责原则，因为类既管业务又管自身唯一性。

### 使用场景

典型场景：

- 日志管理器。
- 数据库连接池管理器。
- 配置读取器。
- 串口、打印机等设备控制器。
- 游戏里的全局资源管理器、音效管理器、UI 管理器。

### 面试官可能追问

#### Q1：为什么推荐局部静态变量单例？

因为它既简洁，又能在 C++11 以后保证线程安全初始化，还能避免手写锁和复杂双检逻辑，基本是现代 C++ 的首选答案。

#### Q2：单例模式一定好吗？

不一定。

它适合全局唯一资源，但如果滥用，会把程序搞成大量隐式共享状态，增加耦合，降低可测试性。

#### Q3：为什么要删除拷贝构造和赋值运算符？

因为如果不删，别人可能通过复制单例对象再构造出第二份实例，这就破坏了“全局唯一”的设计目标。

#### Q4：局部静态变量为什么线程安全？

C++11 标准保证局部静态变量的初始化具有线程安全性。多个线程同时第一次进入 `getInstance()` 时，只有一个线程会执行初始化，其余线程会等待。

更多静态初始化规则见：[[06 内存生命周期与静态成员#饿汉式单例中的静态成员初始化]]

## std move 和移动语义

### 简要回答

`std::move` 本身并不移动任何东西，它做的事情是把一个左值显式转换成右值引用，从而告诉编译器：

> 这个对象的资源可以被“搬走”了。

真正发生资源转移的，是后续被调用的移动构造函数或移动赋值运算符。

### 详细回答

#### 1. std::move 是什么

很多人第一次看到 `std::move`，会误以为它会直接把对象内容搬走。

其实不是。

`std::move` 的本质更接近一个强制类型转换，它把：

- 左值

转换成：

- 右值引用

这样后面的函数重载解析就更容易命中移动构造或移动赋值版本。

```cpp
std::string s = "hello";
std::string t = std::move(s);
```

这里真正移动资源的不是 `std::move`，而是 `std::string` 的移动构造函数。

#### 2. 为什么需要移动语义

因为很多对象管理的资源很重，比如：

- 堆内存
- 文件句柄
- 网络连接
- 大块字符串缓冲区

如果每次都深拷贝，代价很高。

移动语义的思想是：

- 不是复制一份资源
- 而是把资源所有权转移给新对象

这样能减少不必要的拷贝开销。

#### 3. 右值引用和移动构造

移动构造函数的典型形式是：

```cpp
ClassName(ClassName&& other) noexcept;
```

它接收一个右值引用，通常会：

- 接管对方资源
- 再把对方资源指针置空或置成安全状态

#### 4. move 后原对象会怎样

`std::move` 之后，原对象并不一定“彻底不能用”，但它通常只保证处于“有效但未指定状态”。

面试里最稳的说法是：

> move 之后不要再依赖原对象的具体值，只能假设它还能被安全析构、赋新值或重新初始化。

#### 5. 常见使用场景

1. 容器插入临时对象或可转移对象。
2. 函数返回大型对象。
3. 资源管理类实现移动构造 / 移动赋值。
4. 避免不必要深拷贝。

#### 6. 面试官可能追问

##### Q1：`std::move` 会真的移动对象吗？

不会。它只做类型转换，把左值转换成右值引用。真正移动的是后续命中的移动构造函数或移动赋值运算符。

##### Q2：为什么 move 后还要把原对象指针置空？

因为资源已经转走了，如果原对象析构时还保留旧指针，就可能重复释放同一资源。

##### Q3：什么时候不能乱用 `std::move`？

当你后面还要继续依赖这个对象原本的值时，就不要随便 `move`。因为 move 后原对象的内容通常不再可靠。

### 面试短答

> `std::move` 本身不移动数据，它只是把一个左值转换成右值引用，目的是让编译器优先调用移动构造或移动赋值。移动语义的核心价值是转移资源所有权，避免昂贵深拷贝。move 之后原对象通常仍然有效，但值不再可靠，只适合析构、重新赋值或重新初始化。

## 类的静态成员变量

静态成员变量属于类本身，不属于某一个对象。所有对象共享同一份静态成员变量。

```cpp
class A {
public:
    static int count;
};

int A::count = 0; // 类外定义一次
```

更详细规则见：[[06 内存生命周期与静态成员#静态成员变量必须类外定义]]

## 面试速背

1. 类是封装数据和函数的类型，对象是类创建出来的实体。
2. 构造函数在对象创建时自动调用，析构函数在对象销毁时自动调用。
3. 定义对象会构造，定义指针不会构造。
4. 成员对象先于外层对象构造。
5. 多态的核心是继承、虚函数、基类指针或引用。
6. 有虚函数的基类通常要写虚析构。
7. `this` 是当前对象地址，静态成员函数没有 `this`。
