## C++ 三大特性

### 简要回答

C++ 面向对象的三大特性通常指：**封装、继承、多态**。

### 详细回答

- 封装：把数据和操作数据的函数放在类中，通过访问权限控制隐藏实现细节。
- 继承：子类复用父类已有成员，并在此基础上扩展新能力。
- 多态：同一个接口在不同对象上表现出不同行为，C++ 中最典型的是虚函数动态多态。

### 1.封装（Encapsulation）

封装是指把**数据**和**操作数据的方法**包装在类里，通过**访问权限（public、private、protected）**来控制对外的暴露。

好处是**提高安全性**，把实现**细节藏起来**，别人只能用你提供的接口，而**不能直接改内部数据**。

### [#](https://notes.kamacoder.com/cpp/cpp-three-features.html#_2%E7%BB%A7%E6%89%BF-inheritance)2继承（Inheritance）

继承让**一个类（子类）拥有**另一个类（父类）**的**属性和行为，可以**在原有功能的基础上做改进和拓展**。

**有了继承，代码可以复用**，比如定义一个Animal类，再派生出Dog、Cat等具体动物类，不用重复写代码。

### [#](https://notes.kamacoder.com/cpp/cpp-three-features.html#_3%E5%A4%9A%E6%80%81-polymorphism)3多态（Polymorphism）

多态指的是“**同一种接口，不同的行为**”。 主要有两种：

**编译时多态**（函数重载、运算符重载）**运行时多态**（虚函数+继承）

比如写了一个 speak() 接口，猫、狗调用它表现都不一样，这就是多态的威力。

其中编译时多态又叫**静态多态**，指的是**在编译阶段就确定了函数调用的绑定关系**。

典型方式有两个：函数重载和运算符重载

运行时多态又叫**动态多态**，指的是**在程序运行时根据对象的实际类型来决定调用哪个函数**。

原理是通过**重写父类虚函数**，生成**虚函数表和虚函数指针**，通过**父类**引用指向**不同的子类对象**选取**不同的虚函数表**进而实现多态。


### 代码示例

```cpp
class Animal {
public:
    virtual void speak() {
        cout << "animal" << endl;
    }
};

class Dog : public Animal {
public:
    void speak() override {
        cout << "dog" << endl;
    }
};

Animal* p = new Dog();
p->speak(); // dog
```

### 知识拓展

- 封装解决“数据怎么保护”的问题。
- 继承解决“代码怎么复用和扩展”的问题。
- 多态解决“接口统一但行为不同”的问题。

## struct 和 class 的区别

### 简要回答

在 C++ 中，`struct` 和 `class` 都可以定义类。核心区别是**默认访问权限**和**默认继承权限**不同：`struct` 默认是 `public`，`class` 默认是 `private`。

### 简记

结构体默认开门，也就是 `public`；类默认关门，也就是 `private`。功能基本都能用，习惯决定用法。

### 详细回答

C++ 为了兼容 C 语言保留了 `struct` 关键字，并且扩展了它的能力。

在 C 语言中，`struct` 只能包含成员变量，不能包含成员函数；在 C++ 中，`struct` 类似于 `class`，既可以包含成员变量，也可以包含成员函数、构造函数、析构函数、访问控制等。

| 对比点 | struct | class |
|---|---|---|
| 默认成员权限 | `public` | `private` |
| 默认继承权限 | `public` | `private` |
| 常见使用习惯 | 数据聚合、简单结构 | 有封装、有行为的对象 |

### 代码示例

```cpp
#include <iostream>
#include <string>
using namespace std;

struct Point {
    int x; // 默认 public
    int y;

    void print() {
        cout << "Point: (" << x << ", " << y << ")" << endl;
    }
};

class Person {
    string name; // 默认 private
    int age;

public:
    Person(string n, int a) {
        name = n;
        age = a;
    }

    void introduce() {
        cout << "My name is " << name << ", age " << age << endl;
    }
};

int main() {
    Point p;
    p.x = 3;
    p.y = 4;
    p.print();

    Person someone("Tom", 25);
    // someone.name = "Jerry"; // 错，name 默认是 private
    someone.introduce();

    return 0;
}
```

### 面试表达

如果只是语法层面，它们能力几乎一样；如果从工程习惯看，`struct` 更偏数据结构，`class` 更偏封装对象。

### 知识拓展：什么是 POD

POD 是 Plain Old Data，可以理解成“普通老实的数据类型”。它主要负责存数据，不带复杂对象行为，适合用来描述简单、可预测的内存布局。

典型特点：

- 没有虚函数。
- 没有继承。
- 成员通常都是公有的简单数据。
- 没有用户自定义构造函数、析构函数、拷贝构造函数、赋值运算符。
- 内存布局连续、可预测，适合和 C 接口、网络报文、二进制数据结构打交道。

```cpp
struct Point {
    int x;
    int y;
};
```

上面这种就是典型的简单数据结构。

```cpp
struct FancyPoint {
    int x;
    int y;

    FancyPoint() {
        x = 0;
        y = 0;
    }
};
```

这个就不是传统意义上的 POD 风格，因为它有用户自定义构造函数。

### 面试官可能追问

#### struct 默认是 public，那能在 struct 中加 private 吗？

可以。虽然 `struct` 默认是 `public`，但也可以显式写 `private` 或 `protected` 控制成员访问权限。`struct` 和 `class` 在语法能力上几乎等价，只是默认权限不同。

```cpp
struct User {
private:
    int password;

public:
    int id;
};
```

#### 默认继承权限影响大吗？

有影响。`struct` 继承时如果不写继承权限，默认是 `public`；`class` 继承时如果不写，默认是 `private`。因此工程里建议继承时明确写出 `public`、`protected` 或 `private`，不要依赖默认行为。

```cpp
#include <iostream>
using namespace std;

struct Base {
    void sayHello() {
        cout << "Hello from Base" << endl;
    }
};

struct DerivedStruct : Base {
    void greet() {
        sayHello(); // 类内可访问
    }
};

class DerivedClass : Base {
public:
    void greet() {
        sayHello(); // 类内可访问
    }
};

int main() {
    DerivedStruct ds;
    ds.sayHello(); // 对，struct 默认 public 继承

    DerivedClass dc;
    // dc.sayHello(); // 错，class 默认 private 继承，外部不能访问 Base 接口

    dc.greet(); // 对，内部访问没有问题
    return 0;
}
```

#### class 可以用于定义模板函数，而 struct 不行吗？

这个说法不准确。`struct` 和 `class` 都可以作为模板类型参数，也都可以定义成类模板。

```cpp
template <typename T>
struct BoxByStruct {
    T value;
};

template <typename T>
class BoxByClass {
    T value;
};
```

容易混淆的是：模板类型参数可以写 `typename T`，也可以写 `class T`。

```cpp
template <typename T>
void func1(T value) {}

template <class T>
void func2(T value) {}
```

这里的 `class T` 只是表示“类型参数”，不是说只能传 `class` 定义的类型，也不是说 `struct` 不能用模板。

## struct 和 union 的区别

### 简要回答

在 C++ 中，`struct` 和 `union` 都是用户自定义类型。`struct` 的所有成员可以同时存在，并且各自占用独立内存空间；`union` 的所有成员共享同一块内存空间，同一时间通常只保存一个成员的有效值。

C++11 之后，`union` 可以包含非 POD 类型成员，也可以定义成员函数和特殊成员函数，但需要开发者手动管理活跃成员的生命周期。

### 详细回答

### struct 的特性

- 默认成员权限和默认继承权限都是 `public`。
- 支持成员函数、构造函数、析构函数。
- 支持继承和多态。
- 内存布局和 C 结构体类似，但如果引入虚函数、继承等 C++ 特性，布局会更复杂。
- C++11 后支持成员默认初始化。

```cpp
struct Point {
    int x = 0;
    int y = 0;

    void print() const {
        cout << x << ", " << y << endl;
    }
};
```

### union 的特性

- **所有成员共享同一块内存。**
- `union` 的大小通常由最大成员决定，并受内存对齐影响。
- 同一时间只适合有一个活跃成员。
- **可以包含成员函数，包括构造函数和析构函数。**
- **不能继承，也不能作为基类**。
- **不能包含虚函数。**
- 不能包含引用成员。
- C++11 前通常只能包含 POD 类型成员；C++11 后可以包含非 POD 类型，但需要显式管理生命周期。

```cpp
struct S {
    int a;
    double b;
};

union U {
    int a;
    double b;
};
```

### 代码示例

```cpp
#include <iostream>
#include <new>
#include <string>

// C++ 结构体示例：struct 也可以有成员函数和构造函数
struct Student {
    std::string name;
    int age;
    double score;

    Student(const std::string& n, int a, double s)
        : name(n), age(a), score(s) {}

    void introduce() {
        std::cout << "我叫" << name
                  << "，今年" << age
                  << "岁，成绩" << score << std::endl;
    }
};

// C++11 union 示例：包含非 POD 类型，需要手动管理生命周期
union Variant {
    int i;
    double d;
    std::string s;

    Variant() : i(0) {}
    ~Variant() {}

    void setInt(int val) {
        i = val;
    }

    void setString(const std::string& str) {
        new (&s) std::string(str); // placement new
    }

    void destroyString() {
        s.~basic_string(); // 显式调用析构函数
    }
};

int main() {
    Student stu("张三", 20, 90.5);
    stu.introduce();

    Variant v;
    v.setInt(42);
    std::cout << "整数值: " << v.i << std::endl;

    v.setString("Hello");
    std::cout << "字符串值: " << v.s << std::endl;
    v.destroyString();

    std::cout << "结构体大小: " << sizeof(Student) << " 字节" << std::endl;
    std::cout << "联合体大小: " << sizeof(Variant) << " 字节" << std::endl;

    return 0;
}
```

> [!warning] 注意
> 上面代码适合用来理解 C++11 union 的基本机制，但真实工程中还应该额外记录当前活跃成员。例如从 `int` 切换到 `string` 前后，要知道当前是否有需要析构的非 POD 成员。否则容易出现重复析构、忘记析构或覆盖未销毁对象的问题。

### 关键差异

| 对比点 | struct | union |
|---|---|---|
| 内存模型 | 每个成员独立存储 | 所有成员共享存储 |
| 同时有效成员 | 多个成员可同时有效 | 通常只有一个活跃成员 |
| 大小 | 大致为所有成员大小加对齐 | 大致为最大成员大小加对齐 |
| 默认访问权限 | `public` | `public` |
| 访问控制 | 可写 `public/private/protected` | 可写 `public/private/protected` |
| 继承 | 支持 | 不支持 |
| 多态 | 支持虚函数和多态 | 不支持虚函数 |
| 生命周期管理 | 普通对象模型 | 非 POD 成员需要手动管理活跃成员 |

### 适用场景

#### C++ struct 推荐场景

1. 数据传输对象 DTO：在系统间传递数据。
2. 接口简化：作为多个返回值的容器。
3. 内存布局控制：与硬件、网络协议、C 接口交互。
4. 策略模式：作为轻量级策略对象。
5. 模板元编程：作为编译期计算或 traits 工具。

#### C++ union 推荐场景

1. 变体类型：用一块内存表示多种可能类型。
2. 内存优化：嵌入式或高性能场景下节省空间。
3. 二进制协议解析：解释网络数据包或硬件数据。
4. 底层表示转换：查看同一块内存的不同表示。

### C++11 后 union 为什么能包含非 POD 类型

C++11 放宽了限制，让 `union` 可以包含 `std::string` 这类非 POD 类型，目的是增加表达能力。

但代价是：`union` 自己不知道当前活跃成员是谁，也不能自动判断该调用哪个构造函数或析构函数，所以开发者必须手动管理生命周期。

典型要求：

- 使用 placement new 初始化非 POD 成员。
- 显式调用析构函数销毁非 POD 成员。
- 用额外标记字段记录当前活跃成员。
- 拷贝、移动、销毁时都要根据活跃成员分别处理。

### 如何安全使用包含 std::string 的 union

思路是给 `union` 外面包一层结构体，用枚举记录当前活跃成员。

```cpp
#include <new>
#include <string>
using namespace std;

struct Value {
    enum class Type {
        Int,
        String
    } type;

    union Data {
        int i;
        string s;

        Data() {}
        ~Data() {}
    } data;

    Value(int value) : type(Type::Int) {
        data.i = value;
    }

    Value(const string& value) : type(Type::String) {
        new (&data.s) string(value); // placement new
    }

    ~Value() {
        if (type == Type::String) {
            data.s.~basic_string(); // 显式析构
        }
    }
};
```

### 更推荐的现代写法

C++17 之后，如果只是想表达“多个类型中选一个”，优先考虑 `std::variant`。

```cpp
#include <variant>
#include <string>

std::variant<int, std::string> value;
value = 10;
value = std::string("hello");
```

`std::variant` 会帮你管理当前活跃类型和生命周期，比手写 `union` 安全得多。

### 面试官可能追问

#### Q1：C++ 中结构体和类有什么区别？

见 [[#struct 和 class 的区别]]。核心是默认成员权限和默认继承权限不同：`struct` 默认 `public`，`class` 默认 `private`。工程习惯上，`struct` 常用于数据聚合，`class` 常用于复杂抽象。

#### Q2：为什么 C++11 允许 union 包含非 POD 类型？

为了增强灵活性，让一块共享内存可以承载更复杂的对象。但因为 `union` 不记录当前活跃成员，也无法自动调用正确的构造和析构函数，所以非 POD 成员需要手动生命周期管理。

#### Q3：如何安全地使用包含 std::string 的 union？

需要提供构造函数初始化活跃成员，在析构函数中根据标记字段正确销毁非 POD 成员，并在拷贝和移动操作中处理当前活跃成员。实际工程中，如果没有极端内存优化需求，优先使用 `std::variant`。

## sizeof 和 strlen 的区别

### 简要回答

`sizeof` 是运算符，求对象或类型占用的字节数；`strlen` 是函数，求 C 字符串中 `\0` 前的字符个数。

### 易错点

```cpp
char arr[] = "abc";
cout << sizeof(arr) << endl; // 4，包含 '\0'
cout << strlen(arr) << endl; // 3，不包含 '\0'

const char* p = "abc";
cout << sizeof(p) << endl;   // 指针大小，64 位通常是 8
cout << strlen(p) << endl;   // 3
```

### 面试官可能追问

#### Q1：sizeof 对指针和数组有什么区别？

这是最高频追问。

```cpp
char arr[] = "hello";
const char* ptr = "hello";

cout << sizeof(arr) << endl; // 6
cout << sizeof(ptr) << endl; // 8，64 位系统通常是 8
```

核心原因：`sizeof` 直接看类型信息。`arr` 的类型是 `char[6]`，所以 `sizeof(arr)` 得到整个数组大小；`ptr` 的类型是 `const char*`，所以 `sizeof(ptr)` 得到指针本身大小，和字符串长度无关。

#### Q2：数组作为函数参数传递时，sizeof 还准确吗？

不准确。数组作为函数参数时会退化为指针。

```cpp
void foo(char arr[]) {
    cout << sizeof(arr) << endl; // 8，等价于 sizeof(char*)
}

int main() {
    char s[] = "hello";

    cout << sizeof(s) << endl; // 6
    foo(s);                    // 传参后退化为指针
}
```

`void foo(char arr[])` 里的 `arr` 本质上等价于 `char* arr`。如果函数内部需要知道数组长度，要额外传入 `len` 参数，或者使用能保留长度信息的容器和引用写法。

```cpp
void foo(const char* s, size_t len) {
    // 使用 len
}
```

#### Q3：strlen 的时间复杂度是多少？能优化吗？

`strlen` 是 `O(n)`，它会从字符串开头一直遍历到 `\0`。

```cpp
size_t my_strlen(const char* s) {
    const char* p = s;
    while (*p != '\0') {
        p++;
    }
    return p - s;
}
```

如果在循环中反复调用 `strlen`，会重复遍历字符串，容易退化为低效写法。

```cpp
// 差写法：每次循环都重新遍历
for (int i = 0; i < strlen(s); i++) {
    // ...
}

// 好写法：提前缓存长度
size_t len = strlen(s);
for (int i = 0; i < len; i++) {
    // ...
}
```

#### Q4：sizeof 的结果一定是编译期常量吗？

在标准 C++ 中，`sizeof` 的结果是编译期常量。

C99 引入了变长数组 VLA，在 C 语言中某些 `sizeof` 可能运行时求值。

```c
void foo(int n) {
    int arr[n];                  // C99 VLA，不是标准 C++
    printf("%zu\n", sizeof(arr)); // C 中可能运行时求值
}
```

C++ 标准不支持 VLA，所以在标准 C++ 中，`sizeof` 的结果可以视为编译期常量。

## 浮点数比较方法

### 简要回答

浮点数不要直接用 `==` 比较，通常判断二者差值是否小于一个很小的误差 `eps`。

```cpp
double a = 0.1 + 0.2;
double b = 0.3;
const double eps = 1e-9;

if (fabs(a - b) < eps) {
    cout << "equal" << endl;
}
```

### 原因

很多十进制小数不能被二进制浮点数精确表示，运算后会产生微小误差。

### 绝对误差比较

绝对误差适合数值范围比较固定、误差尺度已知的场景。

```cpp
#include <cmath>

bool equal_abs(double a, double b) {
    const double eps = 1e-9;
    return std::fabs(a - b) < eps;
}
```

推荐场景：

1. 物理测量数据：传感器读数，已知测量精度。
2. 固定范围数值：颜色值 `0~1`、标准化数据。
3. 游戏开发：位置坐标、物理模拟。
4. 用户界面：像素坐标、动画参数。

### 相对误差比较

相对误差适合数值规模变化很大的场景。它关注误差相对于数值本身的比例。

```cpp
#include <algorithm>
#include <cmath>

bool equal_rel(double a, double b) {
    const double eps = 1e-9;
    return std::fabs(a - b) <= eps * std::max(std::fabs(a), std::fabs(b));
}
```

推荐场景：

1. 科学计算：数值分析、模拟计算。
2. 工程计算：结构分析、流体力学。
3. 金融计算：利率、汇率计算。
4. 统计分析：大数据处理。

### 更稳妥的综合写法

实际工程中常把绝对误差和相对误差结合起来，避免接近 0 时相对误差失效。

```cpp
#include <algorithm>
#include <cmath>

bool nearly_equal(double a, double b) {
    const double abs_eps = 1e-12;
    const double rel_eps = 1e-9;

    double diff = std::fabs(a - b);
    if (diff <= abs_eps) {
        return true;
    }

    return diff <= rel_eps * std::max(std::fabs(a), std::fabs(b));
}
```

### 面试官可能追问

#### Q1：为什么 0.1 + 0.2 不等于 0.3？

因为 `0.1` 和 `0.2` 在二进制中是无限循环小数，无法用有限精度的浮点数精确表示。计算过程中会发生舍入误差，误差累积后导致结果和 `0.3` 有微小差异。

```cpp
cout << (0.1 + 0.2 == 0.3) << endl; // 通常是 false
```

#### Q2：什么时候可以直接用 == 比较浮点数？

多数计算结果不推荐直接用 `==`。但下面场景可以考虑：

1. 比较整数值的浮点数表示，且范围没有超过精确整数表示能力。
2. 检查某些明确赋值的特殊值，如刚刚赋值为 `0.0` 或 `1.0`。
3. 检查无穷大或 NaN 时，但更推荐用 `std::isinf`、`std::isnan`。
4. 确认位模式完全相同的底层比较场景。

#### Q3：如何处理 NaN 和无穷大？

使用标准库函数：

```cpp
#include <cmath>

std::isnan(x);    // 是否为 NaN
std::isinf(x);    // 是否为无穷大
std::isfinite(x); // 是否为有限数
```

`NaN` 和任何值比较都返回 `false`，包括它自己。

```cpp
double x = std::nan("");
cout << (x == x) << endl; // false
```

## C++ 四种类型转换

### 简要回答

C++ 引入了四种命名类型转换运算符，用来替代 C 风格强制转换，让转换意图更清晰、更安全、更容易查错。

1. `static_cast`
   用于编译期已知、相对安全的转换，如基础类型转换、`void*` 转具体指针、继承体系中的向上转换等。

2. `dynamic_cast`
   用于多态继承体系中的安全向下转换或交叉转换，依赖 RTTI。指针转换失败返回 `nullptr`，引用转换失败抛出 `std::bad_cast`。

3. `const_cast`
   用于增加或移除 `const` / `volatile` 属性。

4. `reinterpret_cast`
   用于底层的比特级重新解释转换，高度依赖平台，不安全，通常只在底层系统、硬件、序列化等场景谨慎使用。

| 转换 | 常见用途 | 风险 |
|---|---|---|
| `static_cast` | 基本类型转换、父子类指针的安全方向转换 | 中等 |
| `dynamic_cast` | 多态类型运行时向下转型 | 失败会返回 `nullptr` 或抛异常 |
| `const_cast` | 去掉或添加 `const` / `volatile` | 修改原本 const 对象是未定义行为 |
| `reinterpret_cast` | 按二进制重新解释类型 | 风险最高 |

### 面试表达

能用 `static_cast` 就不要用 C 风格强转；只有涉及多态运行时检查时才考虑 `dynamic_cast`；`reinterpret_cast` 通常说明代码已经非常底层，要特别谨慎。

### 为什么不用 C 风格转换

C 风格转换写法如下：

```cpp
double d = (double)x;
```

它功能太笼统，可能在背后执行 `static_cast`、`const_cast`、`reinterpret_cast` 等多种转换。读代码的人很难马上判断程序员到底想做什么，编译器也更难帮你检查风险。

C++ 四种转换更像四把专用工具：每种转换表达一种明确意图。

### 1. static_cast

`static_cast` 用途最广，用于编译器认可的、编译期可以判断的转换。

常见场景：

- 基础数据类型转换，如 `int` 转 `double`。
- 枚举和整数之间转换。
- 有转换构造函数或转换运算符的类类型转换。
- `void*` 和具体类型指针之间转换。
- 继承体系中的向上转换。
- 继承体系中的向下转换，但不做运行时检查，不安全。

```cpp
int i = 42;
double d = static_cast<double>(i);

void* pv = &i;
int* pi = static_cast<int*>(pv);
```

### 2. dynamic_cast

`dynamic_cast` 专门用于多态继承体系，也就是基类至少有一个虚函数。

它主要用于：

- 向下转换：基类指针或引用转派生类。
- 交叉转换：多继承中从一个基类视角转到另一个基类视角。

它的优势是安全：运行时检查对象真实类型。

```cpp
class Base {
public:
    virtual ~Base() = default;
};

class Derived : public Base {};

Base* p = new Derived();
Derived* d = dynamic_cast<Derived*>(p);

if (d != nullptr) {
    cout << "cast success" << endl;
}
```

失败规则：

- 指针转换失败：返回 `nullptr`。
- 引用转换失败：抛出 `std::bad_cast`。

缺点是有运行时检查，会有一定开销。

### 3. const_cast

`const_cast` 的功能很单一：修改类型的 `const` 或 `volatile` 属性。

它常用于适配旧接口，比如某个老 API 参数写成了非 `const`，但你知道它实际上不会修改数据。

```cpp
int k = 100;
const int* pk = &k;

int* p = const_cast<int*>(pk);
*p = 200; // 安全，因为 k 本身不是 const
```

但如果对象本身就是 `const`，去掉 `const` 后再修改是未定义行为。

```cpp
const int j = 100;
int* pj = const_cast<int*>(&j);
// *pj = 200; // 未定义行为
```

### 4. reinterpret_cast

`reinterpret_cast` 是最低层、最危险的转换。它基本不做类型语义检查，只是把同一串比特位按另一种类型解释。

常见场景：

- 指针和整数之间转换，比如转成 `uintptr_t`。
- 不相关指针类型之间转换。
- 函数指针之间的底层转换。
- 和硬件、二进制协议、底层内存布局打交道。

```cpp
int x = 42;
int* pi = &x;

auto addr = reinterpret_cast<std::uintptr_t>(pi);
cout << addr << endl;

double* pd = reinterpret_cast<double*>(pi); // 危险
// cout << *pd << endl; // 结果无意义，甚至可能崩溃
```

### 综合代码示例

```cpp
#include <cstdint>
#include <iostream>
using namespace std;

class Base {
public:
    virtual ~Base() = default;
};

class Derived : public Base {};

int main() {
    int i = 42;

    double d = static_cast<double>(i);
    void* pv = &i;
    int* pi = static_cast<int*>(pv);

    Base* base_ptr = new Derived();
    Derived* derived_ptr = dynamic_cast<Derived*>(base_ptr);
    if (derived_ptr) {
        cout << "Downcast succeeded!" << endl;
    }

    Base* base_ptr2 = new Base();
    Derived* derived_ptr2 = dynamic_cast<Derived*>(base_ptr2);
    if (derived_ptr2 == nullptr) {
        cout << "Downcast failed! Returns nullptr." << endl;
    }

    int k = 100;
    const int* pk = &k;
    int* pk_mutable = const_cast<int*>(pk);
    *pk_mutable = 200;

    auto addr = reinterpret_cast<std::uintptr_t>(pi);
    cout << "Address of pi: " << addr << endl;

    double* pd = reinterpret_cast<double*>(pi); // 危险，只演示，不建议解引用
    (void)pd;

    delete base_ptr;
    delete base_ptr2;
    return 0;
}
```

### 面试官可能追问

#### Q1：继承体系中，static_cast 和 dynamic_cast 用于向下转换有什么区别？

核心区别是安全性和开销。

`static_cast` 在编译期完成，不做运行时类型检查。它假设程序员知道转换是安全的。如果基类指针实际并不指向目标派生类对象，转换后继续访问会导致未定义行为。

`dynamic_cast` 在运行期利用 RTTI 检查对象真实类型。转换失败时，指针返回 `nullptr`，引用抛出 `std::bad_cast`。它更安全，但有运行时开销。

#### Q2：能否用 const_cast 修改一个本身声明为 const 的常量？

不能。这样做是未定义行为。

`const_cast` 的相对合理用途是：对象本身不是 `const`，只是通过 `const` 指针或引用传入，此时去掉 `const` 修改原对象是可以的。

如果对象本身就是 `const int x = 10;`，强行去掉 `const` 后修改，行为未定义，可能崩溃，也可能看似成功但结果不可依赖。

#### Q3：reinterpret_cast 和 static_cast 处理指针转换时有什么本质区别？

本质区别是：`static_cast` 可能根据类型关系做必要的指针调整，`reinterpret_cast` 不做这种语义调整。

在类层次结构中，尤其是多重继承时，基类子对象地址和完整派生类对象地址可能不同。`static_cast` 知道类型关系，可能调整指针值。

`reinterpret_cast` 只是把原指针的比特位原封不动地解释成另一种指针类型，不关心类型是否相关，也不保证转换后的指针有效。
