## 用户程序到可执行程序经历什么

### 简要回答

C/C++ 程序通常经历预处理、编译、汇编、链接，最后生成可执行文件。

### 详细回答

1. 预处理：处理宏、头文件、条件编译。
2. 编译：生成汇编代码。
3. 汇编：生成目标文件。
4. 链接：把目标文件和库组合成可执行程序。

### GCC 示例

```bash
gcc -E main.c -o main.i   # 预处理
gcc -S main.i -o main.s   # 编译成汇编
gcc -c main.s -o main.o   # 汇编成目标文件
gcc main.o -o main        # 链接成可执行程序
```

### 面试表达

> 从源代码到可执行程序不是一步完成的。预处理处理宏和头文件，编译生成汇编，汇编生成目标文件，链接把多个目标文件和库合成最终可执行文件。

## 硬链接和软链接有什么区别

### 简要回答

硬链接指向同一个 inode，软链接是一个保存路径的特殊文件。

### 对比表

| 对比点 | 硬链接 | 软链接 |
|---|---|---|
| 指向 | 同一个 inode | 目标路径 |
| 跨文件系统 | 通常不行 | 可以 |
| 指向目录 | 通常不允许 | 可以 |
| 原文件删除 | 只要链接数不为 0 数据还在 | 可能变成悬空链接 |

### 命令示例

```bash
ln source.txt hard_link.txt
ln -s source.txt soft_link.txt
```

### 面试表达

> 硬链接更像给同一个文件数据增加一个目录入口，软链接更像快捷方式。删除原文件后，硬链接仍然能访问数据；软链接可能失效。

## inode 是什么

### 简要回答

inode 是文件系统中描述文件元信息的数据结构。

### 详细回答

inode 里通常保存：

- 文件类型
- 权限
- 所有者
- 文件大小
- 时间戳
- 数据块位置
- 链接计数

注意：文件名不在 inode 里，文件名通常保存在目录项中。

## 文件系统是什么

### 简要回答

文件系统是操作系统管理磁盘文件和目录的数据结构与规则集合。

### 详细回答

文件系统负责：

- 文件创建、删除、读写。
- 目录管理。
- 文件权限。
- 空闲空间管理。
- 文件名到 inode 或元数据的映射。

## 缓存一致性是什么

### 简要回答

缓存一致性是指多个缓存副本和底层数据之间要保持一致，避免读到旧数据。

### 面试表达

> 缓存能提高性能，但会引入一致性问题。操作系统、CPU、多级缓存、数据库缓存里都会遇到类似问题，核心都是“什么时候更新、什么时候失效、谁拥有最新数据”。

## 崩溃恢复是什么

### 简要回答

崩溃恢复是系统在异常断电或崩溃后，尽量恢复到一致状态的机制。

### 详细回答

文件系统和数据库常通过日志、检查点、写前日志等机制恢复。核心思想是：真正修改数据前先记录操作意图，崩溃后根据日志重做或回滚。
