## MVCC 是什么

### 简要回答

MVCC 是多版本并发控制，通过保存数据的多个版本，让读写并发时减少锁冲突。

### 面试表达

> MVCC 的核心是读操作可以读到某个历史版本，而不是一定要等待写锁释放。这样能提高并发性能，常和 undo log、Read View 这些机制配合。

### 详细回答

MVCC 主要解决并发读写问题，让读操作不用阻塞写操作，写操作也不用阻塞普通一致性读。InnoDB 中通常依赖：

- undo log：保存旧版本数据。
- Read View：判断某个版本对当前事务是否可见。
- 隐藏字段：如事务 ID、回滚指针。

在可重复读隔离级别下，事务开始后看到的是一个相对稳定的数据快照；在读已提交下，通常每次查询会生成新的 Read View。

## 数据库锁有哪些

### 简要回答

按粒度有表锁、行锁；按思想有悲观锁、乐观锁；InnoDB 里还常见间隙锁、临键锁。

### 详细回答

- 表锁：锁整张表，开销小但并发低。
- 行锁：锁具体行，并发高但管理成本高。
- 间隙锁：锁索引记录之间的范围。
- 临键锁：行锁 + 间隙锁。

### 其他分类

- 共享锁：读锁，多个事务可以同时持有。
- 排他锁：写锁，和其他读写锁通常互斥。
- 意向锁：表级锁，用来表示事务接下来可能要锁某些行。

## 乐观锁和悲观锁有什么区别

### 简要回答

悲观锁认为冲突经常发生，先加锁再操作；乐观锁认为冲突较少，提交时再检查版本。

### 示例

#### 悲观锁

悲观锁的思路是“我觉得会冲突，所以先锁住再操作”。MySQL 里常见写法是 `SELECT ... FOR UPDATE`。

```sql
-- 开启事务，后续语句要么一起提交，要么一起回滚
BEGIN;

-- 查询 id = 1 的商品，并给这行数据加排他锁
-- 其他事务想修改这行时需要等待，直到当前事务提交或回滚
SELECT stock FROM product WHERE id = 1 FOR UPDATE;

-- 扣减库存
UPDATE product SET stock = stock - 1 WHERE id = 1;

-- 提交事务，释放锁
COMMIT;
```

#### 乐观锁

乐观锁的思路是“先不加锁，提交时检查数据有没有被别人改过”。常用版本号 `version` 或时间戳。

```sql
-- 更新时带上旧 version，只有 version 没变才说明中间没人修改
UPDATE product
SET stock = stock - 1,
    version = version + 1
WHERE id = 1
  AND version = 3;
```

| 对比 | 悲观锁 | 乐观锁 |
|---|---|---|
| 思想 | 先加锁再操作 | 提交时检查冲突 |
| 适合场景 | 冲突多、强一致要求高 | 冲突少、读多写少 |
| 典型写法 | `SELECT ... FOR UPDATE` | `version` 字段校验 |

## 慢查询怎么排查

### 简要回答

先看慢查询日志，再用 `EXPLAIN` 分析执行计划，重点看是否走索引、扫描行数、连接方式和排序临时表。

### 常见优化

- 建合适索引。
- 避免索引失效。
- 减少返回列和扫描行。
- 拆分复杂 SQL。
- 避免大分页。
- 优化表结构和字段类型。

## 行锁、表锁、间隙锁是什么

### 简要回答

表锁锁整张表，行锁锁具体记录，间隙锁锁索引记录之间的范围。

### 详细回答

- 表锁：粒度大，冲突多，但管理成本低。
- 行锁：粒度小，并发好，但要依赖索引定位记录。
- 间隙锁：锁住两个索引值之间的空隙，防止其他事务插入新记录导致幻读。
- 临键锁：记录锁 + 间隙锁，锁住记录本身和前面的间隙。

### 面试表达

> InnoDB 在可重复读下为了解决范围查询的幻读问题，会使用 next-key lock，也就是行锁和间隙锁的组合。
