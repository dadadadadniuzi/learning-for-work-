## C++ 内存分区，堆和栈的区别

### 简要回答

常见内存区域可以粗略分为：

- 代码段：存放程序机器指令
- 全局 / 静态区：存放全局变量、静态变量
- 常量区 / 只读区：存放常量、字符串字面量
- 栈区：存放局部变量、函数参数、调用栈信息
- 堆区：存放动态分配内存

其中面试最常问的是：**堆和栈的区别**。

- 栈：编译器自动分配和释放，适合生命周期短、大小相对确定的对象，速度快，但空间较小。
- 堆：由程序员手动申请和释放，适合生命周期长、大小动态变化的对象，空间大，但管理复杂，容易产生内存问题。

### 详细回答

#### 1. 代码区

代码区也叫文本区，存放程序编译后的机器指令。

特点：

- 通常只读
- 多个进程运行同一程序时，这部分代码可能被共享

#### 2. 全局 / 静态区

全局变量和静态变量通常放在这一块区域。

常见又可以继续细分成：

- 数据段 `data`：已初始化的全局变量、静态变量
- `BSS` 段：未初始化的全局变量、静态变量，以及初始化为 0 的全局 / 静态变量

面试里如果不想展开得太细，直接说“全局变量和静态变量在全局 / 静态存储区”就够了。

#### 3. 常量区 / 只读区

这里通常放：

- 字符串字面量
- 只读常量
- 某些编译期常量数据

这块区域一般不允许修改。

#### 4. 栈区

栈区由编译器自动管理，主要存放：

- 局部变量
- 函数参数
- 返回地址
- 调用现场等栈帧信息

特点：

- 自动分配，自动释放
- 访问速度快
- 空间相对有限
- 非常适合存放生命周期短的对象

#### 5. 堆区

堆区是动态分配内存区域。

在 C++ 里，通常通过：

- `new`
- `new[]`

申请；

通过：

- `delete`
- `delete[]`

释放。

在 C 风格里，则常用：

- `malloc`
- `calloc`
- `realloc`

以及：

- `free`

来管理。

堆空间通常更大，但管理复杂度也更高。

### 栈和堆的区别

这是面试重点。

| 对比点 | 栈 | 堆 |
|---|---|---|
| 管理方式 | 编译器自动管理 | 程序员手动管理 |
| 生命周期 | 随作用域结束自动销毁 | 直到显式释放为止 |
| 空间大小 | 相对较小 | 相对较大 |
| 分配效率 | 高 | 较低 |
| 是否易碎片化 | 基本不会 | 容易产生碎片 |
| 典型数据 | 局部变量、函数参数 | 动态对象、变长数据结构 |

### 1. 管理方式

栈由编译器自动管理，不需要手动回收。

堆需要程序员自己负责释放，所以更容易出现：

- 内存泄漏
- 野指针
- 重复释放

### 2. 空间大小

栈空间一般比较有限。

堆空间通常更大，适合存放大对象和生命周期较长的对象。

### 3. 碎片问题

栈是后进先出结构，分配和释放都非常规整，基本不会产生内存碎片。

堆因为会频繁 `new/delete`，不同大小内存块被不断申请和释放，容易产生不连续小块，也就是内存碎片。

### 4. 生长方向

在很多常见系统实现里：

- 栈通常向低地址方向增长
- 堆通常向高地址方向增长

但这属于常见实现习惯，面试里可以讲，但不建议说成所有平台绝对都这样。

### 5. 分配效率

栈效率高，是因为底层通常有专门的寄存器和入栈出栈指令支持。

堆效率低一些，是因为分配器需要维护空闲块、查找可用区域、处理碎片等。

### 线程角度再看

- 栈通常是线程私有的，每个线程有自己的调用栈。
- 堆通常是进程内共享的，多个线程都可能访问同一片堆内存。

这也是为什么：

- 栈上局部变量天然隔离性更强
- 堆上共享对象往往需要加锁或原子操作保护

### 一个更准确的小补充

严格来说，C++ 标准语境里更常说的是：

- `new/delete` 管的是 **free store（自由存储区）**
- 操作系统层面常说的是 **heap（堆）**

面试里多数时候大家会把它们混着说成“堆”，通常没问题。但如果面试官特别较真，你可以补一句：

> 严格术语上，`new/delete` 面向的是自由存储区，不过在大多数常见实现里通常就是基于堆来实现的。

### 面试官可能追问

#### Q1：平时你在项目中怎么管理内存？

比较稳的答法是：

> 现在项目里我会尽量减少手写裸 `new/delete`，优先使用 RAII、标准容器和智能指针来管理资源。只有在确实需要手动控制对象生命周期或内存布局时，才会直接处理底层内存。

#### Q2：为什么栈比堆快？

因为栈分配通常只是移动栈顶指针，硬件和编译器支持都更直接；堆分配则要经过分配器查找合适内存块并维护复杂元数据。

#### Q3：为什么堆更容易出问题？

因为它生命周期不受作用域自动约束，程序员要自己管理申请和释放，稍不注意就会出现泄漏、悬垂指针、越界或重复释放。

### 面试短答

> C++ 常见内存区域可以分成代码区、全局静态区、常量区、栈区和堆区。面试里最常问的是堆和栈：栈由编译器自动管理，适合生命周期短、大小固定或相对确定的对象，分配快但空间有限；堆由程序员手动申请和释放，适合生命周期长、大小动态变化的对象，空间大但容易出现内存泄漏、碎片和野指针问题。

## new 和 malloc 的区别是什么

### 简要回答

- `new` 是 C++ 运算符，会分配内存并调用构造函数
- `malloc` 是 C 函数，只分配原始内存，不会调用构造函数

更直白一点记：

- `new` 是对象级操作：负责“分配 + 构造”
- `malloc` 是内存级操作：只负责“分配”

### 详细回答

#### 1. 本质不同

`new` 是 C++ 语言里的运算符。

`malloc` 是 C 风格的库函数，定义在标准库头文件里。

这意味着：

- `new/delete` 是语言层能力
- `malloc/free` 是函数调用风格

#### 2. 分配内存方式不同

`new` 不需要你手动写字节数，编译器会根据类型自动计算大小。

```cpp
int* p = new int;
```

`malloc` 需要你自己手动写大小：

```cpp
int* p = (int*)malloc(sizeof(int));
```

所以 `new` 在类型层面更自然，`malloc` 更底层。

#### 3. 是否调用构造函数不同

这是最关键区别之一。

`new` 在分配完内存后，会继续调用构造函数，把对象真正构造出来。

`malloc` 只分配一块原始内存，不会调用构造函数。

```cpp
class A {
public:
    A() { std::cout << "A ctor\n"; }
};

A* p1 = new A;              // 会调用构造函数
A* p2 = (A*)malloc(sizeof(A)); // 不会调用构造函数
```

所以：

- 对普通 POD 数据，用 `malloc` 还能勉强讲通
- 对类对象，尤其是有构造析构逻辑的对象，优先用 `new`

#### 4. 分配失败时行为不同

`new` 默认分配失败不会返回 `NULL`，而是抛出 `std::bad_alloc` 异常。

`malloc` 分配失败时返回 `NULL`。

```cpp
try {
    int* p = new int[1000000000000];
} catch (const std::bad_alloc&) {
    std::cout << "new failed\n";
}
```

```cpp
int* p = (int*)malloc(sizeof(int) * huge_size);
if (p == NULL) {
    // 处理失败
}
```

#### 5. 返回类型不同

`new` 返回的是具体类型指针，类型安全更强：

```cpp
std::string* s = new std::string("hello");
```

`malloc` 返回 `void*`，在 C++ 中通常需要显式强转：

```cpp
std::string* s = (std::string*)malloc(sizeof(std::string));
```

这也是为什么 `malloc` 在 C++ 里显得更不安全、更原始。

#### 6. 是否可重载不同

`new/delete` 可以重载。

比如类可以自定义自己的 `operator new` 和 `operator delete`。

`malloc/free` 不是运算符，不能像 `new/delete` 那样重载。

#### 7. 数组支持不同

`new` 支持直接创建对象数组：

```cpp
int* arr = new int[10];
```

而 `malloc` 必须自己算总大小：

```cpp
int* arr = (int*)malloc(sizeof(int) * 10);
```

#### 8. 底层关系

面试官有时会继续追问底层。

比较稳的说法是：

- `new` 往往先调用 `operator new`
- `operator new` 底层再去申请原始内存
- 具体实现里常常会间接依赖 `malloc`
- 更底层再可能走系统调用或内存映射机制

所以你可以把常见链路理解成：

```text
new -> operator new -> malloc / 更底层分配机制 -> 构造函数
```

但不要把它背成“所有实现都绝对完全一样”，因为不同标准库和平台实现细节可能不同。

#### 9. 什么时候用哪个

| 场景 | 推荐选择 | 原因 |
|---|---|---|
| C++ 中创建对象 | `new` | 类型安全，自动构造 |
| C 风格接口或纯内存块 | `malloc` | 只关心原始内存 |
| POD 类型简单内存块 | `malloc` 可用 | 但现代 C++ 中依然更常用容器或智能指针 |
| 自定义对象生命周期 | `new` 或 `placement new` | 构造过程可控 |
| STL / RAII 环境 | `new` 更自然 | 和现代 C++ 资源管理习惯一致 |

#### 10. placement new 和 malloc 的结合

如果你真的想先用 `malloc` 拿到原始内存，再在这块内存上构造对象，可以结合 `placement new`：

```cpp
void* mem = malloc(sizeof(MyClass));
MyClass* obj = new (mem) MyClass();
```

这里：

- `malloc` 负责分配原始内存
- `placement new` 负责在该地址上构造对象

这在对象池、共享内存、自定义内存管理里比较常见。

### 面试官可能追问

#### Q1：new 和 malloc 的底层实现有什么区别？

`new` 通常会先走 `operator new` 申请原始内存，然后再调用构造函数；`malloc` 只负责分配原始内存，不做对象构造。更底层具体是否经过 `malloc`、`mmap` 或其他机制，要看实现。

#### Q2：能否用 malloc 分配对象后手动调用构造函数？

可以，但这时通常要配合 `placement new`。

```cpp
void* mem = malloc(sizeof(MyClass));
MyClass* obj = new (mem) MyClass();
```

#### Q3：new[] 和 new 有什么区别？为什么 delete[] 不能用 delete 替代？

`new[]` 创建的是对象数组，需要记录元素个数，以便后续析构时逐个调用析构函数。

`delete` 只面向单个对象；`delete[]` 面向对象数组。不能混用，否则析构逻辑和释放逻辑都可能出错。

### 面试短答

> `new` 和 `malloc` 的核心区别在于：`new` 是 C++ 的对象级操作，负责“分配内存 + 调用构造函数”；`malloc` 是 C 的内存级操作，只负责分配一块原始内存，不负责对象构造。`new` 自动计算类型大小、失败时抛异常、返回具体类型指针；`malloc` 需要手动写 `sizeof`、失败返回 `NULL`、返回 `void*`。在现代 C++ 里，创建对象通常优先用 `new`，而不是 `malloc`。

## free 和 delete 的区别是什么

### 简要回答

- `delete` 会先调用析构函数，再释放内存
- `free` 只释放内存，不调用析构函数

更直白一点记：

- `free` 是 C 的释放函数，只负责“还内存”
- `delete` 是 C++ 的释放操作符，负责“析构 + 还内存”

### 详细回答

#### 1. free 做了什么

`free` 配合：

- `malloc`
- `calloc`
- `realloc`

一起使用。

它的核心职责很简单：

- 把之前申请的那块原始内存交还给分配器

但它**不会关心这块内存里是不是对象**，也不会调用析构函数。

所以如果这块内存里放的是一个带资源管理逻辑的 C++ 对象，`free` 并不会帮你做资源清理。

#### 2. delete 做了什么

`delete` 配合 `new` 使用。

当你 `new` 一个对象时，通常发生的是：

1. 申请原始内存
2. 调用构造函数把对象构造出来

那么 `delete` 对应地会做两件事：

1. 先调用析构函数
2. 再释放这块内存

所以它适合管理真正的 C++ 对象生命周期。

#### 3. 为什么 free 不能替代 delete

因为 `free` 不会调用析构函数。

如果一个类在析构函数里做了重要资源清理，比如：

- `delete` 成员指针
- 关闭文件
- 释放锁
- 关闭 socket

那么你用 `free` 释放它时，这些逻辑都不会执行。

这就可能导致：

- 资源泄漏
- 状态不完整清理
- 行为未定义

#### 4. delete[] 和 delete 的区别

如果你分配的是对象数组：

```cpp
Point* arr = new Point[3];
```

那么释放时必须用：

```cpp
delete[] arr;
```

原因是：

- `new[]` 通常需要记录数组元素个数
- `delete[]` 才能逐个调用每个元素的析构函数

如果误写成：

```cpp
delete arr;
```

就可能只析构一个元素，其他元素析构逻辑丢失，造成资源泄漏或未定义行为。

#### 5. 代码示例

```cpp
#include <iostream>
using namespace std;

class Point {
public:
    Point() {
        cout << "构造" << endl;
    }

    ~Point() {
        cout << "析构" << endl;
    }
};

int main() {
    Point* arr = new Point[3];
    delete[] arr;
    return 0;
}
```

这个例子里：

- `new Point[3]` 会调用 3 次构造函数
- `delete[] arr` 会调用 3 次析构函数

#### 6. delete 一个 nullptr 会怎样

这是一个常见追问。

对 `nullptr` 调用 `delete` 是安全的，不会报错，也不会抛异常。

```cpp
int* p = nullptr;
delete p; // 安全
```

所以释放前是否专门判空，一般不是必须。

#### 7. new 和 free 混用会怎样

这是严重错误，属于未定义行为。

例如：

```cpp
MyClass* p = new MyClass();
free(p); // 错
```

或者：

```cpp
int* p = (int*)malloc(sizeof(int));
delete p; // 错
```

这样做可能：

- 直接崩溃
- 表面能跑，但资源偷偷泄漏
- 把堆管理状态破坏掉

#### 8. 底层实现怎么理解

`free` 的本质是把内存块交还给底层分配器。

在常见实现中，分配器通常会在内存块附近维护元数据，比如大小、状态、是否可合并等。调用 `free` 时，会标记这块空间可重用，并尝试和相邻空闲块合并，以减少碎片。

`delete` 则是在这之前多做一步：

- 调析构函数
- 然后再调用底层释放逻辑

所以面试里比较稳的说法是：

> `delete` 本质上是“析构 + 释放”，而 `free` 只是“释放”。

### 面试官可能追问

#### Q1：为什么要分 delete 和 delete[]？

因为数组对象需要逐个析构。`new[]` 对应的是一组对象，释放时必须知道有多少个元素，并逐个调用析构函数，所以要用 `delete[]`。

#### Q2：如果 delete 一个 nullptr 会怎样？

安全，不会出错。

#### Q3：new 和 free 混着用会怎样？

未定义行为，严重时会崩溃，轻则资源泄漏，重则破坏堆管理状态。

#### Q4：delete 的底层一定会调用 free 吗？

不一定必须是字面意义上的 `free`，但它一定会调用对应分配体系里的释放逻辑。更准确的说法是：`delete` 会先析构，再调用与 `operator new` 配套的释放机制。

### 面试短答

> `free` 是 C 的函数，只负责释放原始内存，不会调用析构函数；`delete` 是 C++ 的操作符，配套 `new` 使用，会先调用析构函数，再释放内存。  
> 对象数组必须 `new[]` 配 `delete[]`，否则析构不完整。`new/free` 或 `malloc/delete` 混用都属于未定义行为。

## placement new 的作用

### 简要回答

`placement new` 的作用是在一块已经分配好的原始内存上“原地构造对象”，不负责申请新内存。

它只负责调用构造函数，把对象放到指定地址上，适合需要精确控制对象内存位置和生命周期的场景，比如内存池、对象池、共享内存、`optional/variant` 一类底层组件实现。

### 详细回答

#### 1. 普通 new 做了什么

普通 `new` 一般做两件事：

1. 分配一块足够大的原始内存
2. 在这块内存上调用构造函数

```cpp
MyClass* obj = new MyClass();
```

它既申请内存，也把对象构造出来。

#### 2. placement new 做了什么

`placement new` 只做第二件事：

- **不分配内存**
- **只在你给定的地址上构造对象**

语法是：

```cpp
new (ptr) Type(args...);
```

其中：

- `ptr`：一块已经准备好的原始内存地址
- `Type`：要构造的对象类型
- `args...`：传给构造函数的参数

#### 3. 工作原理

底层有一个专门支持它的 `operator new` 重载：

```cpp
void* operator new(std::size_t, void* ptr) noexcept;
```

这个版本非常特殊，它不会去申请新内存，而是直接把你传进来的 `ptr` 返回回去，然后编译器在那块地址上调用构造函数。

所以你可以把它理解成：

> “这块内存我已经准备好了，你只管在这里把对象生出来。”

### 代码示例

```cpp
#include <iostream>
using namespace std;

class MyClass {
public:
    MyClass(int x) : value(x) {
        cout << "构造: " << value << endl;
    }

    ~MyClass() {
        cout << "析构: " << value << endl;
    }

private:
    int value;
};

int main() {
    alignas(MyClass) char buffer[sizeof(MyClass)];

    MyClass* obj = new (buffer) MyClass(42); // placement new

    obj->~MyClass(); // 显式析构

    return 0;
}
```

这个例子里：

- `buffer` 提供原始内存
- `placement new` 只负责在 `buffer` 上构造对象
- 使用结束后，必须手动调用析构函数

### 为什么不能直接 delete

这是 placement new 面试里最关键的坑点。

因为这块内存不是通过普通 `new` 分配出来的，所以你不能直接：

```cpp
delete obj; // 错
```

原因是标准 `delete` 会尝试：

1. 调析构函数
2. 再把内存交还给默认分配器

但 placement new 的那块内存可能：

- 在栈上
- 在静态区
- 在对象池里
- 在共享内存里

它根本不一定属于默认堆分配器，所以直接 `delete` 是未定义行为。

### 正确释放方式

placement new 对象的正确销毁分两步：

1. 显式调用析构函数

```cpp
obj->~MyClass();
```

2. 再按原始内存的来源，用匹配方式释放那块内存

- 如果原始内存在栈上：什么都不用做，作用域结束自动回收
- 如果来自堆上的字节数组：按字节数组的方式释放
- 如果来自内存池：还回内存池

### 在堆内存上使用 placement new

```cpp
char* raw = new char[sizeof(MyClass)];
MyClass* obj = new (raw) MyClass(100);

obj->~MyClass();   // 先显式析构对象
delete[] raw;      // 再释放原始内存
```

这里一定要记住：

- 不能 `delete obj`
- 因为 `obj` 不是通过普通 `new MyClass` 分配出来的

### 常见适用场景

1. 自定义内存管理
   比如内存池、对象池、环形缓冲区。

2. 高性能和实时系统
   提前准备好内存，避免关键路径上的动态分配波动。

3. 需要对象位于指定地址
   比如嵌入式、共享内存、硬件映射场景。

4. 标准库底层组件实现
   像 `std::optional`、`std::variant` 这类“预留一块存储区，按需构造对象”的设计思想，本质上就很接近 placement new 的用法。

### 为什么不能直接用 memcpy 初始化对象

`memcpy` 只是按字节拷贝，它不会调用构造函数。

对于这些对象：

- 有构造逻辑
- 有资源管理
- 有虚函数
- 有复杂成员

仅靠 `memcpy` 并不能正确创建出一个合法对象。

placement new 的价值就在于：它能在指定地址上，按照 C++ 对象模型正确构造对象。

### 使用 placement new 要注意什么

#### 1. 内存大小

必须保证预分配内存至少有：

```cpp
sizeof(Type)
```

那么大。

#### 2. 内存对齐

必须满足该类型的对齐要求，也就是：

```cpp
alignof(Type)
```

否则轻则性能下降，重则未定义行为。

#### 3. 显式析构

placement new 构造出来的对象，通常要自己手动析构，否则对象持有的资源不会正确释放。

### 面试官可能追问

#### Q1：使用 placement new 时最需要注意什么？

三点：

1. 内存大小够不够
2. 对齐是否正确
3. 析构是否手动处理

#### Q2：为什么不能直接用 memcpy 来初始化对象？

因为 `memcpy` 不会调用构造函数，也不会建立对象应该有的内部状态。对于复杂对象，这样做不能保证对象真的被正确构造出来。

#### Q3：如果在堆内存上使用 placement new，怎么安全释放？

先显式析构对象，再按原始内存的分配方式释放原始内存。

```cpp
char* raw = new char[sizeof(MyClass)];
MyClass* obj = new (raw) MyClass();

obj->~MyClass();
delete[] raw;
```

### 面试短答

> `placement new` 是一种特殊的 new 表达式，它不负责申请内存，只负责在一块已经准备好的原始内存上调用构造函数，把对象原地构造出来。它常用于内存池、对象池、共享内存和需要精确控制对象生命周期的场景。使用时要注意三点：内存大小足够、对齐正确、使用完后必须显式调用析构函数，并按原始内存来源释放那块内存。

## 什么是内存泄漏 什么是野指针 什么是内存越界 如何避免

### 简要回答

- 内存泄漏：申请的内存失去管理，程序不再能释放它
- 野指针：指向无效内存的指针
- 内存越界：访问超出对象或数组合法范围的内存

更口语一点可以这样记：

- 内存泄漏：忘了还
- 野指针：用了废的
- 内存越界：越界胡来

这三类问题都很危险，轻则程序变慢、结果混乱，重则直接崩溃，甚至引发安全漏洞。

### 详细回答

#### 1. 内存泄漏

内存泄漏是指：

- 程序申请了一块堆内存
- 但后面没有释放
- 而且还失去了这块内存的管理入口

这会导致这块内存既不能再用，也不能再释放。

典型情况：

- `new` 了对象却没有 `delete`
- `malloc` 了内存却没有 `free`
- 指针还没释放就被重新赋值，导致原地址丢失

后果：

- 内存占用越来越高
- 长时间运行后程序变慢
- 严重时触发 OOM 或崩溃

#### 2. 野指针

野指针是指：

- 指针变量本身还在
- 但它指向的内存已经失效

例如：

```cpp
int* p = new int(10);
delete p;
// p 现在就是悬空的野指针
```

之后再去访问 `*p`，就是在用一把已经废掉的钥匙去开门，结果不可预测。

常见来源：

- `delete` 后继续使用指针
- 返回局部变量地址
- 指针未初始化就使用

#### 3. 内存越界

内存越界是指访问了不属于这块对象或数组的内存区域。

例如：

```cpp
int arr[3] = {1, 2, 3};
arr[5] = 10; // 越界
```

它既可能发生在：

- 数组越界
- 字符串结尾处理不当
- 动态内存块写过头
- 访问已经释放的内存

内存越界的危险性在于：

- 有时当场崩溃
- 有时不会马上出错，但会悄悄破坏别的数据

### 怎么避免这些问题

#### 如何避免内存泄漏

1. 申请和释放成对出现。
2. 优先使用 RAII。
3. 优先使用智能指针：
   - `std::unique_ptr`
   - `std::shared_ptr`
4. 少写裸 `new/delete`。

#### 如何避免野指针

1. 指针定义时先初始化为 `nullptr`。
2. `delete` 后立刻置为 `nullptr`。
3. 不返回局部变量地址。
4. 不使用已经释放或未初始化的指针。

#### 如何避免内存越界

1. 所有数组访问都检查边界。
2. 尽量使用 `std::vector`、`std::array`、`std::string` 等容器替代裸数组。
3. 开启运行时检查工具，比如 AddressSanitizer。
4. 对外部输入做长度校验。

### 一句非常好背的话

内存问题常见就三种：

- 忘了还：内存泄漏
- 用了废的：野指针
- 越界胡来：内存越界

### 面试官可能追问

#### Q1：智能指针真的能完全防止内存泄漏吗？

不能说绝对。

大多数情况下它能显著降低泄漏风险，但 `shared_ptr` 如果形成循环引用，资源仍然不会释放。

这时需要用：

- `std::weak_ptr`

来打破引用环。

#### Q2：释放指针后为什么要设成 nullptr？

因为这样可以防止后续误用无效地址。

如果不置空，指针变量表面上还“像个正常地址”，后面 `if (p)` 判断也可能误判成可用。

#### Q3：你说内存泄漏会导致程序崩溃，怎么崩？

短时间内内存泄漏不一定立刻崩，但它会不断吃掉可用内存，造成：

- 内存占用持续增加
- 缓存压力变大
- 分配效率变差
- 最终申请内存失败或触发系统 OOM

长时间运行服务和嵌入式系统对这个问题尤其敏感。

#### Q4：free/delete 后为什么不能立刻认为这块内存就“安全可复用”？

因为 `free/delete` 只是告诉分配器“这块内存可以回收”，并不保证你手上的旧指针会自动失效，也不保证那片数据马上被清空。

所以野指针有时还能“读到旧数据”，这反而更危险，因为它会制造一种“好像还能用”的假象。

### 面试短答

> 内存泄漏是申请了内存却没释放，久了会把程序内存吃光；野指针是指针还在，但指向的内存已经失效；内存越界是访问了不属于自己的内存区域。  
> 这三类问题的典型防法是：少写裸 `new/delete`，优先用 RAII 和智能指针；指针初始化为 `nullptr`，释放后置空；数组和缓冲区访问严格做边界检查，并配合 AddressSanitizer 这类工具排查。

## 内存碎片与内存溢出

### 简要回答

- 内存碎片：内存被切成很多不连续小块，导致总量够但大块申请失败
- 内存溢出：申请的内存超过系统或进程可提供范围

更细一点讲：

- 内存碎片分成外部碎片和内部碎片
- 栈溢出是“栈空间不够了”
- 堆溢出更常见的口语说法通常是“堆上发生越界写导致内存结构被破坏”

### 详细回答

#### 1. 什么是内存碎片

内存碎片是指：

- 系统里空闲内存总量看起来还不少
- 但因为这些空闲内存不连续，或者分配粒度不匹配
- 导致新的内存申请无法高效满足

它本质上是内存利用率下降和分配器效率变差的问题。

#### 2. 外部碎片

外部碎片指：

- 空闲内存分散成很多不连续小块
- 总量可能够
- 但没有一块足够大的连续空间满足大请求

例子：

```text
[已用][空闲 4KB][已用][空闲 8KB][已用][空闲 2KB]
```

总共空闲 14KB，但如果程序现在要申请 10KB 连续空间，可能还是失败。

#### 3. 内部碎片

内部碎片指：

- 分配出去的块比实际需求更大
- 其中多出来的部分用户根本没用上

比如：

- 分配器按对齐要求多给了几个字节
- 内存池每块固定 64 字节，但你对象只用了 40 字节

这多出来的 24 字节就是内部碎片。

#### 4. 什么是内存溢出

内存溢出广义上是指程序申请的内存超出了系统或进程当前可提供范围。

例如：

- 持续申请内存不释放，最后申请失败
- 大块申请时系统已经没有足够可用空间

在很多工程语境里，人们也会把越界写、把堆管理结构写坏这种情况口语上说成“堆溢出”。更严格一点的说法是：

- 栈溢出：stack overflow
- 堆越界 / 堆破坏：heap overflow / heap corruption

#### 5. 栈溢出

栈溢出是指：

- 函数调用层次过深
- 或局部变量太大
- 导致线程栈空间被耗尽

常见触发方式：

- 无限递归
- 递归太深
- 栈上定义超大数组

特点：

- 通常比较确定，代码路径固定时容易稳定复现
- 常见结果是程序直接崩溃，比如触发 `SIGSEGV`

#### 6. 堆越界 / 堆破坏

堆上的危险问题更常见于：

- 对动态分配内存块写过头
- 破坏了相邻对象
- 覆盖了堆分配器元数据

这类问题很危险，因为它不一定立刻崩，而可能潜伏很久之后才发作。

它常见后果包括：

- 数据异常
- 随机崩溃
- 安全漏洞

### 对比表

| 特性 | 栈溢出 | 堆越界 / 堆破坏 |
|---|---|---|
| 发生区域 | 栈区 | 堆区 |
| 根本原因 | 栈空间耗尽 | 对动态内存块越界读写 |
| 典型触发 | 递归过深、大局部变量 | 写越界、错误索引、长度检查失误 |
| 结果 | 常常较快崩溃 | 可能立刻崩，也可能潜伏很久 |
| 影响 | 可用性问题更明显 | 安全风险更高 |

### 面试官可能追问

#### Q1：如何检测和避免栈溢出？

常见做法：

1. 代码审查，避免过深递归。
2. 把递归改成迭代。
3. 避免在栈上放特别大的对象或数组。
4. 使用编译器栈保护选项，如 `-fstack-protector`。
5. 配合静态分析和 AddressSanitizer 一类工具排查。

#### Q2：为什么堆越界是严重安全问题？

因为它可能覆盖：

- 函数指针
- 对象虚表指针
- 相邻对象数据
- 分配器元数据

攻击者如果能精心控制覆盖内容，就可能进一步控制程序执行流。

#### Q3：内部碎片和外部碎片哪个更难解决？

一般外部碎片更难。

因为内部碎片通常是“每块多浪费一点”，范围和上限比较可控；外部碎片则取决于长期随机分配和释放序列，难预测、难全局整理。

#### Q4：所有递归都会导致栈溢出吗？

不会。

只有递归深度过大、超出线程栈容量时才会导致栈溢出。浅层递归完全可能是安全的。

### 面试短答

> 内存碎片是空闲内存总量看起来够，但因为不连续或粒度不匹配而不好用，其中外部碎片是空闲块太分散，内部碎片是分配块里有一部分没用上。  
> 栈溢出是栈空间耗尽，常见于无限递归或超大局部变量；堆上的危险问题更多是越界写导致堆结构或相邻对象被破坏，这种问题不仅会崩溃，还可能带来安全风险。

## 如何避免内存碎片

### 简要回答

常见思路：

- 减少频繁小块申请和释放
- 使用内存池
- 复用对象
- 批量分配
- 合理使用容器预留空间

核心思想可以总结成一句话：

> 尽量不要让“不同大小、不同生命周期”的小块内存频繁交替申请和释放。

### 详细回答

#### 1. 根本思路：能少分配就少分配

最直接的办法就是减少动态内存申请次数。

能放：

- 栈上
- 成员变量里
- 静态存储区

就不要总是频繁去堆上申请和释放。

#### 2. 优先使用 STL 容器

像：

- `std::vector`
- `std::string`
- `std::array`

这类标准容器会帮你把内存集中管理起来。

尤其是 `vector` 和 `string`，虽然扩容时会重新分配，但它们倾向于维护连续空间，能显著减少“到处散着的小块堆分配”。

#### 3. 预分配和预留空间

如果提前知道大致元素规模，优先用：

```cpp
vec.reserve(n);
```

这样可以减少多次扩容、搬迁和旧块释放，降低碎片产生概率。

#### 4. 使用对象池 / 内存池

对于高频创建销毁、而且对象大小比较固定的小对象，对象池是非常有效的办法。

思路是：

- 先一次性申请一大块内存
- 再从里面切小块按需使用
- 对象释放后还回池子，而不是交还给通用堆分配器

这样能明显减少外部碎片和分配器开销。

典型适用场景：

- 游戏引擎
- 网络服务器
- 交易系统
- 实时系统

#### 5. 使用自定义分配器

如果某类对象很多、生命周期模式也很固定，可以给它们配自定义 allocator 或 pool allocator。

这样能让这类对象集中走一套更适合它们的内存策略，而不是全部混在通用堆分配器里争抢空间。

#### 6. 复用对象

很多时候不要每次都创建销毁，可以复用已有对象，例如：

- 循环缓冲区
- 连接对象复用
- 任务对象复用

本质上也是减少频繁堆分配。

#### 7. 智能指针和 RAII 的作用

智能指针和 RAII 不能直接“消灭碎片”，但它们能减少：

- 忘记释放
- 释放时机混乱
- 生命周期失控

而泄漏和生命周期混乱本身又会加剧内存长期占用和碎片问题，所以它们是间接有帮助的。

### vector 和 list 在碎片上的差异

这是一个很好用的追问点。

- `vector`：使用连续空间，整体更紧凑，扩容时会整体搬迁，但平时不容易形成到处散落的小块分配。
- `list`：每个节点单独分配，频繁插删会让堆上出现大量离散小节点，更容易形成外部碎片。

所以在不需要链表语义的情况下，不要随意把 `list` 当成默认容器。

### 适用场景

更适合重点考虑碎片问题的系统有：

1. 高频创建销毁小对象的系统
2. 长时间运行的服务端程序
3. 嵌入式和实时系统
4. 对延迟抖动敏感的系统

### 面试官可能追问

#### Q1：外部碎片和内部碎片有什么区别？

- 外部碎片：空闲内存总量够，但被分散成很多小块，大块申请失败。
- 内部碎片：分配出去的块比真实需求大，多出来的部分浪费了。

#### Q2：std::list 和 std::vector 在内存碎片上有什么不同？

`vector` 使用连续空间，整体更集中；`list` 每个节点单独分配，频繁插删时更容易制造外部碎片。

#### Q3：智能指针如何帮助减少内存碎片？

它们主要不是直接减少碎片，而是通过更可靠的生命周期管理减少内存泄漏，从而间接降低长期内存恶化风险。

#### Q4：如何设计一个线程安全的对象池？

最直接方式是用互斥锁保护空闲链表。更高性能一些的方案可以考虑线程本地缓存，让大部分申请释放发生在本线程池内，减少全局锁竞争。

### 面试短答

> 避免内存碎片的核心思路是减少不同大小、不同生命周期内存块的频繁交替申请和释放。工程上常见手段包括：优先用栈和成员变量、用 `vector/string` 这种集中管理内存的容器、提前 `reserve`、使用对象池或内存池、复用对象，以及在需要时给特定容器配自定义 allocator。相比之下，频繁使用 `list` 这种每个节点单独分配的结构，更容易产生外部碎片。
