## DNS 查询过程是什么

### 简要回答

DNS 查询是把域名解析成 IP 地址的过程。实际查询会先查缓存，缓存没有命中再向 DNS 服务器逐级查询。

### 详细流程

1. 浏览器缓存。
2. 操作系统缓存。
3. hosts 文件。
4. 本地 DNS 服务器。
5. 根域名服务器。
6. 顶级域名服务器。
7. 权威域名服务器。
8. 返回 IP，结果按 TTL 缓存。

### hosts 文件路径

```text
# Linux hosts 文件
/etc/hosts

# Windows hosts 文件
C:\Windows\System32\drivers\etc\hosts

# hosts 可以手动把域名映射到 IP，优先级通常高于 DNS 查询
192.0.2.1 www.programmercarl.com
```

### 面试表达

> DNS 的核心作用是域名到 IP 的映射。为了提高速度，浏览器、操作系统、本地 DNS 都会做缓存；缓存未命中时，本地 DNS 再通过根、顶级、权威 DNS 逐级找到最终 IP。

## 递归查询和迭代查询有什么区别

### 简要回答

递归查询是“你帮我查到底”；迭代查询是“我告诉你下一步该问谁”。

### 对比表

| 对比点 | 递归查询 | 迭代查询 |
|---|---|---|
| 查询责任 | 被请求方负责查到底 | 被请求方只返回下一跳线索 |
| 常见场景 | 客户端问本地 DNS | 本地 DNS 问根/顶级/权威 DNS |
| 记忆 | 托人办到底 | 问路，一站一站找 |

### 示例

```text
# 用户输入的完整 URL 中，DNS 只关心域名部分
www.programmercarl.com/ -> programmercarl.com
```

## DNS 常见记录类型有哪些

### 简要回答

常见 DNS 记录有 A、AAAA、CNAME、MX、NS、TXT。

### 记录类型

| 类型 | 作用 | 例子 |
|---|---|---|
| A | 域名 -> IPv4 地址 | `example.com -> 93.184.216.34` |
| AAAA | 域名 -> IPv6 地址 | `example.com -> 2606:...` |
| CNAME | 域名 -> 另一个域名 | `www -> example.com` |
| MX | 邮件服务器记录 | 邮箱服务 |
| NS | 指定权威 DNS 服务器 | 域名解析托管 |
| TXT | 文本记录 | SPF、DKIM、域名验证 |

### 易错点

- DNS 解析失败时，浏览器可能出现 `DNS_PROBE_FINISHED_NXDOMAIN`。
- DNS 缓存有 TTL，不是每次访问都会重新查权威 DNS。
- CDN 常利用 DNS 把用户调度到更近的节点。

## 输入 URL 到页面展示发生了什么

### 简要回答

经历 URL 解析、DNS 解析、建立 TCP 连接、HTTPS 的 TLS 握手、发送 HTTP 请求、服务器处理、返回 HTTP 响应、浏览器解析渲染。

### 分层流程

| 阶段 | 做什么 | 关键点 |
|---|---|---|
| URL 解析 | 拆出协议、域名、端口、路径、参数 | HTTP 默认 80，HTTPS 默认 443 |
| DNS 解析 | 域名解析成 IP | 先缓存，后递归/迭代查询 |
| TCP 建连 | 三次握手 | `SYN -> SYN-ACK -> ACK` |
| TLS 握手 | HTTPS 加密协商 | 证书校验、密钥交换 |
| HTTP 请求 | 浏览器发送请求报文 | 方法、路径、Host、Header |
| 服务器处理 | Web 服务器/后端程序处理 | Nginx、Tomcat、C++ 服务等 |
| HTTP 响应 | 返回状态码、Header、Body | `200`、`Content-Type` |
| 浏览器渲染 | 解析 HTML/CSS/JS | DOM、CSSOM、布局、绘制 |

### 请求示例

```http
# 浏览器请求首页
GET /index.html HTTP/1.1
Host: www.baidu.com
User-Agent: Mozilla/5.0
Connection: keep-alive
```

### 响应示例

```http
# 服务器返回 HTML
HTTP/1.1 200 OK
Content-Type: text/html
Content-Length: 1024
Connection: keep-alive
```

### TCP/TLS 关键片段

```text
# TCP 三次握手
SYN -> SYN-ACK -> ACK

# HTTP 默认端口和 HTTPS 默认端口
80
443
```

### 面试表达

> 这道题不要只背浏览器渲染，也要把网络链路说完整：先解析 URL 和 DNS，再建 TCP 连接；如果是 HTTPS，还要 TLS 握手；然后发送 HTTP 请求，服务器处理后返回响应，浏览器再解析 HTML、CSS、JS 并完成渲染。

## 浏览器访问服务器流程

### 简要回答

从网络和后端角度看，就是客户端通过 TCP 连接把 HTTP 请求发给服务器，服务器根据路由或业务逻辑处理后，把 HTTP 响应写回客户端。

### 后端处理流程

1. Web 服务器接收 TCP 连接。
2. 读取 HTTP 请求行、请求头、请求体。
3. 根据 URL 路径匹配路由或处理函数。
4. 业务层查询数据库、缓存或调用其他服务。
5. 生成 HTTP 响应，写回 socket。
6. 根据长连接策略决定保留或关闭连接。

### Java Web 映射示例

网站示例里出现了 Servlet 映射，C++ 面试中可以类比为“URL 路径映射到某个处理函数”。

```xml
<!-- url-pattern 表示请求路径，servlet-class 表示处理这个路径的类 -->
<servlet-mapping>
  <servlet-name>UserServlet</servlet-name>
  <url-pattern>/user</url-pattern>
</servlet-mapping>

<servlet-class>com.example.UserServlet</servlet-class>
```

### C++ 后端类比

```text
# C++ Web Server 里通常是这种思想：
# URL 路径 -> 回调函数/业务处理器 -> 生成响应
/user -> handleUserRequest() -> HTTP Response
```
