## 什么是死锁

### 简要回答

死锁是多个进程或线程互相等待对方持有的资源，导致所有参与者都无法继续执行。

### 面试表达

> 死锁的典型场景是线程 A 拿着锁 1 等锁 2，线程 B 拿着锁 2 等锁 1，双方都不释放已有资源，程序就卡住了。

### 代码示例

```cpp
std::mutex m1, m2;

void t1() {
    std::lock_guard<std::mutex> l1(m1);
    std::lock_guard<std::mutex> l2(m2);
}

void t2() {
    std::lock_guard<std::mutex> l2(m2);
    std::lock_guard<std::mutex> l1(m1);
}
```

两个线程加锁顺序相反，就可能形成循环等待。

## 死锁产生的四个必要条件

### 简要回答

互斥、请求并保持、不可剥夺、循环等待。

### 详细回答

1. 互斥：资源一次只能被一个线程占用。
2. 请求并保持：持有资源时继续请求其他资源。
3. 不可剥夺：资源不能被强制抢走。
4. 循环等待：多个线程形成等待环。

## 如何处理死锁

### 简要回答

常见思路有预防、避免、检测、解除。

### 详细回答

- 预防：破坏四个必要条件之一。
- 避免：分配资源前判断是否安全，比如银行家算法。
- 检测：允许死锁发生，定期检测等待环。
- 解除：回滚、终止进程、抢占资源。

### C++ 常用避免方式

- 固定加锁顺序。
- 减少嵌套锁。
- 使用 `std::lock` 一次性锁多个锁。
- 加锁时设置超时。

## 银行家算法是什么

### 简要回答

银行家算法是一种死锁避免算法，在分配资源前先判断系统是否还能保持安全状态。

### 面试表达

> 银行家算法的核心是“不把资源分配给会让系统进入不安全状态的请求”。它会模拟分配后是否存在一个安全序列，如果没有安全序列，就暂时拒绝分配。

### 核心数据结构

- `Available`：当前系统可用资源数量。
- `Max`：每个进程最多需要多少资源。
- `Allocation`：当前已经分配给每个进程的资源。
- `Need`：每个进程还需要多少资源。

计算关系：

```text
Need = Max - Allocation
```

### 安全性检查

如果系统能找到一个进程序列，使得每个进程都能在当前可用资源加上前面进程释放资源后顺利完成，那么系统处于安全状态。

## 活锁和饥饿是什么

### 简要回答

活锁是线程一直在改变状态但始终无法推进；饥饿是某个线程长期得不到所需资源或 CPU。

### 对比

| 概念 | 表现 |
|---|---|
| 死锁 | 都阻塞不动 |
| 活锁 | 都在动，但事情没进展 |
| 饥饿 | 某些任务长期得不到资源 |

### 面试表达

> 死锁是大家都卡住，活锁是大家都在让来让去但没有进展，饥饿是某个低优先级任务一直轮不到资源。
